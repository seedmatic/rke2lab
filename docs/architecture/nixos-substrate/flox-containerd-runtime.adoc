= NixOS node substrate — the flox containerd runtime
:toc: left
:toclevels: 3

[NOTE]
====
Workloads run on the *flox containerd runtime* — the reason NixOS is coherent as the node OS
(nix-native). This spec covers where that runtime lives in the target substrate and the dev→prod
build trajectory. It is one row of link:concern-ownership.adoc[concern ownership], expanded.
====

== The runtime belongs in the base closure

In the target the flox containerd runtime is a *nix derivation in the base closure*, not a runtime
host build:

* the current DaemonSet-trampolines-to-host + `nix flake build` is a *Debian-era workaround* for a
  non-nix-native OS; on NixOS the shim is just part of the image, built on the existing ARM64 build
  infra (linux-builder, remote-nix-store, cachix) at *image* time.
* it belongs to `rke2lab-node-base` — every node that runs pods needs it — not to a specialisation.
* the containerd wiring (NRI plugin, ZFS snapshotter, SystemdCgroup, registries) is declarative in
  `nixos/containerd.nix`; the flox runtime is the derivation those settings point at.

NOTE: "Base closure" scopes to the runtime *shim* — the plugin + OCI hooks + `/etc/flox.toml` +
NRI containerd config. The flox *envs* the shim injects are NOT in the base closure: they are
delivered at runtime as `FloxEnv` CRs reconciled by our flox controller onto the host `/nix/store`
(link:../patterns/flox-store-resolved-runtime-and-builder.adoc[Flox Store-Resolved Runtime] §Runtime
env delivery). Baking the *envs* was the interim; that migration is DONE — the env-bake machinery
(the `environment.d` envs + their per-env GC-roots) is RETIRED, so only the hooks + host-wide
`/etc/flox.toml` policy remain baked (`nixos/flox-runtime.nix`). Delivering the envs as CRs is what
keeps a package bump from cold-starting the control node.

== Dev vs prod — runtime now, harden later

During active shim development the runtime build (a DaemonSet from the projected worktree) keeps a
fast edit loop; once stable, it bakes into the image. This is the general "runtime now → harden
later" trajectory the whole substrate follows (see link:substrate-model.adoc#_the_maturation_arc[the
maturation arc]): the switch point is per shim, chosen when the shim stops changing.

For the flox shim that switch has flipped: the baked form is LIVE (`nixos/containerd.nix` resolves
`flox-runtime.packages.<system>.flox-nri-plugin` and symlinks it to `/opt/nri/plugins/10-flox`), and
the shim source (a *fork* of flox's containerd plugin) is extracted to
`github:seedmatic/flox-nri-plugin`, consumed as the rke2lab flake input `flox-runtime`. The DaemonSet
build survives as the *retained runtime-contribution* tier, no longer the primary delivery.
