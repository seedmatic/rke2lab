== What this is, and what it fixes

`osgi/ssh-to-age-edge` is the single door toward the `ssh-to-age` CLI: it converts an OpenSSH private
key to an age private key by shelling the tool. It fixes the purity violation the
link:../patterns/frontier-playability-model.adoc[frontier-playability model] inventoried:
`SopsAgeSecretManifestsUnit` used to *fetch* the key mid-synthesis — read `.ndh-ssh.d/keys.yaml` and
spawn `ssh-to-age` inside `doSynthesize`, a hidden side-effect in the describe step.

Two defects were folded into one fix:

* *Synthesis fetched its input.* The unit now *receives* the age key as a prerequisite on the context
  and only renders the Secret. The describe step is a pure function of its inputs again.
* *The ssh-to-age contact was inline and nameless.* It is now a named external edge — the system's
  skin made explicit — even though the OSGi world could (and does) call it inline. Materialising the
  boundary is the point; playability only decides which world the edge lives in.

The regex that parsed `keys.yaml` is gone: the key-store is structured YAML, read with a typed Jackson
path lookup (`keys → rke2-cluster → private`), the same shape as `BboxSecretsReader`.

== The shape (worked example B, realised)

There is NO domain here: ssh-to-age reasons over nothing. So — per
link:../patterns/port-edge-domain-ownership.adoc[the ownership rule] — there is *no `-core` and no
`ssh-to-age-port`*. Just the edge, plus a seam owned by its consumer.

[cols="1,3",options="header"]
|===
| Role | For ssh-to-age

| The consumer (owns the seam)
| `DefaultManifestSynthesisService` (manifests-core, an OSGi `@Component`). It declares the seam and
  calls it in a pre-synthesis step.

| The seam (`-port`, owned by the consumer)
| `SshToAgeConverter` (`String toAgeKey(String sshPrivateKey)`) + `SshToAgeConversionException`, in
  `manifests-contract`. Pure passive type, exported. NOT named after the edge. The gateway profile
  `SopsAgeMaterial` (the age key) lives beside the other profiles.

| The edge (`<target>-edge`, OSGi world)
| `osgi/ssh-to-age-edge` — `ProcessBuilderSshToAgeConverter implements SshToAgeConverter`,
  `@Component(service = SshToAgeConverter.class)`. The `ProcessBuilder("ssh-to-age", "-private-key")`.
  Owns no port.
|===

== The data path (pre-synthesis, in the OSGi world)

. `DefaultManifestSynthesisService.synthesize()` runs a *pre-synthesis step* BEFORE binding the
  context: `SopsAgeMaterialResolver` reads the `rke2-cluster` SSH key from `.ndh-ssh.d/keys.yaml`
  (typed Jackson, fail-soft if absent → `unknown()`, fail-fast if malformed), then calls the injected
  `SshToAgeConverter` edge to get the age key, producing a `SopsAgeMaterial`.
. The material is bound onto `ManifestSynthesisContext` — the *profile-bearing* context (request /
  ThreadLocal), the same channel that already carries `IncusIdentityMaterial` / `BootstrapIdentity`.
  NOT `ManifestsUnitContext` (the per-unit record: chart, domainId, resolver — no profile).
. `SopsAgeSecretManifestsUnit.doSynthesize` reads `context.sopsAgeMaterial()`, skips if `unknown()`,
  else base64-encodes the key into the Secret. Zero `ProcessBuilder`, zero file read.

The *channel rule* holds: the edge is a service → bound by `@Reference`; its result (the age key) is
data → carried on the ThreadLocal context.

== Why the edge lives in the OSGi world (three reasons, not one)

ssh-to-age is the first external edge to materialise in OSGi rather than host. Playability is the
*enabler* (`ProcessBuilder` + `java.nio` run fine inside Felix), but three *positive* reasons make OSGi
the right home once the consumer is already there:

. *The frontier is explicit.* The edge is the system's skin made a named module, regardless of world.
. *Inherited IoC.* SCR does the discovery + injection + lifecycle (`@Component` / `@Reference`). A host
  edge is assembled by hand (`new …` in an assembly); here the converter simply *appears* in the
  service by injection — no factory, no registry code.
. *Fail-fast for free.* Because the injection is container-managed, the `@Reference` is *mandatory*:
  no edge ⟹ the component never activates ⟹ `ManifestSynthesisService` never publishes ⟹ a hard
  boot/resolution failure, not a silently half-rendered Secret. A host edge has neither the injection
  nor the guard — you would write (or forget) the null-check yourself.

Reasons 2 and 3 are two faces of the same SCR mechanism: container-managed injection is what lets the
reference be mandatory, which is what makes "edge missing" a resolution failure instead of a runtime
bug. The edge follows the world of its consumer — `DefaultManifestSynthesisService` is a `@Component`,
so the edge is OSGi; pulumi/dbus stay host because their callers are host.

== Packaging — the edge is a new embedded bundle (single-source by capability)

The edge is the first NEW embedded bundle since the
link:osgi-boot-single-source-handoff.adoc[boot single-source] change, and it exercised it exactly as
designed: adding it was *one staging `artifactItem` + one `Provide-Capability` line*, zero Java in the
boot path.

* `ssh-to-age-edge/bnd.bnd` self-declares
  `Provide-Capability: io.seedmatic.rke2lab.embed; type=edge; edge=ssh-to-age`. The boot scan keys on the
  NAMESPACE, so the edge is discovered like any model bundle; the `type`/`<type>=<id>` attributes
  qualify its NATURE (read by humans, not the scan) — and ssh-to-age is the first carrier whose nature
  is `edge`, not `model`, which is why the two cores were retrofitted to `type=model; model=<id>`.
* Both execs that boot manifests-core (`seed-outcluster`, `manifests-cli`) stage the edge jar + exclude it
  from the flat shade (the two irreducible pom faces) and declare a `runtime`-scope dependency on it —
  never a compile dep (DIP: the consumer compiles only against the `-port` seam).

== Two traps met and closed during implementation

* *`locateOnClasspath` matched a path substring.* The classpath topology test
  (`HostSeamEmbeddedFelixTest`) located bundles by `path.contains(artifact)`. This worktree is named
  `ssh-to-age-edge`, so EVERY classpath entry contains the string and the lookup returned the wrong
  jar — the edge was never installed, the mandatory `@Reference` stayed unsatisfied, the seam services
  never published. Fixed to match the jar's LEAF (`<artifact>-<version>.jar`) or the module directory
  name, never a substring.
* *The test named the bundles to install.* That is a hand-list that drifts — a forgotten edge would
  silently un-publish the seam. Replaced by `OsgiRuntime.embeddableBundlesOnClasspath()`: the test now
  *discovers* the model + edge bundles by the SAME embed capability as the boot scan, sourced from the
  classpath. The third-party boot stack (pax / felix.scr / felix.resolver) carries no embed capability
  — verified on the real jars — so it stays located by name: the irreducible remainder for jars we do
  not own.

== Improvement requests for the boot registry (→ osgi-boot-single-source v2)

This edge being the first new client of the boot capability scan surfaced three further single-source
steps. They were deliberately *deferred* to keep this change single-topic — they belong to the
`osgi-boot-single-source` increment, whose territory is `OsgiRuntime`, owned by the integration
session. Recorded here as explicit, actionable requests so they are not lost:

. *Unify the two capability readers into one, parameterised by source.* `scanEmbeddedModelBundles()`
  (source = the staged `META-INF/bundles/` root) and `embeddableBundlesOnClasspath()` (source = the
  reactor classpath) now read the *same* `io.seedmatic.rke2lab.embed` capability through *two* duplicated
  manifest-reading loops. The single-source move is one reader keyed on the capability, taking the
  source as a parameter — the embedded vs classpath topologies differ only in where they enumerate
  jars, not in what they look for. Today the discovery logic is forked; it should be one.

. *Give the third-party boot stack a typed registry (enum), not four free constants.* `pax-logging-api`,
  `pax-logging-logback`, `org.apache.felix.scr`, `org.apache.felix.resolver` are still four loose
  `public static final String … _JAR` constants plus matching builder verbs and `locateOnClasspath`
  calls scattered across `embeddedBootStack()` and the tests. An `enum BootStackJar` carrying
  `(artifactId, stagedFileName)` would single-source them and let `embeddedBootStack()` iterate. Note
  the *honest frontier*, verified on the real jars: these cannot use the embed capability — they are
  not ours to annotate, and `pax-logging-api` declares **no** `Provide-Capability` at all, while
  felix.scr declares only the standard `osgi.extender`/`osgi.component`. So "ours → discovered by
  capability, third-party → a named enum" is the correct split, not an inconsistency to remove.

. *Resolve (or formally accept) the shade-`exclude` duplication.* Carried over from v1: the staging
  `artifactItem` and the shade `<exclude>` are the two pom faces of one declaration, and the shade runs
  pre-boot so it cannot be derived from a runtime scan. Either derive the exclude from the staging set
  via a small mojo, or document it as irreducible — but state it once, authoritatively.

The through-line for all three is the same north-star as the boot scan itself: *read the real artifact,
never maintain a parallel list* — applied now to the reader (one, not two), the boot stack (a typed
registry, not loose constants), and the pom faces (one declaration, not two hand-synced sites).
