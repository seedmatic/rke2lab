= Cluster Addressing Plan — a deterministic allocation per `<host>-<role>`
:toc: left
:toclevels: 3

This document is the *single source of truth* for how every network span a cluster owns —
node/VIP/LB, pod, service, the IPv6 ULA mirror, the clustermesh `cluster.id`, and the BGP
ASN — is derived from a cluster's identity `<host>-<role>`. It is the addressing companion to
link:management-workload-topology.adoc[Management / Workload Topology] (the *what* — which
clusters exist) and link:cilium-bgp-multi-host-topology.adoc[Cilium BGP Multi-Host Topology]
(the *fabric* — how nodes exchange routes).

It exists because the topology moved from *one* cluster to *four* — `bioskop-mgmt`,
`bioskop-wrkld`, `nikopol-mgmt`, `nikopol-wrkld` — that co-exist on a *shared L2 fabric* and
federate in *two* clustermesh domains. Under one cluster the pod/service CIDRs and the BGP ASN
could be global constants (`10.42.0.0/16`, `10.43.0.0/16`, `65010`); under four they *must*
become a deterministic function of identity, or routes collide on the shared bridge and
clustermesh cannot federate. This plan defines that function.

== The constraint that forces per-cluster addressing

Two facts from the topology make global-constant CIDRs incorrect:

. *Clusters share an L2 fabric per host.* Each host's Incus engine gives every cluster the
  `default` project's bridge (`features.networks=false`, see
  link:management-workload-topology.adoc#incus-tenancy[Incus tenancy]). So `bioskop-mgmt` and
  `bioskop-wrkld` nodes are L2-adjacent and advertise pod routes (cilium BGP) on the *same*
  segment. If their pod CIDRs overlapped, two nodes would advertise the same prefix via
  different next-hops — the route table is ambiguous, pods misroute. Overlap is broken *before*
  any clustermesh.
. *Clusters federate in two role-partitioned meshes.* Meshing is *by role*: the management
  clusters mesh with each other (`bioskop-mgmt` ↔ `nikopol-mgmt`) and the workloads mesh with
  each other (`bioskop-wrkld` ↔ `nikopol-wrkld`) — never mgmt↔wrkld. Cilium clustermesh
  requires, within a mesh, a unique `cluster.id` and non-overlapping pod CIDRs.

Both point the same way: **every span a cluster owns is a pure function of `(host, role, node)`.**
Because clusters sharing a host already need disjoint pods (fact 1), we allocate *globally*
distinct spans across all four — which trivially satisfies each mesh's intra-mesh uniqueness
(fact 2) and stays robust if a cluster ever moves hosts.

== The identity encoding — `clusterId`

`clusterId` packs the two identity bits, host-major:

[source]
----
clusterId = (host << 1) | role
  host: bioskop = 0, nikopol = 1        role: mgmt = 0, wrkld = 1

  bioskop-mgmt  = 0     nikopol-mgmt  = 2
  bioskop-wrkld = 1     nikopol-wrkld = 3
----

`clusterId ∈ 0..7` leaves room for a third bare-metal host (bit 2) without touching the packing.
Every span below is `f(clusterId)` — and, for per-node spans, `f(clusterId, nodeId)` with the
`nodeId` map, packed contiguously (`master=0, peer1=1, peer2=2, peer3=3, worker1..8=4..11`) so the
twelve nodes fit the workload cluster's LAN node `/28` without overflow.

NOTE: This *re-encodes* today's ids (`bioskop=0`, `nikopol=1`). The existing clusters' addressing
shifts, which is safe: clusters are re-seeded, never live-migrated
(link:management-workload-topology.adoc#function-of-git[function of git]).

== IPv6 dual-stack

The node's `cluster-cidr` is baked dual-stack in `nixos/rke2.nix`; the pod/service v6 halves are
this plan's `fd00:<44+id>::/56` and `fd00:<48+id>::/112`, and cilium's `routingMode: native`
requires the v6 native-routing CIDR whenever v6 is enabled (see
link:../nixos-substrate/node-bootstrap-delivery.adoc[node-bootstrap delivery], the dual-stack
IMPORTANT). So the pod v6 span is not optional trivia — it is a required cilium input, and it must
track this table.

== The LAN — asymmetric per-role slices in the HIGH half

The physical LAN `192.168.1.0/24` is fixed (the home network), but the LOW half (`.0-.127`) is NOT
the lab's to allocate — it is the home network's own DHCP pool and existing devices (the gateway
sits at `.254`). A cluster node dropped there collides with the home LAN (an early attempt placed a
node at `192.168.1.6` and the router refused the reservation). So the lab takes the HIGH half only
(`192.168.1.128/25`), carved *by role* from

[source]
----
base = 192.168.1.<128 + hostId·48 + roleId·16>
  hostId: bioskop = 0, nikopol = 1, test = 2      roleId: mgmt = 0, wrkld = 1
----

A *management* cluster is a single node, so it takes a compact `/29` node slice + a `/29` LB slice.
A *workload* cluster runs four control-plane + up to eight workers, so it takes a `/28` node slice
(`host(3)..host(14)` — 12 nodes, `host(15)` is broadcast) + a `/29` LB slice. The LB slice holds the
headscale/tailscale VIPs (`host(1)`/`host(2)`); the node hosts are `host(3 + nodeId)`.

[cols="2,^1,^1,2,2,2",options="header"]
|===
|Cluster |`hostId` |`roleId` |base |Node slice |LB slice

|`bioskop-mgmt`  |0 |0 |`.128` |`192.168.1.128/29` |`192.168.1.136/29`
|`bioskop-wrkld` |0 |1 |`.144` |`192.168.1.144/28` |`192.168.1.160/29`
|`nikopol-mgmt`  |1 |0 |`.176` |`192.168.1.176/29` |`192.168.1.184/29`
|`nikopol-wrkld` |1 |1 |`.192` |`192.168.1.192/28` |`192.168.1.208/29`
|`test-mgmt`     |2 |0 |`.224` |`192.168.1.224/29` |`192.168.1.232/29`
|===

`test-mgmt` (hostId 2) is a *reserved* slice: it is the fallback the manifests node-env context
derives when the handed-over identity carries no cluster (a bare survey / no seeded identity), so
that path lands on a valid, distinct slice at `.224` instead of overflowing the octet — never a real
cluster's address space. A genuinely unknown host is NOT silently mapped: `hostId()` throws (fail
fast, "add it to the addressing plan") rather than fabricating an out-of-range base. Real clusters
fill `.128-.223`; a fourth bare-metal host would need its OWN LAN segment rather than more slices of
this `/24`.

----

*Legend*: solid = clustermesh federation (same role, across hosts); dotted = same-host L2
adjacency on the shared fabric (NOT a mesh — but the reason pods must still be disjoint). The
`cluster.id` is assigned globally-unique (`clusterId+1`, 1..4) though each mesh only needs
intra-mesh uniqueness: global uniqueness is robust against fabric adjacency and a cluster
changing hosts, and 4 ≪ 255 (the clustermesh ceiling) so there is no scarcity. `cluster.name` is
the identity `<host>-<role>` — which also retires the hardcoded `cluster.name: sample` /
`cluster.id: 7` placeholder in the cilium HelmChartConfig.

.The role partition is also the TRUST boundary
[NOTE]
====
This plan justifies the role partition on technical grounds (cilium requires intra-mesh unique
`cluster.id`s and disjoint pod CIDRs). It carries a second, independent justification: a mesh's members
must *trust each other*, which necessarily pierces the sibling-CA isolation `WorkloadClusterCas`
guarantees ("independent keys, so a compromise of one cluster's CA never reaches another"). The role
partition bounds the blast radius of that shared trust to one role-mesh, never the fleet — so
`mgmt ↔ wrkld` is not merely "not meshed", it is *not in the same trust domain*.

*This plan decides `that` the meshes exist; it does not decide how one is peered* — which CA signs
whom, where the material comes from, who owns it. That is
link:clustermesh-trust-and-peering.adoc[Clustermesh — trust domains and declarative peering], along
with the finding that the peering is *out-of-band today* (`tls.auto` self-signs a random CA per
cluster, `clustermesh-remote-users` is rendered empty) because no role-mesh has ever had a second
member.
====

== BGP ASN — per cluster

Each cluster's cilium BGP `localASN` is `64512 + clusterId` (`64512..64515`), inside the 16-bit
private-ASN range `64512–65534`. The external fabric gateway peer keeps its fixed `peerASN`
(`65020`). Intra-cluster peering stays the iBGP mesh of
link:cilium-bgp-multi-host-topology.adoc[the BGP topology]; the per-cluster ASN keeps sessions
unambiguous when clusters that share the L2 fabric both run BGP on it.

== Invariants

* *Deterministic.* Every span is a pure function of `(host, role[, node])` — no allocation
  state, no registry. Re-seeding a cluster reproduces its addressing exactly (function of git).
* *Globally disjoint pod & service CIDRs.* Forced by the shared-per-host fabric; it also makes
  both role-meshes collision-free for free.
* *Shared fabric unchanged.* `features.networks=false` and the L2 bridge are untouched; this plan
  changes only *which* L3 spans each cluster claims on it.
* *Extensible.* `clusterId 0..7` (third host on bit 2); pod/service `/14` supers hold four
  clusters and widen to `/13` for eight. The LAN `/24` is the exception: only its HIGH half is the
  lab's (the low half is the home network). It holds the four real `<host>-<role>` clusters
  (`.128-.223`) plus the reserved `test` slice (`.224`); an unknown host fails fast in `hostId()`
  and a fourth bare-metal host brings its own LAN segment rather than more slices here.

== Before → after (the code delta — SHIPPED)

The "shipped" column is now the code: `ClusterNetworkBlueprint` derives `clusterId = (hostId << 1) |
roleId`, per-cluster pod/service CIDRs, `bgpLocalAsn = 64512 + clusterId`, and clustermesh
`cluster.id = clusterId + 1`. The "before" column is historical.

[cols="1,2,2",options="header"]
|===
|Concern |Before (single-cluster, superseded) |Shipped (per `<host>-<role>`)

|`clusterId` |`ClusterNetworkBlueprint.clusterId(name)` switch `bioskop→0, nikopol→1` (host only) |`(host<<1)\|role`, keyed on `<host>-<role>`
|Pod / Service CIDR |global constants `POD_CIDR=10.42.0.0/16`, `SERVICE_CIDR=10.43.0.0/16` (+v6) |`10.<44+id>.0.0/16` / `10.<48+id>.0.0/16` (+v6 `fd00:<44+id>`/`fd00:<48+id>`)
|BGP ASN |`ClusterAsn.RKE2_CLUSTER=65010` (constant) |`64512 + clusterId`
|clustermesh `cluster.id`/`name` |hardcoded `id: 7`, `name: sample` in the cilium HelmChartConfig |`clusterId+1` / `<host>-<role>`
|LAN slices |two `/27` per cluster (node + LB), hand-mapped |asymmetric per role from `128 + hostId·48 + roleId·16`: mgmt node `/29` + LB `/29`, wrkld node `/28` + LB `/29`; reserved `test` slice at `.224`
|Node/VIP/LB, ULA |per-cluster already, keyed on the host-only `clusterId` |same formulae, keyed on the new `clusterId`
|===

The blueprint is the single derivation site; `ClusterAsn` and the pod/service CIDRs are
`clusterId`-indexed derivations, and the cilium `HelmChartConfig` reads
`cluster.name`/`cluster.id` from identity instead of literals.
