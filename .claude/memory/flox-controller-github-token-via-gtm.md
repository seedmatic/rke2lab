**Root cause.** Le flox-controller tourne `flox activate` sur l'HÔTE via nsenter → utilise le nix du node. Ce nix fait `!include /etc/nix/nix.custom.conf` (ndh `nix-settings.nix`) mais **personne n'écrit ce fichier** → zéro `access-tokens`. Or `claude-hub` (input de **ndh**, `github:seedmatic/claude-hub`, **privé**) est tiré dans la closure catalogue→rke2lab→ndh ; `flox activate --mode dev` **re-locke** l'input branche `rke2lab` → re-fetch claude-hub → **404** (repo privé, fetch anonyme). Le mesh marchait avant parce que claude-hub était déjà dans le store (fetché lors d'un `nixos-rebuild-gh` opérateur, qui source son token de `gh auth token`) ; pod frais / GC → re-fetch → 404. Le seul mécanisme de token = `nixos-rebuild-gh` (ndh), **interactif opérateur**, pas pour le controller unattended.

**Décision (user).** Le mint n'est **PAS le rôle du flox-controller** ; le `githubapp` (App creds) **reste dans flux-system** (pas de réplication/rename). On déploie **isometry/github-token-manager (gtm)** — opérateur k8s dédié qui mint+rafraîchit des installation-tokens App dans des Secrets. Le flox-controller **consomme** juste le token (comme `FLOX_FLOXHUB_TOKEN`).

**Faits API gtm (github.com/isometry/github-token-manager) :**
- CRDs **`github.as-code.io/v1`** : `App`, `Token` (namespaced), `ClusterToken` (cluster-scoped).
- `App` : `spec.{appID(int), installationID(int), provider: secret, keyRef.name}` → Secret same-ns avec clé **`private-key.pem`**.
- `ClusterToken` : `spec.{appRef.{name,namespace}, permissions.{metadata,contents,…}, refreshInterval, secret.{name,namespace,basicAuth}}` → Secret de sortie `data.token` (défaut) ou username/password (basicAuth).
- Déploiement : **Helm chart OCI `oci://ghcr.io/isometry/charts/github-token-manager`** (pas de release.yaml unique → on utilise le chart, PAS l'upstream-yaml).

**Plan (gtm dans `rke2lab-system`, chart via `HelmChart` CR rke2 comme cert-manager/openebs) :**
1. `GithubTokenManagerManifestsUnit` (units/platform) : (a) `helm.cattle.io/v1 HelmChart` (ns kube-system, `chart: oci://…/github-token-manager`, `targetNamespace: rke2lab-system`, version pinnée) ; (b) Secret `private-key.pem` (rke2lab-system) rendu depuis `GithubAppMaterial.privateKeyPem`, **chiffré branche+sops** (nom `*-secret-*` → filtre) ; (c) `App` CR (appID/installationID depuis GithubAppMaterial, provider:secret, keyRef) ; (d) `ClusterToken` CR → Secret **`github-token`** (rke2lab-system), permissions `metadata:read + contents:read`, refreshInterval 45m.
2. `FluxServiceKustomizationPlanner` : enregistrer le groupe CRD **`github.as-code.io`** comme runtime-installé par le chart gtm (pour l'ordering App/ClusterToken, comme tailscale.com/zfs.openebs.io).
3. `FloxControllerManifestsUnit` : monter `github-token` en env (`secretKeyRef data.token` → ex. `GITHUB_ACCESS_TOKEN`), à côté de floxhub-token.
4. **flox-controller (Go, repo séparé `develop`)** : minimal — `internal/provisioner/exec.go` `buildEnv`/`addEnvSubtree`/`containerize` posent `NIX_CONFIG += "\naccess-tokens = github.com=$GITHUB_ACCESS_TOKEN"` dans `cmd.Env` (passé via nsenter au nix du host). Pattern déjà là : `floxenv.NixConfig()` + `FLOX_FLOXHUB_TOKEN` via l'env.
