= Realm library isolation — each world loads its own copy of a shared library, never one across the seam
:toc: left
:icons: font

*Status:* DESIGN (converged 2026-06-30, NOT yet built). A correction increment, sequenced BEFORE
link:seed-broker-spec.adoc[the world gateway] and the remote-validation
capstone. It closes a gap 2C's peer model exposed but did not yet act on: a third-party library a
*world* uses (today jackson; with 2D, networknt) is still *shared* across the host/OSGi boundary
through `system.packages.extra`, rather than each world loading its own classloader-isolated copy —
the isolation the OSGi framework offers natively.

[IMPORTANT]
.Why this lands before 2D
====
2D adds `networknt` to the OSGi side. If `networknt` follows jackson's *current* disposition
(flat + mirrored, one shared copy), 2D would deepen the very sharing 2C's seam made unnecessary.
The uniformity principle (CLAUDE.md) forbids a mixed pattern — `networknt` isolated while `jackson`
stays shared, or vice versa. So the disposition must be corrected for jackson *first*, as a derived
rule networknt then inherits for free. This increment moves jackson; 2D adds networknt onto the
corrected rule.
====

== The theorem this increment adds

After 2C, the two worlds gateway only opaque `Document(domain, coordinate, payload : String)`
values — no Java type crosses the seam. A library a world uses to *parse* that String (jackson on
both sides; networknt on the OSGi side from 2D) is therefore a *world-internal* concern: nothing
about it needs to be the same class on both sides. The theorem:

____
A third-party library a world uses is loaded by *that world's* classloader. The host loads its copy
flat (on the JCL); the OSGi world loads its copy as an installed bundle (its own bundle
classloader). The two copies never meet, because no type from such a library appears on the seam.
____

This is not something we *build* — it is the isolation the OSGi framework provides by construction
(separate bundle classloaders). The current state *defeats* it with one deliberate act:
`BootPlanner.deriveSystemExports` mirrors every model bundle's `Import-Package` into
`system.packages.extra`, so `doctor-core`'s `import com.fasterxml.jackson.databind` wires to the
*system bundle* (the host's flat jackson) instead of an isolated jackson bundle. The mirror
collapses the two copies into one. This increment stops collapsing them.

[NOTE]
.Embedded vs remote — both isolate, the proof differs
====
In the *embedded* topology (host + framework in one JVM), the framework enforces isolation through
separate bundle classloaders: `doctor-core` sees a different `ObjectMapper.class` than `seed-outcluster`.
The proof is the in-container suite (`-Pall-worlds`): were a jackson type to cross the seam, two
distinct `Class` objects would meet and raise `LinkageError` / `ClassCastException` in-container —
the failure `DuplicateRealmClass`'s javadoc names. In the *remote* topology (the capstone — host and
framework in separate OS processes), isolation is *in situ*: two processes share no classpath at
all. Both topologies isolate; the embedded one is what this increment's tests exercise.
====

== The derivation rule — no hand-list

The disposition is *derived from what the bundles declare*, exactly as the staging extension already
derives everything (`StagingClosure`'s doctrine: "derive what to stage from what the bundles declare,
never a hand-list"). The rule:

____
A *realm library* is a third-party OSGi bundle (carries a `Bundle-SymbolicName`, is not under
`io.seedmatic.rke2lab.*`, is not the framework launcher, and is not a `type=seam` carrier) whose
package is imported by a `model`/`edge`/`record` bundle. A realm library is *staged as a bundle*
(the OSGi world loads its own copy) AND *kept flat* where the host imports it (the host loads its own
copy on the JCL).
____

Today that rule selects jackson's five jars (`jackson-core`, `jackson-databind`,
`jackson-annotations`, `jackson-dataformat-yaml`, `snakeyaml`). With 2D it will also select
`networknt:json-schema-validator` and `com.ethlo.time:itu` — *with no code change*, because both
carry clean OSGi manifests and `doctor-core` will import `com.networknt.schema`. The rule, not a
list, decides.

The contrast with the existing dispositions, all already keyed on the same `EmbedCapability` type:

[cols="1,2,2",options="header"]
|===
| carrier kind | how it loads today | unchanged?

| `type=seam` (seed-broker-port — the sole surviving seam)
| system-exported — ONE copy, shared host↔framework. Its reason to exist.
| YES — the one seam stays shared. The seam is the membrane; sharing is its job.

| `type=model` / `edge` / `record` / `contract` (doctor-core, manifests-core, doctor-contract, manifests-contract, …)
| installed as a bundle, exports never mirrored (the leak guard already removes them). The domain
  contracts (former `-port`s, now `type=contract`) are here too: installed and wired bundle-to-bundle
  inside the OSGi world, never system-exported.
| YES — already isolated bundle-side.

| third-party library a model imports (jackson, snakeyaml; networknt with 2D)
| *flat + mirrored* into `system.packages.extra` — ONE copy, shared. **The defect.**
| **NO — becomes flat∧staged: two isolated copies.**

| boot-stack (felix.scr, pax, …)
| installed as bundles (by `BootStackJar` name); host keeps its own off the JCL.
| YES — already the flat∧staged shape we now generalise.
|===

== The three mechanism deltas

All three are *refinements of the existing flat-coverage logic*, mirrored at build time and runtime.

[cols="1,3",options="header"]
|===
| site | change

| *`StagingClosure` (build-time stage set)*
| `indexHostFlatPackages` (lines 115-121) currently folds *every* package a `model`/`edge` bundle
  imports into `hostFlatPackages`, which makes `close()` (line 142) skip staging jackson — it stays
  flat-only. The refinement: a third-party OSGi bundle exporting a model-imported package is a realm
  library → it MUST be staged (added to the closure) even though the host also serves it flat. The
  `hostFlatPackages` short-circuit must no longer suppress staging a realm library; it must still
  suppress staging a *seam* package (a seam is genuinely host-flat-only). `isStageable` already
  excludes `launcher()` and `isSeam()` — the realm-library case rides on that exact predicate.

| *`StagingExecutionStrategy.injectShadeExcludes` (build-time shade)*
| Lines 495-510 add a shade `<exclude>` for *every* `closure.stagedGas()` — staged ⟹ excluded from
  the flat uber-jar, a 1:1 coupling. The refinement: decouple "staged" from "excluded". A realm
  library is staged as a bundle AND *kept in the shade* (the host needs it flat for its own codec).
  Only OUR bundles + the boot-stack are excluded from the shade; a realm library is the exception
  that is both.

| *`BootPlanner.deriveSystemExports` (runtime mirror)*
| Lines 154 + 164-180 already remove from `system.packages.extra` any package an *installed bundle*
  exports (it is the sole in-framework provider — the leak guard, today scoped to domain bundles).
  The refinement: a staged realm-library bundle is also an installed in-framework provider, so its
  exported packages must likewise be dropped from the mirror. Once jackson is a staged bundle,
  `doctor-core`'s jackson import wires bundle-to-bundle, NOT to the system bundle. The mirror stops
  collapsing the copies.
|===

== The gate law — `DUPLICATE_REALM_CLASS` derives its exemption from seam purity

Staging a realm library while keeping it flat creates the *flat∧staged* shape `DUPLICATE_REALM_CLASS`
forbids (today only `org.slf4j` is exempt, by a hand-list `ALLOWED_SHARED_ROOTS`, for an orthogonal
pax reason). The law must now express *why* flat∧staged is safe here — and the answer is precisely
the user's invariant:

____
A flat∧staged package is a dangerous duplication only if a type from it can *cross the seam*. It
cannot cross if no `type=seam` bundle's exported-package surface contains it. So: a flat∧staged
package is exempt from `DUPLICATE_REALM_CLASS` if and only if it is absent from the union of all
`type=seam` bundles' exported packages.
____

This turns the invariant "the library does not transpire into seed-broker-port" *into the gate's check*.
It is self-enforcing: the day someone makes a seam import jackson, that package enters the seam
surface, loses the exemption, and the build breaks — surfacing the leak at build time, exactly as
`REALM_BOUNDARY` surfaces a type leak. No hand-list; the exemption is *derived* from the seam
capability, the same source the rest of the design reads.

[NOTE]
.The fate of `org.slf4j`
====
`org.slf4j` is flat∧staged for a different reason (pax-logging-api is its sole in-framework provider;
`BootPlanner` drops it from the mirror so the binder is not split — the R1 scar). It is not a
realm-library case and not a seam package. The spec's default is that the seam-derived exemption
*replaces* `ALLOWED_SHARED_ROOTS` entirely: `org.slf4j` is absent from every seam's surface, so the
derived rule already exempts it, and the hand-list can be deleted (no-dead-code). The plan verifies
this empirically (slf4j is in no seam's `Export-Package`); if some seam unexpectedly surfaces slf4j,
the plan keeps the pax exemption as a documented, narrow special case rather than widening the
derived rule. Derivation first; hand-list only if the evidence forces it.
====

== Scope — verified breadth

* *Realm libraries today:* jackson's closure — `jackson-core`, `jackson-databind`,
  `jackson-annotations`, `jackson-dataformat-yaml`, `snakeyaml`. All five carry native OSGi manifests
  (`Bundle-SymbolicName` + `Export-Package`), so each stages as a bundle with zero wrapping.
* *Model bundles that import jackson:* exactly two — `doctor-core` (`jackson-core` + `databind`) and
  `manifests-core` (those plus `jackson-dataformat-yaml` + `snakeyaml`). No `edge`, no `record`, no
  `seam` imports jackson.
* *Host side:* `seed-outcluster` declares jackson compile-scope (shades flat — its own codec). The other
  two exec entrypoints (`netplan-cli`, `manifests-cli`) share the build-parent shade config;
  `manifests-cli` embeds `manifests-core` so the staged-bundle jackson must resolve for it too.
* *Seam purity holds today:* the sole seam, seed-broker-port, does not import jackson — the derived
  exemption is satisfied at the outset. (The domain contracts doctor-contract / manifests-contract are
  no longer seams — they are installed `type=contract` bundles, wired bundle-to-bundle — so they do not
  enter the seam surface even where they touch jackson.)

== What "green" means

* Full reactor `package -Pall-worlds` BUILD SUCCESS — the OSGi framework resolves with jackson as a
  staged bundle (the bundle-to-bundle wire replaces the system-bundle wire).
* `DUPLICATE_REALM_CLASS` stays at `ERROR` and reports *zero* violations: jackson's flat∧staged
  packages are exempt because they are absent from every seam surface; the existing slf4j case is
  either subsumed by the derivation or kept as the documented narrow exception.
* `REALM_BOUNDARY` stays at `ERROR`, unchanged (this increment moves no type across a realm).
* The doctor in-container tests pass — the parse/serialize round-trips still work with `doctor-core`
  wired to the staged jackson bundle, proving the isolated copy is functional.
* The host `pulumi preview` stays green (the host codec still has its flat jackson).

== Scope boundary — where this increment stops

* It does NOT add networknt — that is 2D. This increment establishes the *rule* networknt will be
  selected by; 2D adds the dependency and the rule picks it up.
* It does NOT change the `Document` record, the seam, or any payload shape — purely a build/runtime
  *disposition* of third-party jars.
* It does NOT touch the remote capstone — but it is what makes the capstone's process split trivial
  (each process already loads its own library copies; the remote case is the same isolation, in situ).

== Follow-up — the jsr310 ServiceLoader regression and `Cdk8sApps`

Staging `jackson-databind` as its own bundle was correct for the static-import graph, but it broke a
path the import graph cannot see: *runtime* module discovery. `jsii-runtime` (under the
`manifests-cdk8s` carrier) builds an `ObjectMapper` and calls `findAndRegisterModules()`, which runs
`ServiceLoader<com.fasterxml.jackson.databind.Module>`. `ServiceLoader` reads `META-INF/services` off
the *thread context classloader*, NOT through OSGi package wiring. `jackson-datatype-jsr310` is
runtime-discovered (no model statically imports it), so the realm-library rule never staged it — it
stayed flat. With `databind` now a bundle, the flat `JavaTimeModule` extended the *flat* `Module`
while jsii saw the *bundle* `Module`, and jsii failed with `ServiceConfigurationError: JavaTimeModule
not a subtype` — fatal in the deployed exec-jar's "cdk8s setup" synthesis, though both the reactor
gate and the in-container tests were green.

The coverage gap that hid it: `EmbeddedBundlesBootTest` booted the staged topology but only
`awaitService(...)` — it never RAN a synthesis. The fix begins with closing that gap (a test that
calls `ManifestSynthesisService.synthesize` on the staged bundles, reproducing the error as a build
failure), then:

* *Nest jsr310 in the carrier.* `manifests-cdk8s/bnd.bnd` adds `jackson-datatype-jsr310-*.jar;lib:=true`
  to its `-includeresource`, putting jsr310's classes AND its `META-INF/services` on the carrier's
  Bundle-ClassPath — the same classloader that imports the `databind` bundle, so there is one
  `Module` view.
* *Pin the TCCL at the jsii entry point.* `Cdk8sApps.create(AppProps)` — the carrier's sole `App`
  factory — sets the thread context classloader to the carrier's loader for the construction, so
  `ServiceLoader` resolves the nested jsr310 rather than the host-flat copy. `manifests-core`'s
  synthesis calls `Cdk8sApps.create(...)` instead of `new App(...)`. The bundle that embeds the
  closure owns its classloader contract; callers stay ignorant of the TCCL.

This is the general shape for any cross-jar `ServiceLoader` SPI embedded in a carrier: nest the
provider jar with the consumer, and pin the TCCL to the carrier at the call that triggers discovery.
