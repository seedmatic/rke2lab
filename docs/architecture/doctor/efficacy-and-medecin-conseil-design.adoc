== Overview — what problem this solves

A problem was prescribed for, then it resolved. The question efficacy must answer is honest only if
it asks: did our treatment work, or did *something else* heal the patient? Crediting our own
prescription for a resolution something else caused is *confounding* — and it poisons every future
decision that trusts "this remedy worked before".

The actor that answers this is the *médecin-conseil* — by analogy with the French health system, a
doctor employed by the *system* (l'Assurance Maladie), not by the patient. He does not heal. He
reviews, a posteriori, whether treatments were effective, and reports. In our model this is the role
the `DriftSpecialist` was groping toward without a name.

The real driver is the upcoming *efficacy-first gate*
(provisional — memory `efficacy-first-prescription-provisional`): before
re-prescribing a remedy, consult whether it actually worked. That decision needs an honest efficacy
*report* — which is what the médecin-conseil produces.

*The médecin-conseil writes nothing.* This is the decisive property: dropping the external-change
inference (below) removes the only write the `DriftSpecialist` had (`writer.append`). The analyst
reads the ledger and the record, and produces a report — it touches neither the live system (that is
the Remediator's confined risk) nor the dossier. It is *pure by construction*, which dissolves the
question "does its write violate the doctor's purity?".

== The three efficacy verdicts (one measurement, not "two kinds of drift")

Efficacy is not a permanent state; it is a *measurement* of one prescription, yielding one of three
verdicts:

[cols="1,2,1",options="header"]
|===
| verdict | observation | creditable to us?

| *effective*
| administered → the symptom does NOT recur at the next visit
| YES

| *ineffective*
| administered → the symptom PERSISTS / recurs
| NO — plain therapeutic failure

| *confounded-declared*
| symptom resolved, but a KNOWN operator-declared intervention in the window explains it
| NO — we cannot tell it was us
|===

"Drift" is therefore *not an actor* — it is what makes an attempt *non-creditable* (ineffective or
confounded). `ineffective` is the most reliable signal: it does not depend on the operator's
declarative discipline. `confounded-declared` depends on a declared `OPERATOR_MANUAL` intervention
(see <<external>>).

This supersedes the thin `TreatmentEfficacy.everWorked()` boolean, which folds *all* history into a
single "ever worked" with no interval, no references, no explanation kept.

[#external]
== External intervention — recorded when KNOWN, never INFERRED

An out-of-band change (the operator runs `nft delete ...`, or something external acts) WILL happen,
and the patient's history must be able to *mention* it. But the médecin-conseil must not *guess* it.
Two gestures the old `DriftSpecialist` fused, now separated:

[cols="1,2",options="header"]
|===
| gesture | verdict

| *inferring* "external" by absence ("nothing explains it → must be external")
| DROPPED — fragile: it cannot tell a true external change from an operator who forgot to declare.

| *recording* a KNOWN external intervention in the history
| KEPT — but it enters only by *declaration* (`OPERATOR_MANUAL` via `RecordInterventionCommand`,
  already built) or, one day, by *observation* (compare observed vs expected state). Never by guess.
|===

So when a symptom resolves and *no known fact* explains it, the médecin-conseil does NOT write an
efficacy verdict. It SIGNALS that a phenomenon is unmodelled — a *renvoi to recruitment* (see
link:runbook-doctor.adoc[the runbook §recruiting-a-specialist]). The external intervention, if real,
is characterised and entered into the history *during* a recruitment, not by the analyst.

== The EfficacyReport — bounded, dated, keeps its references

The report is the médecin-conseil's product. Three requirements fix its shape (the *maille* —
exactly which fields — is deferred; the spirit is settled):

. *bounded to an interval* `[from, to]` — a measurement valid for that window, not "since forever".
. *dated* `measuredAt` — taken at an instant; re-measurable later as another report.
. *keeps references, not copies* — each finding POINTS to the problem consultation and the resolved
  symptom (same spirit as the path-addressing in
  the multiplexor design — memory `multiplexor-two-models-design`), and keeps
  the *why* — the explanation the `DriftSpecialist`'s returned `ReferralReply` letters carry today
  and which `reviewOpenProblems`' caller currently *discards*.

[mermaid]
....
flowchart TB
  subgraph report["EfficacyReport"]

    fs["findings : List&lt;Finding&gt;"]
  end
  subgraph finding["Finding (per symptom/prescription)"]
    v["verdict: effective | ineffective | confounded-declared"]
    rc["→ ref: problem consultation"]
    rs["→ ref: resolved symptom"]
    why["the why (kept, not thrown)"]
  end
  report --> finding
  rep_consumer["the efficacy-first GATE / the operator runbook"]
  report --> rep_consumer
  classDef new fill:#ddf,stroke:#22a,stroke-width:2px;

....

The GATE consumes the *report*, not a boolean: "do not re-prescribe X — ineffective on the last
interval, see consultation Y". This closes a circuit that is open today: the drift letters are
produced and then dropped.

== Existing types this design governs (were drifted out of the specs)

[cols="1,2",options="header"]
|===
| type | role in this model

| `TreatmentEfficacy` (record) — *SUPERSEDED by `EfficacyReport`*
| the as-built thin measurement (`symptom` + `List<Attempt>`, `everWorked()`); the bounded
  `EfficacyReport` replaces it. `Attempt(version, programRef, recurred, confounded)`. The type is
  marked `@Transitional(to = "EfficacyReport")` in code — the two-way link: code points here, this
  spec names what it replaces.

| `ProblemReview` (record)
| the transient request handed to the analyst: `problem`, `expectation`, `priorVisit`, `nextVisit`,
  `ledger` — the window `(prior, next]` it measures over.

| `Intervention` / `Provenance`
| the ledger entries the analyst reads. `OPERATOR_MANUAL` = the operator's declaration;
  `PULUMI_ENGINE` = our own engine; `EXTERNAL_CHANGE_DETECTED` = the inferred verdict this design
  STOPS minting.

| `SymptomHistory`
| the longitudinal view of one symptom across visits the analyst folds over.

| `ProblemRef` (record)
| the problem-oriented join key shared by three actors: the generalist OPENS a problem when a symptom
  appears at a checkpoint, the operator DECLARES interventions against it, the analyst EXPLAINS its
  resolutions. `(Checkpoint, Optional<Symptom>)` — a checkpoint-only ref explains every symptom there;
  a symptom-specific ref explains only its own.

| `ExpectationPredicate` (sealed) / `ResolutionPredicate` (record)
| the EXTENSION SEAM for "what a prescription expects at the next visit". A sealed ADT: today the only
  permit is `ResolutionPredicate` (the symptom is gone); a future analyst will want a richer one (e.g.
  a `FingerprintPredicate` diffing observed state) — it slots in without touching callers. This is the
  observed-vs-expected detection axis the brainstorm flagged as the reliable, declaration-independent
  drift signal.
|===

== Anti-patterns (what this design forbids)

* ❌ *Infer "external" from absence.* "Nothing explains the resolution → external change" is a guess
  that masquerades as a fact. ✅ Record external interventions only when declared or observed.
* ❌ *Let the analyst write to the ledger.* A reader that writes is no longer an analyst. ✅ It
  produces a report; declarations are written by the operator's command.
* ❌ *Throw the explanation away.* Returning verdicts as a bare boolean (`everWorked()`) or
  discarding the `ReferralReply` letters loses the "why". ✅ The report keeps a reference to the
  reasoning.
* ❌ *Measure "since forever".* An unbounded verdict cannot be re-evaluated as the world changes. ✅
  Every report is bounded to an interval and dated.

== Deferred (the maille — settle with real recruitment use-cases)

* report per-run (all symptoms) or per-symptom?
* the 3-verdict set final, or more?
* references point to what exactly — `ConsultationReport`, `Expectation`, `Visit`?
* the interval — the last two visits, or an explicit `[from, to]` passed in?
* the analyst's SPI placement: a third `Clinician` species, or a system-employed reviewer tier
  distinct from `Specialist`/`Remediator`? (it stays core-internal either way: no `domain()`,
  per-run, reads the run's ledger — same non-distributing profile as the Generalist.)
