**Contexte (2026-09-17) :** `nerd-nixos` tournait alors sur le **baremetal de nikopol** (Tart VM sur le Mac corp, config `nikopol-nixos`), PAS sur bioskop. `ssh nerd-nixos -- hostname` répondait `bioskop` ; `ssh root@nerd-nixos.local` répondait `nerd-nixos`. Deux bugs distincts, tous deux corrigés à la source dans ndh (`develop`, commits `6d0e7eff` + `402bb31d` + `e40efa3e`).

**Bug 1 — ProxyCommand `tart ip` fantôme.** Le bloc `Host nerd-nixos` du `~/.ssh/config` généré portait un `ProxyCommand sh -c 'nc "$(tart ip %h)" 22'` (source : `modules/darwin/tart-config.nix`, matchBlock `hm.programs.ssh.settings."${cfg.vmName}"`, gardé par `tartBinaryPath != ""`). Vestige de l'époque où nerd-nixos était une VM Tart LOCALE ; maintenant `tart ip nerd-nixos` ne renvoie rien sur ce Mac → misroute silencieux. **Piège de diagnostic clé : `ssh nerd-nixos` (alias) applique le ProxyCommand, mais `ssh root@nerd-nixos.local` NE matche PAS le bloc `Host nerd-nixos` (cible = le FQDN, pas l'alias) → pas de ProxyCommand → connexion directe qui marche.** Outil décisif = `ssh -G <cible>` (config effective résolue). Fix = retrait du bloc + stanza direct déclaratif `nerdNixosAlias` dans `modules/home-manager/ssh-tailnet-hosts.nix` (mDNS `.local`, `User root`, clé rdp-host `config.sshPaths.privKeyFile`, `IdentityFile none` reset ; couvert par le wildcard `Host *-nixos` pour known_hosts). Rendu uniformément sur tous les Macs (comme les alias vzhost).

**Bug 2 — TMPDIR trop long pour un socket unix (limite macOS 104 o).** `nixos-rebuild --target-host` (nixos-rebuild-ng) impose son propre `NIX_SSHOPTS` avec `ControlPath=$TMPDIR/nixos-rebuild.XXXXXXXX/ssh-%C`. Le nom de socket imbriqué APRÈS `$TMPDIR` = **~85 chars fixes** (`/nixos-rebuild.`=15 + mkdtemp 8 + `/ssh-`=5 + hash `%C` SHA1=40 + `.`+suffixe temp ssh=17). `sun_path` macOS = 104 o (103 utilisables) → **len(TMPDIR) ≤ 18**. Le TMPDIR ndh était `~/.tmpfs` = `/Users/nxmatic/.tmpfs` (21) → 106 > 104 → `unix_listener: path "…" too long for Unix domain socket` → `error: failed to start SSH connection`. **Ne PAS dériver TMPDIR du username** : `/tmp/.stephane.lacoin` (Mac corp) = 21 → re-péterait. Fix = chemin fixe court `/tmp/.nxmatic` (13 → 98, marge 5). `~/.tmpfs` était un VRAI tmpfs 4 Go monté par `modules/home-manager/tmpdir-tmpfs.nix` (launchd `RunAtLoad` + script `tmpdir-tmpfs.sh` qui `mkdir -p` + `mount_tmpfs`) ; l'option `mountPoint` sert à la fois de mountpoint ET de `TMPDIR` (single source). Fix = changer son `default` → `/tmp/.nxmatic` ; `/tmp` vidé au reboot mais l'agent RunAtLoad re-crée+re-monte au login. Ancien mount `~/.tmpfs` traîne jusqu'au reboot (`sudo umount` optionnel). **Gotcha symlink (fix `64f1177e`) : `/tmp`→`/private/tmp`, donc `mount_tmpfs /tmp/.nxmatic` monte sur `/private/tmp/.nxmatic` ; le garde d'idempotence de `tmpdir-tmpfs.sh` cherchait `" on $MP (tmpfs"` littéral → jamais matché sous chemin symlinké → EMPILE un mount à chaque login. Fix = comparer aussi le chemin résolu `pwd -P`. Le `TMPDIR` publié reste le court `/tmp/.nxmatic` (ne pas résoudre : `/private/tmp/.nxmatic`=17 → marge 1).**

**Application :** darwin-rebuild switch home-manager → régénère `~/.ssh/config` + plist tmpfs + sessionVar TMPDIR. Le nouveau TMPDIR n'entre que dans les NOUVEAUX shells (re-login, ou `launchctl kickstart -k gui/$(id -u)/io.seedmatic.ndh.tmpdir-tmpfs` + nouveau terminal). Supprimer aussi les fichiers manuels `~/.ssh/config.d/nerd-nixos.conf{,~}` (doublon avec le stanza généré).
