**Tailnet stale-device GC — the deterministic trigger FOUND (design converged 2026-09-02, NOT coded).**

**Problem** (render-loop backlog item 4, see [[manifests-publish-in-cluster-render]]): on a cold-start / re-grow the incus master is deleted+recreated, but its tailscale devices (headscale/tailscale, incl. the PaC `pac-webhook` device via the tailscale operator) linger in the tailnet → the new node's devices get a `-N` suffix (`pac-webhook-2.mammoth-skate.ts.net`) → the GitHub App webhook (pointed at `pac-webhook…`) delivers to the dead device → PaC never fires the render. The open question was always the DETERMINISTic TRIGGER (the operator has no ephemeral knob; a steady-state re-grow doesn't touch it).

**★ The trigger = incus instance renewal.** In `host/pulumi/incus-ingress/.../InstanceGrow.java` `createInstance()`, the `Instance "seed-instance"` has `deleteBeforeReplace(true)` + `replaceOnChanges(["config","config.*"])`; a cold-start/rebuild changes `user.rke2lab.imageBuildChecksum` / `imageFingerprint` → delete+recreate. That IS the exact moment the old node's devices go stale.

**Design (user-driven):** a `com.pulumi.command.local.Command` (NEW dep `com.pulumi:command` — no Command usage exists host-side yet) in InstanceGrow, `triggers=[imageFingerprint]` (re-fires on instance replacement), `create` = `sleep <delay>; manage-tailnet --prune-stale-devices --stale-after <threshold> --yes`.
- **Delay is REQUIRED** (user's point): tailscale doesn't mark a device offline instantly, and `--prune-stale-devices --stale-after <t>` only deletes devices offline LONGER than t. So `sleep` (a few s → ~15-30s) lets Tailscale register the just-deleted node offline + exceed the threshold. `--stale-after` short enough to catch the fresh-offline node; single-node cluster → only the master's devices are tagged → low prune risk. `--yes` needed (dry-run by default).
- **The binary** = ndh flake output `inputs.ndh.apps.${system}.manage-tailnet` (type app; darwin, built via `ndhStoreApiDarwin`). rke2lab ALREADY has `ndh.url="github:seedmatic/ndh/develop"` as a flake input → reachable, NO ndh checkout needed for the binary. Src: `ndh:modules/.common.d/manage-tailnet.d/manage-tailnet.sh`.
- **The auth** = the Tailscale SaaS API (`api.tailscale.com/api/v2`), OAuth client-secret → short-lived token. `manage-tailnet` currently HARDCODES reading its OWN `.secrets` via sops (`[tailnet][tailscale][client]`, requires cwd=ndh repo root + `[ -f .secrets ]` guard + sops age key). To use from rke2lab WITHOUT the ndh checkout/sops → **parameterize manage-tailnet to accept the OAuth client_secret via env/arg on the prune path** (ndh change).
- **Creds source** = rke2lab's own tailscale OAuth. `.secrets` (rke2lab) has `kubernetes.…tailscale = {name: operator-oauth, replicateTo: [mesh-system]}` (the REPLICATION POINTER only) + `TailscaleManifestsUnit` renders `Secret operator-oauth {client_id, client_secret}` (replicated from source). Same tailnet (mammoth-skate), operator OAuth has device-write scope → has delete for prune. **KEY MODE FACT (user):** in STANDALONE/dev the worktree `.secrets` is CLEAR (`.gitattributes: .secrets filter=sops-yaml` smudges it on checkout — verified 0 `ENC[`, no `sops:` block); IN-CLUSTER the git sops filter is NOT configured → `.secrets` stays encrypted. **★★ PIVOT — MOVE THE PRUNE IN-CLUSTER (design converged 2026-09-05, mid-implementation).** The Pulumi-Command approach above (`InstanceGrow.pruneStaleTailnetDevicesOnReplace`) aimed at the WRONG layer: the funnel devices (`pipelines-webhook`, `flux-webhook`, `headplane`, `headscale`, `controlplane`) are NOT registered at the incus instance boot — they are registered IN-CLUSTER by the tailscale operator when the funnel Ingresses reconcile (late in the grow, via Flux). And `deleteBeforeReplace(true)` makes the delete+create ONE atomic replace → no hook "between delete and create". So the incus-lifecycle prune couldn't gate registration. **The funnel DEPLOYMENT is the precise, controllable gate point** (user's insight: "gate le déploiement du funnel … ou un hook sur le déploiement des funnels pour procéder à la purge").

**The in-cluster design (settled, 5 pieces):**
1. **A mesh purge unit** (NEW `TailnetPurgeManifestsUnit`, operators layer): a Job `tailnet-purge` that loops `manage-tailnet --prune-stale-devices --stale-after 1s --yes --format=json`, parses `select(.event == "pruned")` (yq-go), retries until a pass emits NO pruned events, returns. Mounts `operator-oauth`'s `client_secret` key as a file → `--client-secret-file` (ndh reads the file RAW as the OAuth `client_secret`; Tailscale accepts the `tskey-client-…` alone — NO sops, NO composition, NO kube RBAC beyond mounting the secret in mesh-system).
2. **Gate (Flux `dependsOn`):** `mesh-tailscale-operators` gains `dependsOn: mesh-tailnet-purge` → the operator (hence ALL proxies) deploys only after a clean tailnet. One gate covers funnel + controlplane + the operator's own device. Safe by construction: purge runs before the new cluster registers anything; `--stale-after` is the double safety.
3. **`manage-tailnet` in-cluster** = re-exported from ndh (PUBLIC — user confirmed; + nix has/should-have a GH token anyway) as an output of the CATALOG flake `runtime/flox/flake.nix`, delivered via a FloxEnv like kdns/headscale (NOT a private-repo fetch).
4. **Delete** `InstanceGrow.pruneStaleTailnetDevicesOnReplace` (the shipped Pulumi Command above — SUPERSEDED dead code) + the `com.pulumi:command` dep if unused elsewhere.
5. (retry semantics: active loop, not `--stale-after 90s` passive wait; on cold start the old cluster's devices are the only tagged offline ones → prune until empty.)
