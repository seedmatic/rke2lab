**C7 — greenfield node networking + zfs (SHIPPÉ 2026-09-16, cold-start-validation PENDANTE).** Les nodes greenfield CAPRKE2 montaient avec `lo` seul (LXCMachine sans NICs) et ne pouvaient pas monter le dataset zfs containerd. Fix "Path 2" (dynamique, PAS de MAC déterministe) shippé sur 3 repos : seed-incluster `14d392e33`, rke2lab feature/nixos-node-substrate `8459d3b66`, flox-catalogue `a80ece0dd`.

**Le refactor profils incus :** le profil `rke2lab` renommé **`node`** (root disk + raw.lxc + security.* + linux.kernel_modules + kmsg/zfs unix-char = config commune SSOT standalone+CAPN) ; nouveau **`node-<cluster>`** par cluster co-localisé (lan0 sur lan-br + vmnet0 sur vmnet-<role>, **DYNAMIQUES sans hwaddr**). `lxcMachineSpec` (Go) ne porte plus QUE `profiles: [node, node-<cluster>]` + image (drop config/devices — "caprke2 ne référence que des profils"). `GrowNetworkView` re-keyé par cluster (`ClusterBridge{bridgeName,config}`) pour nommer les profils ; `InstanceGrow.ensureNodeProfiles` les crée au grow. Le standalone garde ses NICs par-instance déterministes (hwaddr blueprint) + réf `node`. La plage DHCP dynamique existait DÉJÀ sur le bridge (`GrowNetworkResolver:74-75` ipv4.dhcp + ipv4.dhcp.ranges=wanDhcpRange) → un node random-MAC prend une IP ; avahi/mDNS est IP-agnostique → pas de réservation.

**Conclusions de design GRAVÉES (dures) :**
- **CAPI ne peut PAS distribuer une valeur par-réplica** sur le control-plane (vérifié doc CAPI write-clusterclass) : `files`/template du RCP = UN template partagé, cloné N fois ; pas de `builtin.controlPlane.machine.index` (Perplexity hallucinait). Donc MAC/hostname/IP déterministes par-nœud = **impossibles en greenfield** (cattle). Le seul chemin per-nœud = **`Machine`+`LXCMachine` individuelles = le bras ADOPT** (pets). ClusterClass n'y change rien (usine à templates, pas distributeur).
- **La config rke2 par-cluster du greenfield est DÉJÀ livrée — le bon path existait** : le controller lit les ConfigMaps rendus (Flux) via `clusterConfigFiles` → les injecte dans `RKE2ControlPlane.spec.files` → CAPRKE2 write_files → **SECRET-FREE (pas de fetch git ni token sur le node)**, gaté sur Flux. Meilleur que le path node-fetch (`install-rke2-config`) du standalone. Pas de gap.
- **zfs containerd (containerd.nix)** : le service `rke2lab-zfs-containerd` est MANDATAIRE (contrairement aux autres consommateurs de node.env qui `ConditionPathExists`-skip sur greenfield : node-labels/provider-id/node-ip viennent de CAPN/CAPRKE2). Fix = node.env optionnel (`-`), nom de dataset **auto-dérivé du hostname** si absent, + **crée-si-absent** avant mount (pool `tank` in-container → le node owns `zfs create`). DataplanLayout bake `control-nodes/{master,peer1,peer2,peer3}` — un nom random greenfield n'y est pas → d'où le create.

**Follow-ups (gravés, hors C7) :**
- **avahi alias `.local`** : greenfield garde son hostname random CAPRKE2 (identity.nix no-op sans node.env, kubelet/CAPN OK) ; avahi publie EN PLUS un `.local` stable aliasé (extra record, comme le fork tailscale) → nom stable sans désync.
- **MAC/netplan déterministe = bras ADOPT** : cloud-init per-Machine via `bootstrapSecretObj(nodeName)` (aujourd'hui sentinelle vide car node déjà running) → poser MAC blueprint + hostname + reconfig netplan → IP réservée. À coder quand on fera l'adopt déterministe.
- **App renommée** `propagate-seed-incluster` → **`update-flox-envs`** (hop-3 re-lock TOUS les envs via `lock-envs` du flox-catalogue).

**MAJ 2026-09-16 (live iteration — le début du fichier est superséé sur des détails) :**
- **Nom final = `node-base`** (PAS `node`) — convention HARDCODÉE des deux côtés (InstanceGrow `NODE_BASE_PROFILE` Java + littéral Go controller), le knob Pulumi `rke2lab:profile:name` + tout le plumbing `BootstrapConfig.profileName`/`IngressConfig.profileName`/`Rke2labConfig.ProfileConfig` SUPPRIMÉS. Le knob pointait `Pulumi.dev.yaml:profile:name` (lu au RUNTIME par pulumi up, pas le build-cache) — c'était le vrai maillon, pas le défaut Go.
- **Split corrigé** : `node-base` = root+config+kmsg+zfs+**lan0** (lan-br partagé, une fois) ; `node-<cluster>` = **vmnet0 seul**. Instance = `[node-<cluster>, node-base]` (node-base LAST = précédence incus), les deux via **liste d'Output** (`ensureNodeProfiles` retourne l'Output du cluster grown) → les deux dépendances profil-avant-instance threadées.
- **STANDALONE VALIDÉ LIVE** : master sur `[node-bioskop-mgmt, node-base]`, NICs inline hwaddr déterministes (override les dynamiques du profil), voit `tank`+`/dev/zfs`, `rke2lab` supprimé.
- **GOTCHA CAPN (dur)** : CAPN applique un de ses **profils embarqués** (`internal/static/embed/{kind,kubeadm,unprivileged*}.yaml`, v0.9.0) au niveau **config d'instance** → **override les profils** ; TOUS posent `linux.kernel_modules` AVEC la trio legacy `ip_tables/ip6_tables/iptable_raw` → **FATAL modprobe sur kernel-6.18** (nftables-only). Fix : re-asserter `linux.kernel_modules` (safe, trio retirée) + raw.lxc/security **INLINE sur `LXCMachine.spec.config`** (spec.config gagne sur l'embedded) — PAS sur le profil (overridé). `lxcMachineSpec` reporte donc le config inline (commit `f4ea02e31`).
- **GAP `ensure` = create-if-absent** (`controller_shared.go:65`) : le controller ne réconcilie JAMAIS la dérive du LXCMachineTemplate/RCP → un changement de spec (profils, image fingerprint, kernel_modules) ne se propage pas → **delete manuel du template/RCP** requis (safe pour greenfield jamais-up ; DANGEREUX pour un cluster running = nuke le CP). **DESIGN follow-up gravé** : SSA-apply systématique (idempotent) pour les ressources mutables (RCP/Machine/LXCMachine/Secret) + **LXCMachineTemplate content-addressé** (nom = hash du spec, immutable-safe) + repoint `RCP.machineTemplate.infrastructureRef` → **rollout CAPRKE2** (zéro downtime CP), GC des vieux. `generation` ne suffit PAS (les profils hardcodés côté controller ne bumpent pas la generation de l'intention) → clé = content-hash.
- **Reflector write-token — RÉSOLU en code (2026-09-16, deploy en cours)** : le reflector push 403ait (`Permission denied to seedmatic-rke2lab[bot]`) car `github-token` est `contents:READ` (least-privilege Flux/nix). Les tokens d'installation GitHub App sont scopés par permission → un read ne peut pas push. Fix : **2ème `ClusterToken` de la MÊME App gtm avec `contents:write`** → minte `github-token-write` dans `rke2lab-secrets` + réplique (mittwald `replicate-from` stub dans `rke2lab-system`, ajouté par `SeedInclusterManifestsUnit`) ; le reflector lit `rke2lab-system/github-token-write` (`main.go` default). Le `github-token` read inchangé. Commits rke2lab `664981cde`, seed-incluster `a66b4f02b`. **Deploy = 2 canaux** : les CR (ClusterToken+stub) sont des MANIFESTS → render+push `manifests/<cluster>` (Flux applique → gtm minte → réplique) ; le binaire controller → `update-flox-envs`. Ne bloquait PAS le provisioning initial, seulement la boucle greenfield→reflect→adopt.
