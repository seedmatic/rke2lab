= The host/OSGi frontier — playability, edges, and the membrane
:toc: left
:toclevels: 3

[NOTE]
====
*Status:* DESIGN (2026-06-21). A transverse model that sharpens the host/OSGi frontier. It emerged
mid-refactor during the doctor-model extraction and is recorded here at design level so every domain
reads against it, not just the doctor. The reserved vocabulary (`edge`, `ingress`/`egress`,
playability) is graved in the `system/space/world/universe` glossary; this doc carries the reasoning
and the vocabulary view.
====

== Why this model exists

The first cut of the frontier used a *describe-vs-actualise* lens ("pure model describes → osgi;
observation/rendering actualises → host"). Executing the doctor extraction, that lens mislabeled real
files: it flagged a type as "host" merely because it NAMED a host-shaped type, even when the type was a
pure record. A sharper, code-probable criterion surfaced — *playability* — and with it two reserved
words (`edge`, `ingress`/`egress`) that let us say what the old lens could not.

== The three orthogonal axes

The frontier is not one line but three independent axes. Confusing them is what made the old lens
mislabel files. The vocabulary view (Diagram 0) draws them so collisions surface at design time.

* *Axis 1 — purity / playability.* Can the third-party libraries a type needs resolve and run inside a
  Felix bundle? Pure JDK (`java.nio` files, `ProcessBuilder` commands) and Jackson ARE playable —
  touching the disk or spawning a process is never the disqualifier. `com.pulumi.*` and jgiven
  `com.tngtech.*` are NOT. This decides WHERE an impl can live (osgi-world vs host-world).
* *Axis 2 — edge.* Does the operation cross a boundary? An edge is what makes a *port* necessary, and
  it comes in two species (see <<two-species>>): an *external edge* crosses the SYSTEM boundary toward
  an outside system (Pulumi, k8s, systemd) — mutualised by target as `<target>-edge`; an *internal
  edge* is a domain's face toward the rest of OUR system. Either way the port is the membrane.
* *Axis 3 — direction.* Across the membrane, an operation is *ingress* (read from the world) or *egress*
  (write to the world). Used in prose and method names, never in module names (the k8s `Ingress`
  collision).

== The load-bearing claim: the port is the membrane of BOTH worlds

The port is reached *identically* whether the caller is in the OSGi world (a `core` bundle) or the host
world. The host has no privileged direct route to the external system — it too passes through the port.
There is never a second path ("direct host access" plus "a port for OSGi"); there is ONE door.

Consequence: if an edge's impl migrates host↔osgi (because its library becomes playable), callers are
unaffected — they were already going through the port. *The port decouples the domain not only from the
external system but from the edge's own world-of-residence.*

== Playability is orthogonal to edge — it does NOT eliminate ports

A tempting error: "we can read the Pulumi state in pure JDK, so it's playable, so put it in `core` and
drop the port." Wrong, and the orthogonality is the proof. Reading the state in pure JDK still REACHES
the state backend — it is still an edge; the port still protects the domain from the backend's file
format, location, and CLI flags. Dropping it would re-couple `core` to the world.

What playability *does* buy is migration: when an edge's lib is playable, the edge's IMPL can move from
a host module to an OSGi bundle — serving the standing goal of maximising what lives in the better
structured OSGi world — while the port and all callers stay put. So:

* ❌ "more playable logic in OSGi → fewer ports" — no, that re-couples.
* ✅ "more playable logic in OSGi → edges migrate host→osgi, ports stay" — yes, and that is the gain.

== What this simplifies (measured honestly)

The benefit is not that each port is easier to *type* — the seam that touches the world (pure-record
translation) is exactly as much work. The benefit is that *writing a port becomes a derivation, not a
judgement*:

* it removes ports we would have created in error (the `BootstrapConfig`-pure probes are `core`/ports,
  not edges with host impls — ports that no longer exist);
* it mutualises egress ports by target (one `pulumi-edge`, not one per domain);
* it replaces a fuzzy per-type judgement ("describe or actualise?") with a closed, code-probable
  question ("is this type's lib playable?", "does it reach an external system?").

A richer vocabulary that is *easier* to wield, because each new word CLOSES a question instead of
opening one: `world` closes "which classloader", `edge` closes "external contact?", `ingress`/`egress`
close "which direction". Three closed questions = three judgements removed.

== Worked example — the doctor domain

* `doctor-core` (osgi-world) — the ~48 pure diagnostic types; in-domain, never leaves.
* `doctor-contract` — the membrane: `SnapshotSource` plus the pure gateway records `SnapshotEntry` /
  `SnapshotView` that replace the host `StackSnapshot` / `StackHistory` at the boundary.
* `pulumi-edge` (host today) — the realised egress/ingress: `StackHandleSnapshotSource` (ingress, reads
  the timeline) and `PulumiInterventionLedgerWriter` (egress, writes the ledger). Mutualised: any other
  domain's Pulumi contact lives here too, not in a private doctor adapter.

The `BootstrapConfig`-pure probes (`ClusterReadinessProbe`, `SystemdAdapterProbe`) are *ports* (pure
functional interfaces), not edges — only their PRODUCTION impls that fetch the live world are
non-playable and belong to a `cluster-edge` / `systemd-edge`.

The doctor extraction (branch `refactor/doctor-model-to-osgi`) is the FIRST realisation of this whole
model end-to-end: it splits `doctor-core` (in-domain) / `doctor-contract` (membrane) / `pulumi-edge` (the
realised contact). Crucially, the edge it builds is `pulumi-edge` MUTUALISED BY TARGET — not a
`doctor-pulumi` private adapter. The two Pulumi contacts (state read + ledger write) are two faces of
ONE shared edge that every Pulumi-touching domain uses.

== Every port traces to an edge (no orphans)

A discipline the inventory confirmed on the facts: *every port traces to an edge* — directly (the port
gateways the external system's own state types) or transitively (the port describes a pure model the
host actualises against an external system downstream). A port that traces to NO edge is not a port —
it is a mis-named internal interface. The inventory found ZERO orphan ports, so the rule holds with no
counter-example.

[[two-species]]
== Two species of edge — internal and external (validated 2026-06-21)

An edge is any *boundary crossing*; there are two species, by WHICH boundary it crosses:

* *external edge* — crosses the SYSTEM boundary, toward a system OUTSIDE ours (pulumi, systemd,
  cluster, incus, ssh-to-age). Mutualised by target as `<target>-edge`. Often non-playable.
* *internal edge* — the face of a DOMAIN turned toward the rest of OUR system; crossed by other
  domains/orchestration through a pure port. This dissolves the earlier "transitive port" category:
  `manifests-contract`/`netplan-contract` do not "trace to no edge" — their consumer-facing side IS an internal
  edge. So *every port traces to an edge* holds with no orphan, no "transitive" exception.

A single domain can carry BOTH faces. Doctor is the proof: `doctor-contract`'s `SnapshotSource` is its
external edge (→ pulumi), and its consumer-facing side is an internal edge (→ the orchestration).

*Internal edge is PRESCRIPTIVE, not just descriptive.* It is not satisfied by "the domain has a port
package"; its value is the LEAKAGE its absence allows. The tell is not the port's presence but whether
neighbors import the core's IMPL types instead of calling a contract. Measured on the reactor:

* *manifests / netplan — CLEAN internal edge.* Consumers (`IncusResourceBootstrap`, the CLIs) import
  ONLY `-port` service types; zero `-core` impl leakage. The reference shape.
* *doctor — internal edge MISSING (the smoking gun).* `doctor-contract` carries only the external face
  (`SnapshotSource`); the internal face is absent, so 40+ files in `controlplane` import `doctor-core`
  impl types directly (`Generalist`, `ConsultationLog`, `MedicalRecord`, `Symptom`, `Checkpoint`),
  passing them as constructor params. Changing `MedicalRecord`'s shape ripples through 20-40 files.

The prescribed fix (first internal-edge increment): add a `ConsultingService` internal edge to
`doctor-contract` (`consult(symptom, observation) → RemediationPlan`, record/history queries), hide the
impl types behind it, rewire the consumers — making doctor symmetric with manifests/netplan. The doctor
extraction merged so far closed the EXTERNAL face only; this closes the internal one.

Readings:

* *Only Pulumi is irreducibly host* (×2) — `com.pulumi.*` carries native deps, `ServiceLoader`, and
  classloader assumptions that cannot resolve in a Felix bundle. Its `<target>-edge` modules stay host.
* *dbus-systemd was mis-classified as irreducibly host — corrected.* The native-deps disqualifier
  applies only to the *unix-socket* transport (junixsocket); we use *TCP only* (`dbus-java-transport-tcp`,
  plain sockets), which is playable. The one real obstacle, `ServiceLoader` transport discovery, is
  solved by *embedding* the dbus-java jars in the edge bundle so the lookup and the `TcpTransportProvider`
  share one bundle classloader. So dbus-systemd-edge *migrates into OSGi* — the first edge both extracted
  and migrated in one move. See link:../osgi/dbus-systemd-edge-spec.adoc[the dbus-systemd-edge spec].
* *Four more edges are host today but PLAYABLE* (incus, cluster/kubectl, host-filesystem, ssh-to-age) —
  pure JDK `ProcessBuilder` / `java.nio`. These are the migration candidates: their edge impls CAN move
  host→osgi, serving the goal of maximising the OSGi world, with no change to callers (they cross the
  port either way).
* *One purity violation* — `SopsAgeSecretManifestsUnit` in `manifests-core` (OSGi world) shells out to
  `ssh-to-age` DURING synthesis: an osgi module touching an edge directly, no port between. To fix by
  deferring the conversion to host-time or routing it through a port to a `ssh-to-age-edge`.
