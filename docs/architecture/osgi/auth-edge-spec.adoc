*Status:* IMPLEMENTED (2026-07-07). The seventh external edge of the frontier-playability model, after

Same working unit as the rest of the control-plane→OSGi sweep: *one external contact, extracted
atomically* — the port, the edge, AND the re-wiring of the consumer, in one change. The criterion
holds: a type migrates to a bundle only if a bundle `@Component` contacts an external system (→ edge)
or rides its verb (→ port). Reading an environment variable is not a contact — it stays host.
====

== The contact today — inlined in the host launch-secrets updater

`IncusResourceBootstrap.LaunchSecretsUpdater` (seed-outcluster) upserts two credentials into the
launch-secrets YAML: a GitHub token and a FloxHub token. Each is resolved by a two-step precedence —
first an environment variable (`GITHUB_TOKEN`/`GH_TOKEN`, `FLOXHUB_TOKEN`/`FLOX_TOKEN`/`FLOX_AUTH_TOKEN`),
then, failing that, by *asking the provider's CLI*: `gh auth token` / `flox auth token`, run through a
`ProcessBuilder` (`captureCommandOutput`).

Only that CLI call is an edge. The environment-variable precedence, the YAML upsert that preserves
comments, and the dry-run guard are host orchestration that genuinely stays — reading `System.getenv`
crosses no frontier.

== Resolution — an `auth-edge` `@Component` and an `auth-contract`

* *auth-contract* (`type=contract`): `AuthTokenContact` — the verb `tokenFor(AuthTokenSource) →
  Optional<String>` (empty = the CLI is absent/unauthenticated/non-zero, a present value is trimmed and
  non-blank); and `AuthTokenSource`, the flat contract enum — `FLOXHUB` only, since GitHub stopped being
  a CLI-sourced token. No host config type crosses; the host maps its own env-var precedence and only
  asks the contact when the environment yielded nothing. It also carries the GitHub *mint verb*:
  `GithubWriterTokenMint.mint(GithubAppCredentials) → String`, a FRESH `contents:write` installation
  token minted AT THE POINT OF USE, which throws rather than return a blank one; an absent mint (the
  edge filtered out under a survey/preview) is the caller's empty `Optional`, so the caller skips the
  push. Its least-privilege twin `GithubReaderTokenMint` mints a `contents:read` token — for a consumer
  that only READS a private repo (a node fetching its rendered `manifests/<cluster>` branch to install
  its rke2 config), where a write-scoped token is over-privileged.
+
Both take the owner's `GithubAppCredentials` (ghapp-contract). They used to take three plain strings,
"so no `ghapp-contract` type is dragged into a consumer that mirrors the App material" — but the edges
re-packed those strings into that very record before delegating to ghapp's `GithubAppMinter`. The
strings were a round trip through a mirror, and they went with the change below.
+
*`GithubAppTokens` — the one place a GitHub token is obtained (2026-10-10).* A record holding the two
mints and the process environment, with three lanes: `writer` (mint only), `writerOrPipeline` (mint,
else the token Pipelines-as-Code exported in a Tekton run, under `PIPELINE_TOKEN_ENV`) and `reader`. It
reads the App from its OWNER, `GhAppCoordinate.GITHUB_APP`, never from a consumer's mirror. It
replaced three copies of "reveal the App, then mint" — the manifests render's push token, the grown
node's reader token, and the version bump's release-query token — each grown on the manifests mirror.
The lanes stay named because the callers differ: the bump never fell back to the pipeline token, and
folding the copies must not give it one (a test pins it). auth-contract therefore depends on
ghapp-contract; that is not a new coupling, since auth-edge already imported those types to delegate
to the minter. The manifests synthesis keeps its mirror (`GhAppCase` + `GithubAppMaterial`) for what
it RENDERS, the `githubapp` Secret, uniform with its six sibling mirrors: only the token path moved. This SUPERSEDES the former durable auth-seal
  (`GithubToken` filed SEALED at an `AuthCoordinate` and revealed on fetch): an installation token is
  ephemeral (≈1 h), so a token sealed before provisioning had gone stale by the reveal after the cluster
  came up — mint-on-demand is the fix. `GithubToken` and `AuthCoordinate` are deleted.
* *auth-edge* (`type=edge`, `@Component`): `CliAuthTokenContact` — maps `FLOXHUB → flox auth token`,
  and shells nothing else. Pure `ProcessBuilder` over the JDK, no embedded
  jars, mirroring incus-edge's ssh contact. Its sibling `GithubWriterTokenMintEdge` realises
  `GithubWriterTokenMint` by delegating to the ghapp `GithubAppMinter` (the JWT-signing GitHub contact);
  it is `cultivating`-gated, so it activates only when the minter is present. `GithubReaderTokenMintEdge`
  is its least-privilege twin — same delegation, `TokenScope.READER` (`contents:read`).
* *seed-outcluster* (host): the updater keeps the env-var precedence and the YAML upsert;
  `ensureLaunchSecretsToken` resolves `AuthTokenContact` from the registry
  (`singleSpiProvider(AuthTokenContact.class)` on the already-held `BootedFramework`) and passes it into
  `LaunchSecretsUpdater.ensureTokensPresent`. The host `captureCommandOutput` is gone.
