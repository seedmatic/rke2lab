= Doctor internal edge — Move B scope + the test/fixture debt Move A left
:toc: left
:icons: font

A review report for the master-branch space. Move A (commit `1fef4cb1`) relocated the 38 value
types into `doctor-port` and reconciled the poms. This report surfaces two coupled decisions that
must be made *before* Move B is implemented, because Move A revealed a debt it did not itself close.

[IMPORTANT]
====
*Frozen point-in-time report.* The module names below are those of this session. The doctor boundary
was later *de-seamed*: `doctor-port` is now the installed, bundle-to-bundle-wired `doctor-contract`
bundle (`type=contract`), its package root `io.seedmatic.rke2lab.doctor.port` →
`io.seedmatic.rke2lab.doctor.contract`, and the `doctor-testkit` module weighed here was subsequently
deleted. Read the historical names below through that map.
====

The headline: **we moved 38 production types and left 100% of their tests behind.** The tests are
not "resisting" the refactor — they are *orphaned from their subject*. The right cut is not the one
the original plan drew.

== The production internal edge — the uncontested part of Move B

This part is sound and validated against real usage; it is *not* what needs deciding.

Consumers call exactly four methods on `Generalist`, confirmed by reading every call site
(`SystemdAdapterStage`, `ClusterReadinessStage`, `ResourcesStage` → `ResourceManager` →
`ResourceCreationPipeline`, plus `reviewDriftAtReconstruction`):

[source,java]
----
interface ConsultingService {           // NEW, in doctor-port
  RemediationPlan consult(Symptom s, Observation o);
  MedicalRecord   recordForCurrentPatient();
  String          cohortFinding(Symptom s);
  List<ReferralReply> reviewOpenProblems(MedicalRecord r, InterventionLedger l);
}
----

`Generalist` already exposes these four with identical signatures → it `implements
ConsultingService` directly, **no adapter**. Graph construction (today `bindMedicalRecord` +
`currentPatient` + `reviewDriftAtReconstruction` in `BootstrapPipeline`, touching
`HealthSystem.admit`, `DriftSpecialist`, `NetworkSpecialist`, `ClusterSpecialist`,
`LiveMedicalRecordRegistry`, `PulumiInterventionLedgerWriter`) moves into a `DoctorAssembly` in
`controlplane.bdd` — the package that *already* hosts the host realisation. The assembly reads
config/env/Pulumi and returns a `ConsultingService`; the pipeline's `PipelineState` holds the
service, not a `HealthSystem`. After this, the pipeline imports **zero** doctor-core types — the
internal edge is closed for production, symmetric with manifests/netplan.

This much I can implement immediately. The decision below is orthogonal to it.

=== Why this reframes the whole thing

The original plan said "rewire the ~9 graph-constructing tests through a test factory". That framing
was wrong. The model-actor tests are not consumers to be rewired onto a contract — they are
**doctor's own tests, sitting in the wrong module**. The honest move is to relocate ~46 of the 52
files to follow their subject (port-tests → doctor-port, model-tests → doctor-core), keeping only the
~6 genuine host tests. Move A's scope was "the types"; its true scope was "the types *and their
tests*", and we did the first half only.

=== The fixture that blocks a naive relocation — `ReferralReplies`

`ReferralReplies` is a `final class` of test-only `ReferralReply` factories. It is used by **12
tests** — and those 12 split across BOTH target modules (value-type tests → doctor-port, model tests
→ doctor-core). It imports only port types, so it *could* live in doctor-port. But a doctor-core test
that uses it then needs a doctor-port test-fixture on its classpath.

This is exactly the cross-module case the repo already has a convention for
(memory `shared-test-fixtures-module`, set 2026-06-09): **a dedicated `*-testkit` module, fixtures in
`src/main/java`, consumed in `scope=test`; never a copy, never a Maven test-jar (m2e won't resolve
test-jar classpaths).** There is precedent: `pulumi-automation-ext-testkit`, `osgi/testkit`.

So relocating the tests is not free — it pulls in a `doctor-testkit` (or fixtures land in
doctor-port's own `src/test` if only port-tests need them, with doctor-core tests as the trigger for
promotion). The other three fixtures are single-consumer / host-only and stay put.

== The options to decide

[cols="1,3,2",options="header"]
|===
| Option | What ships | Cost / risk

| *B-prod only* (my recommendation to sequence first)
| `ConsultingService` + `DoctorAssembly`; pipeline sees only the contract; the 2 pipeline
  *wiring* tests (`DriftReviewWiringTest`, `DriftReviewReconstructionLiveTest`) rewire onto the
  assembly. Tests stay where they are for now.
| Low. Closes the production edge. Leaves the test-relocation + Export-Package narrowing as a named
  follow-up (the same way `ac2fae1b` deferred increment 5).

| *B-prod + test relocation*
| All of the above PLUS move ~46 tests to their true module and stand up the fixture story
  (`doctor-testkit` or doctor-port `src/test`). doctor-port/doctor-core stop shipping empty test
  trees.
| Medium. This is the "finish what Move A started" option. Bigger diff, touches jgiven/fake infra,
  but it is the honest completion.

| *Full hiding*
| All of the above PLUS narrow `Export-Package` so the actors are unimportable outside the bundle.
| Highest. Only meaningful once the model tests are *inside* doctor-core (else they can't see the
  actors either). So this strictly depends on the relocation option.
|===

The three are a strict dependency chain: full-hiding ⟶ requires test-relocation ⟶ independent of
(but naturally paired with) B-prod.

== Recommendation

Sequence, don't bundle:

. Ship *B-prod only* now (clean, low-risk, delivers the architectural payload — the internal edge).
. Then a dedicated *test-relocation + fixture* increment (this is where the `ReferralReplies` /
  `doctor-testkit` decision actually gets made and reviewed on its own merits).
. *Export-Package narrowing* last, riding on (2).

The question for the master-branch space: **do we accept this sequencing, or do we want Move B to
mean "finish Move A properly" (option 2) in one go?** Either is defensible; the fixture convention
already exists, so option 2 is not blocked — it is just larger and deserves its own review.

== DECISION TAKEN (design space, do not re-litigate)

Option 2 + full hiding. We finish Move A properly in THIS increment, as three sequenced commits on
this branch (sequencing ≠ deferring — all three land here before integration):

* *commit 1 — B-prod*: `ConsultingService` (the 4 ops) in doctor-port; `Generalist implements`
  it directly (no adapter); a `DoctorAssembly` in `controlplane.bdd` builds the graph and returns a
  `ConsultingService`; `PipelineState` holds the service, not a `HealthSystem`. Target: the
  pipeline imports zero doctor-core types.
* *commit 2 — test-relocation + doctor-testkit*: ~29 value-type tests → `doctor-port/src/test`, ~17
  model-actor tests → `doctor-core/src/test`, ~6 host tests stay; `ReferralReplies` → a new
  `doctor-testkit` module (`src/main/java`, consumed `scope=test`), per `shared-test-fixtures-module`.
* *commit 3 — export-narrowing*: narrow doctor-core's `Export-Package` so the 12 actors become
  unimportable outside the bundle. Strictly depends on (2): model-tests must be INSIDE doctor-core to
  see the actors.

Strict dependency chain: 3 ⟶ 2 ⟶ B-prod. We go all the way to (3).

== RESOLVED (design space) — the graph is assembled behind a `Doctor` façade in doctor-core

Decision: *Option 1 — façade `Doctor` in doctor-core, standard roster internal to the core.* Not a
re-litigation; the implementation fork the plan left open is now closed.

* *`Doctor` façade* (public, exported, in `io.seedmatic.rke2lab.doctor`):
  `Doctor.consultingService(Patient, MedicalRecordRegistry, InterventionLedgerWriter,
  List<Specialist> hostSpecialists, Consumer<String>) → ConsultingService`. Port-only
  signature. It news up GrantPolicy/ClinicalAccess/DriftSpecialist/Network+ClusterSpecialist/
  Generalist/HealthSystem internally and returns the `Generalist` (which implements the contract).
* *Roster*: the core adds Network+Cluster internally; the host passes only the config-bound
  specialists (`DbusTcpSpecialist`). Keeps Network/Cluster hideable.
* *`DoctorAssembly`* (host) supplies only host impls: `LiveMedicalRecordRegistry`,
  `PulumiInterventionLedgerWriter` (or a no-op), `DbusTcpSpecialist`, the patient — and runs the
  drift-at-reconstruction review THROUGH the contract.
* *Consequence (deliberate)*: seed-outcluster imports ZERO actor from commit 1 onward — this is what
  makes commit 3 mechanical.
* *commit-3 mechanism = package-private, NOT bnd `Export-Package` narrowing.* The caveat below is
  right: bnd governs OSGi resolution, not the Maven compile classpath. So commit 3 drops `public`
  from the 12 actors (all in the one package `io.seedmatic.rke2lab.doctor`); the Java compiler then
  forbids importing them from seed-outcluster (another module) at BOTH compile and OSGi level, while the
  co-located doctor-core tests (relocated in commit 2) still see them white-box. No ArchUnit, no
  api/impl split. `Doctor` stays the only public assembly type; the concrete `Generalist` it returns
  becomes package-private ("public interface, package-private impl"). This is exactly why 3 depends
  strictly on 2.

The "HealthSystem.admit direct" alternative is rejected: it would leave HealthSystem / DriftSpecialist
/ the two specialists imported by seed-outcluster, breaking commit 3.

[discrete]
==== Historical: the conflict that drove the decision

The Placement-2 plan's verified-facts say `DoctorAssembly` (which lives in seed-outcluster, i.e. OUTSIDE
the doctor-core bundle) calls `HealthSystem.admit(Patient, MedicalRecordRegistry, List<Specialist>,
DriftSpecialist)` and therefore does `new NetworkSpecialist()`, `new ClusterSpecialist()`,
`new DriftSpecialist(...)`.

But commit 3 lists exactly `HealthSystem`, `DriftSpecialist`, and the two specialists among the actors
to make unimportable outside the bundle. **If `DoctorAssembly` instantiates them, commit 3 cannot hide
them — direct contradiction.** And `DoctorAssembly` must stay host (it reads BootstrapConfig/env/Pulumi;
pushing it into doctor-core would re-couple the core to BootstrapConfig, which the plan forbids).

=== The two options

[cols="1,3,2",options="header"]
|===
| Option | Shape | Consequence

| *Façade `Doctor` in doctor-core* (my recommendation)
| doctor-core exposes a new exported `Doctor.consultingService(Patient, MedicalRecordRegistry,
  InterventionLedgerWriter, List<Specialist> hostSpecialists, Consumer<String>)` taking only
  PORT-typed inputs; it news up GrantPolicy/ClinicalAccess/DriftSpecialist/Network+ClusterSpecialist/
  Generalist/HealthSystem INTERNALLY and returns the `Generalist` (which implements the contract).
  `DoctorAssembly` supplies only the host impls (`LiveMedicalRecordRegistry`,
  `PulumiInterventionLedgerWriter`/no-op, `DbusTcpSpecialist`, the patient).
| seed-outcluster imports ZERO actor from commit 1 onward — more than commit 1 targeted, and exactly what
  makes commit 3 mechanically possible without re-touching production code. Drift-at-reconstruction
  review then runs entirely THROUGH the contract (`recordForCurrentPatient()` +
  `reviewOpenProblems(record, ledger)`); host just loads the ledger via `InterventionLedgerSource`.
  Deviates from the letter of the plan's verified-facts.

| *`HealthSystem.admit` direct*
| `DoctorAssembly` calls `HealthSystem.admit` + `new Network/ClusterSpecialist` + `new DriftSpecialist`,
  to the letter of the verified-facts.
| Closer to today's code, but commit 3 CANNOT hide HealthSystem / DriftSpecialist / the two specialists
  — they stay imported by seed-outcluster. Breaks the 3 ⟶ 2 ⟶ B-prod chain at (3).
|===

Sub-question (rides on the above): *the specialist roster*. Network+Cluster are parameter-free. Either
`Doctor.consultingService` adds the standard roster (Network+Cluster) internally and host passes only the
config-bound `DbusTcpSpecialist` (keeps Network/Cluster hideable in commit 3) — or host passes all three
(keeps the roster host-side but blocks hiding Network/Cluster). The façade option pairs naturally with
"core adds the standard roster".

=== A caveat for commit 3 (flagged now, not solved here)

doctor-core is a Maven *compile* dependency of seed-outcluster. A narrowed bnd `Export-Package` governs OSGi
resolution BETWEEN bundles, not the Maven compile classpath. Making the actors truly unimportable from
seed-outcluster's compiler likely needs an api/impl split or an ArchUnit rule, not bnd alone. To be scoped in
commit 3 — but the `Doctor` façade above is the prerequisite under any mechanism.

*doctor-core*: `Generalist implements ConsultingService` (signatures already identical, the 4
methods already public); + `Doctor` assembly façade (if the façade option is chosen).
