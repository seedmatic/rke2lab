= Atlas L1 — Fabric control-plane view (from keys and SaaS to our own tailnets)
:toc: left
:toclevels: 3

_Level-1 (per-subsystem) view of the link:../integration-atlas.adoc[integration atlas] (L0)._
_L0 shows how this subsystem integrates with the others and the value that emerges; this file is the detail._

The access plane of the infrastructure — how a machine of the fabric is reached, by whom, and with what
— migrating from today's shape (one SaaS tailnet for everything, an SSH authority whose private sits
on every host, keys rotated at every activation) to the target specified in ndh
`docs/fabric-control-plane-spec.adoc`: **one self-managed headscale tailnet per metalspace** for the
infrastructure nodes, the clusters staying on the SaaS, and access granted by policy.

Everything marked *measured* was read on 2026-10-06 in ndh, rke2lab, the Tailscale source or the
headscale source. The corporate bare-metal is named by its role and its alias `vzhost.nikopol`.

== The thesis — access stops being key material

Each figure carries its own before/after in one frame (atlas convention). The red `BEFORE` block is
what the transition deletes; the green `AFTER` block is the target.

The motive is a measured incident, not tidiness. On 2026-08-27 a misrouted sops rule published the
whole key registry in this public repository: eight private keys, including the SSH authority every
host trusted, where this repository reads four items. Renewing the keys closed that leak, not the next
one, because the shape that caused it stayed: **a registry that carries privates everywhere eventually
leaks everywhere.** The target removes the shape: access becomes a grant, a key becomes an exception,
and an exception is generated by the machine that uses it.

== The migration sequence

Each step leaves every connection working, and the old path goes only once the new one is
*measured*. The invariant across all of them: an operator always has a path to the machine being
changed — the serial console, `incus exec`, or the emergency screen.

honoured it** — `modules/nixos/headscale-daemon.nix` took `pkgs.headscale` directly, so the re-aim
alone would have moved darwin and left NixOS on stable, on the very platform the control plane is
about to run on

| 2 — bioskop control plane
| `headscale-daemon` moves from the guest's host system into an Incus container; `server_url` = a
private fabric name, reached locally by the tailnet's members; the bbox `tcp/41841` forward closed
| headscale FAQ: running it on a tailnet member *"is not supported"*. The control traffic never
crosses the public network, so no ACME and no public name are needed — the control URL's TLS leaf is
signed on an operator seat from the shared `mammoth-skate-tls` root, which every member already trusts
(`security.pki.certificates` on NixOS, the System keychain on darwin). *Measured:* Apple's 398-day
ceiling does not apply to an administrator-added root, so the leaf can be long-lived

| 3 — per-tailnet policy
| **The carve landed** (ndh `0e727c3a`): `netplan.tailnet` became `netplan.tailnets`, keyed
`saas` / `bioskop` / `nikopol`, each a control plane's *domain of authority*. The vendor entry is
`allocation = "vendor"` with its `/10` as an opaque **given**; ours are `allocation = "ours"`,
`magicDns = false`, no `domain`, with `v4 = 100.{127 - hostId}.0.0/16` and
`v6 = fd7a:115c:a1e0:{hostId + 1}::/64` — and `assert hostId < 9`, because the v6 carve spells the
index as a **hextet** and only 1–9 agree in decimal and hex. `netplan.segments` went 33 → 38: the
hard-coded `100.64.0.0/10` pair is gone, replaced by six **derived** entries `tailnet-{saas,bioskop,nikopol}`,
so nnh's attribution now tells the tailnets apart instead of collapsing every address into one
`tailnet` label. ⬜ *Remaining:* `manage-tailnet` rendering one policy per tailnet and applying it
through headscale's own tooling
| `config-example.yaml`: *"Using a SUBSET of these ranges is supported"*. ⚠️ *The carve is for
legibility — nothing may depend on it:* no machine is ever on two tailnets (clusters on the vendor's,
infra on ours, one `tailscaled` each), so a collision is never resolved on a host, and cross-tailnet
traffic targets **segment** addresses because `tailscaled`'s `ts-forward` hard-codes
`-s 100.64.0.0/10 -j DROP`. What it buys is that an address says which tailnet it belongs to.
*Measured:* the SaaS is not a carve participant — its 13 live addresses are scattered 100.65 → 100.120
across the whole `/10` and we do not control its allocator; the asymmetry is in the type so nobody
later "fixes" the vendor entry by carving it

| 4 — vmnet announcement
| each cluster's nodes announce their own `/21` into the SaaS
| open in `management-workload-topology.adoc`; must land BEFORE step 5, or CAPI loses the workload VIPs

| 5 — bioskop infra nodes
| bioskop and bioskop-nixos register to their tailnet and leave the SaaS

stops describing it. It matches nothing rather than mis-matching, so nothing breaks; but the pattern
must follow the guest to its new tailnet, and our tailnets form no FQDN at all

| 6 — nikopol control plane
| same as 2–5, with a private `server_url` reached over the segment
| nikopol is itinerant and has no inbound door; all its members are local

| 7 — the bridge
| WireGuard between the gateways; nikopol initiates with a keepalive
| one static keypair per gateway — the accepted exception

| 8 — screens
| routes + grants replace `svc:rdp-*`; `tailscale-vnc-forward` and its `0.0.0.0:5901` removed

| 9 — keys

and the principals command removed; `vz-nudge` becomes `tart exec`; **no emergency SSH key replaces

| `tart exec` is unmeasured — `tart list` failed on a locked `disk.img`. ⚠️ The ssh repair **changes

=== The password-store ownership split — the cleanup that closes the migration

The store is the bootstrap root (ndh `docs/fabric-control-plane-spec.adoc` § *The initiating
gesture*), so who owns what about it stops being cosmetic. *Measured 2026-10-06:*

== What the transition deletes

* every SSH key an operator would use to reach the fabric — none is introduced to replace them;
* the `rdp.mammoth-skate` ssh tunnel and the `tcp/2222` forward it needed;
* the `mammoth-skate` SSH authority, the certificates, and the `KnownHostsCommand` / `TrustedUserCAKeys`
  machinery that consumes them;
* every key regenerated at activation, and the eviction logic that could never catch them;
* the principals command that granted every principal to every account;
* the whole-registry subtree in this repository — replaced by its projection;
* the Tailscale Services for the screens, and the ssh tunnel on the screen path;
* the in-cluster mesh domain (`MeshDomainRegistrar`);
* the `remoteFetch` ssh fallback and the uncalled enrichment orchestrator.

== Verdict — does it hold?

[cols="1,3",options="header"]
|===
| Question | Answer

| Is the move monotone?
| Yes, by ordering: every step adds the new path before it removes the old, and steps 4 → 5 are the one
hard dependency — the vmnet announcement must move before any guest leaves the SaaS.

| Does any step risk a lockout?
| Only if layer 0 is not measured first. The serial console and `incus exec` depend on nothing the
migration changes; step 5 starts by proving them.

| What stays out of reach?
| The clusters' move, gated on headscale 0.30.0; and addressing the other tailnet's `100.x` directly,
gated on the fork patch.

| What is still open?
| the vmnet announcement owner, the CGNAT sub-prefix values, the leaf's validity period, the console login of the
runtime guests, sftp and `nix-daemon --stdio` over Tailscale SSH, `tart exec` for the nudge.
|===

== The private binary cache — from a public watch-store to one builder

The second consumer of the fabric's Incus containers. The target is ndh
`docs/private-binary-cache-spec.adoc`; this section carries the delta from today. Everything marked
*measured* was read on 2026-10-10 from store paths that already existed, or on 2026-10-11 in an
isolated throwaway store, without evaluating a flake of ours.

The motive is again a measured incident. A `cachix watch-store` daemon pushed every new store path
to the public `nxmatic` cache. Every flake evaluation of a dirty rke2lab tree copies the tree as it
sits on disk, and the sops smudge has decrypted `.secrets` and `.ndh-ssh.d/keys.yaml` there. So 52
plaintext copies became public. The daemon was disabled on every host (ndh `395b34a1`). It is not only a dirty tree: measured on
2026-10-11, any evaluation that names a decrypted checkout copies those files in clear, clean or
dirty. Only a revision read from git objects stays encrypted. The operator
wants the cache back for a different reason than speed of one host: **the hosts share most of one
configuration, and each one rebuilds it.**

=== Diagram F — Who builds, who publishes: BEFORE vs AFTER

Reads: the BEFORE has every host building for itself and a daemon publishing whatever entered any
store, a worktree copy included. The AFTER has one builder evaluating revisions only. It publishes
to the public cache only what passes a closure rule, and sends each host its closure. A private cache
keeps everything else for the active session, and three store tiers each inherit the immutable EROFS
base and substitute only their delta.

=== What rke2lab gains — the nodes and their workloads

The cluster nodes are Incus containers in the same Incus cluster as attic-nixos (project `rke2lab`,
Incus members `bioskop` and `nikopol`, named after their metalspaces). So the mechanism ndh builds for
its own Incus containers is the one the
nodes **inherit**: a `/nix/store` that is an overlay on the NixOS guest's EROFS layers, a lower DB shipped
with the layers, and an upper that receives only the node's delta. The clusters read the **public
tier only**: what they need from us is what the allow-list must name.

[cols="1,2,2",options="header"]
|===
| Tier | Today (measured or read in code) | With the cache

| node store
| no node running on 2026-10-10. Its closure was realised in neither bioskop's nor bioskop-nixos's
store, so it is unmeasured.
| overlay on the EROFS layers. The node's closure and its `FloxEnv` closures are built by the fill
job, and published when they pass the closure rule.

| env closures
| realised on each node by the flox controller, which GC-roots them. The node collects on disk
pressure (`nixos/nix-env.nix`: `min-free = 128MB`, `max-free = 1GB`).
| built once by the fill job from the pushed `flox-catalog` lock. A node that collected one
re-substitutes it from the public tier, or **through the NixOS guest of its metalspace, its builder**, holding no attic
token. The flox controller realises with `flox activate` in the node's namespace, so it follows the
node-base nix configuration.

| pod store
| `flox-nri-overlay-hook.sh`: the lower is a read-only bind of the node's **live** `/nix`, the upper a
2 GiB tmpfs or a PVC. The DB is reconciled at every pod container start (`--dump-db \| --load-db`, then
`--verify`), after a defect measured on 2026-09-30.
| unchanged in mechanism; it reads the env closures the node substituted. Remote builds of unknown
packages (`max-jobs = 0` → `{bioskop,nikopol}-nixos`) go to the **private** tier through that host's
watch-store, never to the public one. No attic token in pods: the remote builder substitutes for
them (`builders-use-substitutes = true`).
|===

⚠️ The pod tier's lower is the node's live store, which the controller grows and the node's GC
shrinks. In OverlayFS, a lower that changes while mounted is undefined. ndh's spec forbids exactly
that for the Incus containers, and the hook's reconcile repairs the DB, not that rule. With the immutable
base available, stacking the pod on the EROFS layers plus a stable env layer becomes a candidate. That
decision is rke2lab's.

|===
| Step | Content | Precondition / measured fact

| c1 — re-lock ndh's rke2lab input
| ✅ *DONE, ndh `3492ca41`*: the `rke2lab` node of ndh's `flake.lock` relocked from its GitHub archive
| *measured 2026-10-10*: that node (`github:seedmatic/rke2lab`, rev `372f6578`) carried the narHash
of a **plaintext** copy, `8qizqgcj…-source`, one of the 52. GitHub's archive is encrypted and cannot
produce that hash. So every evaluation of ndh substituted the plaintext copy from the public cache,
and the purge would have broken ndh's evaluation had the relock not come first.

| c2 — purge
| ✅ *DONE by the operator*: 173 of the 173 listed paths answer 404 on `nxmatic.cachix.org`
| the list is held outside the repo (counts and paths only). Rotations are the operator's gestures.

| c3 — attic-nixos
| the shared ndh Incus container module (ndh `feature/incus-nixos-container`), with project and target
stated. `services.atticd` from stable nixpkgs, its package from unstable (attic `7a19204d`). SQLite
with a GC every 15 minutes, no database service. `tank/nerd/attic` mounted at
`/var/lib/private/atticd`. The cache created **without** `--public`, a retention of hours (6
proposed)
| the quota, 16G or about 8G, stays **open** until the public/private split is measured on the four
hosts. The upper bound without that split is 1.15 GiB + 0.52 U compressed, now that `pulumi-bin` (4.59
GiB) left the flox seat in rke2lab `2ef9dab8f`. The test that closes the step: an anonymous narinfo request
gets **401**, a request with a read token gets 200.

| c4 — watch-stores
| an `attic watch-store` on each of the four hosts, each with its own write token (`--sub {host}`).
attic's upstream key names: the upstream substituters, the layer key, `seedmatic-publish-1` and
`nxmatic.cachix.org-1`, never the fleet's build key
| decided 2026-10-10 and kept on 2026-10-11 for the private tier. The price, stated in the ndh
spec's trust model: one slipped `.#x` on bioskop puts a plaintext `-source` in attic, unsigned so
never skipped; it is detected by a store sweep, and prevented only by the fork

| c5 — the fill job
| one job on bioskop, its own user and fetcher cache. It evaluates **revisions only**
(`github:…/{sha}` or `git+file:///Volumes/git-bare-store/seedmatic/{repo}.git?ref=develop&rev={sha}`),
builds every configuration, the Linux ones on bioskop-nixos, and sends each host its closure with
`nix copy --to ssh-ng://nix-store.{host}`. No other host builds from source
| *measured by develop-2a, 2026-10-11*: any evaluation naming a decrypted checkout copies `.secrets`
in clear, clean or dirty. And the fetcher cache keys a commit's source by revision, first
evaluation wins, so one `nix build .#x` in a worktree poisons every later `?rev=` build of that
commit. Hence the job's own fetcher cache

| c6 — publication
| the job publishes the paths whose **whole closure** is upstream-served or meets four conditions:
allow-listed, built (has a deriver), from a revision, passing the content guard. It signs them with
`seedmatic-publish-1` (sops, never in `secret-key-files`), `cachix push`es that set explicitly, then
checks that cachix holds exactly that set
| *measured 2026-10-11*: `secret-key-files` signs built paths only, never added ones (a `-source`,
`toFile`, a sops-nix file); 15 of 15 added paths have no deriver. On bioskop's system closure, 161
of 179 built paths (341 MiB) are publishable; the 18 private ones (2 MiB) are the host's
aggregates

| c7 — cluster nodes
| the nodes take the EROFS layers as lowers. They substitute from the **public tier only**, and
write and build **through the NixOS guest of their metalspace** (operator, 2026-10-10): the node-base
nix configuration carries `builders = ssh-ng://…`, `max-jobs = 0`, `builders-use-substitutes = true`
and `require-sigs = true`, and the NRI plugin mounts the same for pods. **No attic token in a
cluster**
| ⚠️ *design only*: measured 2026-10-10, nothing declares `builders`, `max-jobs` or
`builders-use-substitutes`, neither `nixos/*.nix` nor flox-nri-plugin. That configuration is
**rke2lab's follow-up**. The build clients must not be `trusted-users` of the builder: nix 2.34 then
forces signature checks on their imports and builds their derivations itself (ndh spec,
_cluster-builds_). The three builder tests decide between this and fallback B (nodes never build).
|===

=== What the transition deletes

* the `cachix-watch-store` modules (`modules/.common.d/`, `modules/darwin/`, `modules/nixos/`),
  disabled since `395b34a1` and still in the tree. The public cache stays, fed by the fill job only;
* the per-host rebuild of the shared paths: no host but bioskop builds from source.

=== Verdict — does it hold?

[cols="1,3",options="header"]
|===
| Question | Answer

| Is the move monotone?
| Yes. Its one hard order, c1 before c2, has been kept: the relock landed before the purge.

| Does it fix the leak?
| For the **public** cache, it closes the path the incident took. Only the fill job publishes, from
revisions, under a closure rule that refuses any added path no upstream serves, and after a content
guard. A signature attests content, not how it was evaluated, so the guard is the last line and
"revisions only" stays mandatory. For the **private** tier it **confines**: a worktree copy can still
reach attic through a host's watch-store, read only by token holders, kept for the session only.
The real fix there is an attic fork that refuses secret-bearing paths at upload (ndh spec, _The real
fix_), and upstream of it, no plaintext on disk in a flake tree.

| What stays out of reach?
| the size of the package outputs and of the node and env closures, since none is realised in any
store today; the public/private split on the four hosts, which the quota waits for; and the pod
tier's lower, which is rke2lab's decision.
|===
