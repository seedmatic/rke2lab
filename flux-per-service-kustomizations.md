**Split the Flux reconcile from per-LAYER to per-SERVICE Kustomizations (SHIPPED + LIVE 2026-08-30, rke2lab `56fad1cf1`).** Motivation (user): observability — `flux get kustomizations` should show per-service progress/health, a failure stay local, retries be independent (the old model's headplane failure NotReady'd the whole `workloads` layer).

**Before:** `FluxRootManifestsUnit` emitted 4 chained per-layer Kustomizations (`crds→foundation→operators→workloads`, dependsOn+wait), each `path ./<layer>`. dependsOn is an ORDER relation, not ownership → `flux tree`/resource graph showed them flat (no hierarchy).

**After (two-level):**
- `FluxRootManifestsUnit` seeds only the `GitRepository` + ONE root Kustomization **`flux`** (`path ./flux`, prune, wait, NO sops — it applies only child Kustomization objects). It OWNS the children → the resource graph shows root→children.
- New **`FluxServiceKustomizationPlanner`** (package-private in manifests-core — NOT exported, so no spec-coverage gate; the gate DOES follow core's exported types) runs POST-EXPLODE, wired in `DefaultManifestSynthesisService` after `explodeService.explode(...)`. It has the written cells (from `ManifestExplodeResult.writtenFiles`, each `<layer>/<domain>/<package>/<file>`) + the in-memory graph (`CoherentManifestsDomainRegistry.visitOrder()` → each unit's `dependsOnManifestsUnitIds` + `requireDomainIdForManifestsUnit`; cell↔unit mapped by `<domainId>/<outputDir()>`). Writes one child Kustomization per cell under `synthOutdir/flux/*.yml`.
- Child `dependsOn` = **(a) layer barrier**: the immediately-previous NON-EMPTY layer's cells (transitive → CRD-before-CR without enumerating each CR→CRD edge; covers the HIGH edges flox-envs/catalog→flox-controller-crds for free) + **(b) INTRA-layer service edges** from the unit graph (same-layer only, e.g. headplane→headscale in workloads). **Same-layer-only is the cycle-safety rule**: a cross-layer graph edge from an operators-service to a workloads-service (envoy-gateway→cilium-advanced) would invert the barrier → cycle; barrier edges only go to a lower layer + intra-layer stay within one layer (unit graph is a DAG) ⇒ acyclic by construction.

**Names: bare `<domain>-<package>`** (+ `-<layer>` ONLY for the 5 services spanning layers: flox-controller, cluster-api-operator, tekton, tailscale, envoy-gateway → e.g. `runtime-flox-controller-crds`/`-operators`). Cluster slug DROPPED everywhere incl. the root (`flux`, was `<slug>-flux`) — the branch + `flux-system` ns are already per-cluster. Delivery unchanged: render → force-push `manifests/<slug>` → root (node-bootstrap seeded) reconciles `./flux`. Exploder UNCHANGED (tree stays `<layer>/<domain>/<package>`).

**Proven live:** 40 per-service Kustomizations, all `Ready` on one revision. Op note: after a grow the old `bioskop-mgmt-flux` root lingers orphaned (node-bootstrap, not prune-managed) → `kubectl -n flux-system delete kustomization bioskop-mgmt-flux` once.

**DESIGN VERDICT — dedicated `flux-<cluster>` namespace: NO (statué 2026-08-30).** seed-master grow is a SINGLE mgmt cluster, self-managing (node-base bakes Flux per-cluster; each cluster reconciles its own `manifests/<slug>` branch; NOT hub-and-spoke). So the `<cluster>` in `flux-<cluster>` is redundant (same as the prefix just removed) — a content ns would only be "engine vs content" cosmetics at bootstrap-lane cost + Flux-convention deviation. Keep everything in `flux-system`. Reopen only if topology becomes hub-and-spoke (excluded by baked-Flux-per-cluster).

**★ Flux push webhook — SHIPPED + LIVE (2026-08-31).** `FluxServiceKustomizationPlanner` sibling `FluxReceiverManifestsUnit` (gitops, steady-state) emits: a `Receiver` (type github, `secretRef flux-webhook-token`, resources=[GitRepository rke2lab]) + the `flux-webhook-token` replica stub (mittwald `replicate-from`) + a **Tailscale funnel `Ingress`** (`ingressClassName tailscale`, `tailscale.com/funnel:"true"`, defaultBackend → `webhook-receiver`:80). Funnel comes from the Tailscale k8s OPERATOR (Tailscale SaaS via `operator-oauth`), NOT headscale (headscale v0.29.3 = private hs.net, no funnel — the decisive fact). The HMAC token rides the replicator lane: `.secrets github.webhook.token` + `kubernetes.secrets.web-hook` (name flux-webhook-token, replicateTo flux-system); `ReplicatorSecretsSealScenario.webhookSecret` builds the source secret. **Verified live after cold-start:** Receiver Ready (`webhookPath /hook/7d6ed571…`), funnel Ingress got public host **`flux-webhook.mammoth-skate.ts.net:443`** (tailnet=`mammoth-skate.ts.net`), GitHub webhook DECLARED by the operator (URL = `https://flux-webhook.mammoth-skate.ts.net<webhookPath>`, secret = github.webhook.token, event=push). Kills the polling latency / manual force. Design settled earlier: NOT a seed-master apiserver-trigger (dropped — polling auto-syncs at cold-start, all ks Ready), NOT cluster-pki TLS (that needs a public-trusted cert → Tailscale LE via funnel, not our private CA). Get URL post-grow: `kubectl -n flux-system get ingress flux-webhook -o jsonpath='{.status.loadBalancer.ingress[0].hostname}'` + receiver `.status.webhookPath`.
