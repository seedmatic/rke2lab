**Converged design (2026-09-03, NOT yet coded) — the repeated-cold-start workflow's cleanup + persistence.** Born from "no TaskRuns despite pushing new heads".

**THE ROOT SYMPTOM (fully diagnosed):** repeated re-grows recreate the `pac-webhook` funnel → each re-issues a Let's Encrypt cert for the SAME FQDN `pac-webhook.mammoth-skate.ts.net` → hit LE's **"5 certificates per exact FQDN per 168h"** limit → the funnel can't get a TLS cert → GitHub webhook deliveries fail at TLS (confirmed in the GitHub App hook deliveries: `push`/`check_suite` POSTs → `context deadline exceeded`/`EOF` 500; and tailscaled logs: `getCertPEM: 429 rateLimited … retry after 2026-09-04 02:42 UTC`) → PaC receives nothing → zero PipelineRun/TaskRun. NOT a naming drift (name was clean this grow), NOT code. Separately: ~62 orphaned ZFS PVC datasets (~3.28G) accumulate on `tank/rke2/control-nodes/master` across re-grows (current gen = 2 PVCs; reclaim=Delete but cluster-destroy bypasses the CSI, so datasets orphan on the host `tank` pool — which SURVIVES instance replacement, accessed via `/dev/zfs` passthrough).

**KEY GROUNDED FACTS:** tailscale operator `v1.102.3`; `proxyclasses.tailscale.com` CRD present; the proxy stores state in a Secret named `$(POD_NAME)` = `ts-pac-webhook-<random5>-0` (TS_KUBE_SECRET) → **name NOT stable across grows** (per-StatefulSet random suffix, tracked by labels not name). Funnel certs: no wildcard, per-exact-FQDN; `ts.net` is a public-suffix so `mammoth-skate.ts.net` = registered domain → also a **50 certs/registered-domain/week** ceiling. GitHub App **4581114** (`seedmatic-rke2lab`) is used by BOTH PaC webhooks AND the manifests push; webhook URL is correctly `pac-webhook.mammoth-skate.ts.net`, events include `push`.

**★★ DESIGN CONVERGED 2026-09-03 (collaborative brainstorm) — see "CONVERGED ARCHITECTURE" below; the numbered DECISIONS are superseded where they conflict.**

**DECISIONS (original — kept for provenance; #4 ZFS-prune REVERSED, see converged):**
1. **Persist the funnel cert (stable name), NOT rotate names.** A unique-name-per-grow (`pac-webhook-<gen>`) dodges the 5/FQDN limit but hits the 50/registered-domain/week ceiling under churn → so persist instead. Tailscale names are FLAT single labels under `<tailnet>.ts.net` — NO nested subdomains (`pac-webhook.<gen>.bioskop.…` impossible; dots sanitised to hyphens).
2. **Two-tier storage.** Ephemeral per-gen `tank/rke2/control-nodes/<node>/*` (GC'd on grow) vs persistent cross-gen `tank/rke2/persist/*` (retained + re-bound each grow). `persist/` holds the tailscale funnel cert state AND the render **maven build cache** (which today orphans+re-provisions each grow → lost incremental cache) and any other cross-gen state. User's naming: `persist` (not `persistent`) — the NixOS impermanence convention (`/persist`), and `impermanence` is a flake-commons input.
3. **Cert persistence mechanism (★★ BLOCKED — 2026-09-04, VERIFIED at source):** the plan was the tailscale proxy stores state on a `persist/` PVC via a **ProxyClass** + `TS_STATE_DIR`. **IMPOSSIBLE with the tailscale operator: `ProxyClass` exposes NO volume mount.** `k8s-operator/apis/v1alpha1/types_proxyclass.go` (main): `Pod` = {Labels,Annotations,Affinity,TailscaleContainer,TailscaleInitContainer,SecurityContext,ImagePullSecrets,NodeName,NodeSelector,Tolerations,TopologySpreadConstraints,PriorityClassName,DNSPolicy,DNSConfig}; `Container` = {Env,Image,ImagePullPolicy,Resources,SecurityContext,Debug}. **NO Volumes / VolumeMounts / PVC / volumeClaimTemplate.** So `TS_STATE_DIR` can be SET (Env) but has nothing persistent to point at. → Increment 4 (ProxyClass cert mount) + the persist PV *for the cert* are OFF. **Persist tier STILL valid for the maven-cache** (Tekton pods mount PVCs normally). Real need = persist the proxy NODE KEY across grows (lives in the pod-named, etcd-ephemeral `TS_KUBE_SECRET`). OPEN options to decide with user: (1) `TS_KUBE_SECRET`=stable name via `Container.Env` + persist/restore that Secret (etcd-wipe ⇒ needs a durable source); (2) unique funnel name per gen (hits 50/registered-domain/week, previously rejected); (3) check if a newer operator version attaches storage to its proxy StatefulSet; (4) provision the webhook URL in GitHub dynamically (user's earlier idea) instead of a static funnel FQDN. AWAITING USER DECISION.
4. **Tailnet device prune** — cluster-scoped **oneshot Job**, ordered BEFORE the tailscale operator registers devices (Flux `dependsOn`). Running before registration lets the new devices reclaim CLEAN names → **prevents** the `pac-webhook-1/-2` drift instead of cleaning up after. Uses `manage-tailnet` **aarch64-linux** variant + the replicated `operator-oauth` Secret (in-cluster locality, via `--client-secret-file <mounted secret>` — the over-seed wrapper still applies). **SUPERSEDES the operator-side `local.Command` shipped this session (`dac7eb5f9` + wiring): the Command runs AFTER the node boots + devices register → too late to prevent drift. Retire it; keep the manage-tailnet package.**

**★★ CONVERGED ARCHITECTURE (2026-09-03) — the persist tier + the two-owner split:**

**★ DECIDING FACT (user, confirmed):** **etcd is WIPED at every cold start** (single control node `bioskop-mgmt-master`, instance delete+recreate → node-local etcd gone). ⇒ dynamic openebs-zfs provisioning ALONE **cannot** persist cross-grow (fresh cluster mints a new random `pvc-<uid>` + the PVC→PV→ZFSVolume binding lived in the wiped etcd → the surviving persist dataset is re-orphaned, cert lost). **A STABLE volumeHandle is MANDATORY, not optional.** (This also EXPLAINS the ~62 accumulating orphans — if they re-bound they wouldn't orphan.)

**Two-owner split (the reframing — datasets are created by ndh, like netplan):**
- **ndh (HOST layer) owns the dataset lifecycle (survives etcd + instance replacement, on the host `tank` pool via `/dev/zfs` passthrough):**
  - rke2lab contributes a **dataplan** — the TWIN of its netplan contribution. ndh already has a catalog + multi-contributor MERGE model (`ndh/catalog/default.nix`: `catalog.netplan.{lan,wan,tailnet,baremetal}`, `catalog/default.nix:286` throws `"netplan segment …: contributors disagree"`; `flake.nix:79` "rke2lab in turn consumes ndh's catalog.netplan.lan (Direction A)") + ZFS materialisation in `ndh/modules/nixos/zfs-disko-config.nix` (disko). The dataplan slots in as a new catalog dimension → ndh materialises `tank/rke2/persist/{funnel-cert,maven-cache}` at host provisioning, BEFORE the cluster.
  - ndh also **wipes** the ephemeral tree `tank/rke2/control-nodes/*` at instance renewal → kills the orphans, keeps `persist/*`. **RIGHT timing (fresh instance = before rke2 boots) + RIGHT layer (owns the pool).**
- **rke2lab (CLUSTER layer) consumes, does NOT manage the pool:**
  - Dedicated **`openebs-zfs-persist` StorageClass** (pool `tank/rke2/persist`, `reclaimPolicy: Retain`, NON-default). `OpenebsZfsManifestsUnit.createStorageClass` is parameterised on pool + reclaim (both hardcoded today — `ZFS_POOL`, `"Delete"` L97).
  - **Static PV** (`csi.driver: zfs.csi.openebs.io`, stable `csi.volumeHandle`, `storageClassName: openebs-zfs-persist`, `Retain`, `nodeAffinity` topology key **`openebs.io/nodename`** [openebs-zfs FAQ, NOT `kubernetes.io/hostname`] value `bioskop-mgmt-master`) + hand-authored **`ZFSVolume` CR** (adopts the pre-existing dataset) + **PVC `claimRef`**. Re-rendered identically each grow → same names → re-binds the surviving dataset. openebs-zfs still does attach/mount — only `CreateVolume` (random naming) is skipped.

**★ NO in-cluster ZFS agent anymore — the DaemonSet/nsenter idea (original decision 4b) is RETIRED.** nsenter was never needed anyway (ZFS = `/dev/zfs` ioctl in a privileged pod — the openebs-zfs node-plugin's own posture; nsenter/host-mount-ns is the flox-NRI/flox-controller need, not ZFS). The ZFS cleanup moves to ndh/host. **The two prunes DIVERGE in owner:** tailnet = in-cluster Job (SaaS-side, host can't reach the tailnet); ZFS = ndh/host (owns the pool).
