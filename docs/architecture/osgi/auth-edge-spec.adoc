[NOTE]
====
*Status:* IMPLEMENTED (2026-07-07); the credential-CLI token contact RETIRED (2026-10-11). The seventh
external edge of the frontier-playability model, after link:pulumi-edge-handoff.adoc[pulumi-edge],
link:ssh-to-age-edge-handoff.adoc[ssh-to-age-edge], link:dbus-systemd-edge-spec.adoc[dbus-systemd-edge],

It was born as a bare-`ProcessBuilder` edge mirroring incus-edge: `CliAuthTokenContact` shelled
`gh auth token` / `flox auth token` for the launch-secrets writer, which upserted the result into
`.secrets`. GitHub left it first, for the one org-owned App (link:ghapp-domain-spec.adoc[ghapp]); the
FloxHub token then lost its last consumer — nothing in-cluster pulls from FloxHub with auth — and was
removed with its writer, its `.secrets` blocks and its replicated `floxhub-token` Secret. The edge
shells nothing any more: what remains are the two mint verbs, delegated to ghapp.
====

== The contract — two mint verbs

`auth-contract` (`type=contract`) declares the GitHub token mints a consumer calls AT THE POINT OF USE,
from the App's durable credentials:

* `GithubWriterTokenMint` — `mint(GithubAppCredentials) → String`, a FRESH `contents:write`
  installation token (the rendered-branch force-push, the version bump's bot commit).
* `GithubReaderTokenMint` — the least-privilege twin, same signature, a `contents:read` token for a
  consumer that only READS a private repo (a node fetching its rendered `manifests/<cluster>` branch).

Both throw when no usable token can be minted — a caller that must not mint (a survey/preview, an
enclosure without App credentials) never resolves the edge.

Both take the owner's `GithubAppCredentials` (ghapp-contract). They used to take three plain strings,
"so no `ghapp-contract` type is dragged into a consumer that mirrors the App material" — but the edges
re-packed those strings into that very record before delegating to ghapp's `GithubAppMinter`. The
strings were a round trip through a mirror, and they went with the change below.

*`GithubAppTokens` — the one place a GitHub token is obtained (2026-10-10).* A record holding the two
mints and the process environment, with three lanes: `writer` (mint only), `writerOrPipeline` (mint,
else the token Pipelines-as-Code exported in a Tekton run, under `PIPELINE_TOKEN_ENV`) and `reader`. It
reads the App from its OWNER, `GhAppCoordinate.GITHUB_APP`, never from a consumer's mirror. It
replaced three copies of "reveal the App, then mint" — the manifests render's push token, the grown
node's reader token, and the version bump's release-query token — each grown on the manifests mirror.
The lanes stay named because the callers differ: the bump never fell back to the pipeline token, and
folding the copies must not give it one (a test pins it). auth-contract therefore depends on
ghapp-contract; that is not a new coupling, since auth-edge already imported those types to delegate
to the minter. The manifests synthesis keeps its mirror (`GhAppCase` + `GithubAppMaterial`) for what
it RENDERS, the `githubapp` Secret, uniform with its six sibling mirrors: only the token path moved.

This SUPERSEDES the former durable auth-seal (`GithubToken` filed SEALED at an `AuthCoordinate` and
revealed on fetch): an installation token is ephemeral (≈1 h), so a token sealed before provisioning
had gone stale by the reveal after the cluster came up — mint-on-demand is the fix.

== The edge — delegation to ghapp

`auth-edge` (`type=edge`) publishes `GithubWriterTokenMintEdge` and `GithubReaderTokenMintEdge`, each
`@Reference`-ing the ghapp `GithubAppMinter` (the JWT-signing GitHub contact) with the matching
`TokenScope`. Both are `cultivating`-gated, so they activate only when the minter is present.
