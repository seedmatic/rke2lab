**rke2lab integration (all committed on `feature/nixos-node-substrate`):**
- flake consumes `flox-controller` + `flox-runtime` (NRI plugin) on the **`develop`** integration branch (releases abandoned); re-exports their packages; `nixos/flox-controller.nix` **bakes the controller image** into the node-base (`agent/images` air-gap import) — the controller's OWN image is the one baked flox image; it PRODUCES the carriers.
- `FloxControllerManifestsUnit` (runtime domain, registered in `RuntimeDomainRegistrar`): emits the CRD via `UpstreamYamlInclusion` from the flake-staged `/crds/` classpath resource (`nix run .#stage-flox-controller-crd` / seedMasterJar stages it) → `crds` layer by kind; DaemonSet + SA (ns `rke2lab-system`) + ClusterRole/Binding on the **`operators`** layer; image via `FloxDebugPolicy#floxControllerImage` (`io.seedmatic.flox-controller:0.0.0-develop`, IfNotPresent); host `/nix` + containerd-sock + env-root mounts; NODE_NAME + POD_NAMESPACE downward.

**4 bugs peeled at deploy (all fixed + committed):**
1. **Layer deadlock** — controller (operators) needed `rke2lab-system`, but that namespace was created in `workloads` (waits on operators). Fix: `ClusterRuntimeNamespaceManifestsUnit` → **`foundation`** layer (a namespace later layers depend on belongs early).
2. **Node label never applied** — `flox.seedmatic.io/enabled` (renamed from `flox.dev/enabled`) was delivered as an RKE2_CONFIG ConfigMap glob'd from the cluster POST-join, but kubelet applies `--node-labels` only at FIRST registration. Fix: **nixos oneshot `rke2lab-node-labels`** writes `30-node-labels.yaml` at boot (like dualstack/tls-san), from `node.env`; retired the manifest ConfigMap. Cross-world (Java↔nix) dep guarded by the **`node-label-concord` flake check** (`NODE_FLOX_RUNTIME_LABEL` in `ManifestAnnotations` = single source).
3. **Entrypoint `/bin/flox-controller` not found** — `buildLayeredImage` `contents` didn't symlink to /bin.
4. **Entrypoint store-path shadowed** — the controller mounts host `/nix` at `/nix` (to realise + exec node tools), which SHADOWS the image's own `/nix/store` where the binary lived. **Fix (KEY lesson): the controller's binary + cacert are REAL files OUTSIDE `/nix`** (`extraCommands` copies the static CGO-off binary to `/usr/local/bin`), verified in the image tar. Same real-file lesson as the flox carrier's `/etc` — anything a host-`/nix`-mounting container needs at runtime must live outside `/nix`.

**On-node exec VALIDATED (2026-08-28, develop `6882186`).** Ran the controller binary on the node via `incus exec master -- env KUBECONFIG=/etc/rancher/rke2/rke2.yaml NODE_NAME=bioskop-mgmt-master POD_NAMESPACE=rke2lab-system nix run --refresh github:seedmatic/flox-controller/develop#flox-controller` (host binary, no image/mount-shadow; node access = `incus exec master`, no ssh). `Realize` completes CLEANLY (reconciled=N, failed=0): the carrier FloxEnv goes `Ready: True`, `status.realized[bioskop-mgmt-master].storePath=/nix/store/…-environment-dev`, `flox containerize` writes `carrier:latest`, `ctr import` lands it in containerd. The whole producer chain works. Flakes peeled to get here: missing `.flox/env.json` (write it), manifest `schema-version` missing (inject in serialise), `ctr` not on PATH (default `/var/lib/rancher/rke2/bin/ctr` + `--containerd-address /run/k3s/containerd/…`), intermittent `flox activate exit 1` = flox's detached bg check-for-upgrades racing the `.flox` lock (set `_FLOX_TESTING_DISABLE_BG_SIDE_EFFECTS=true`, mirrors the plugin) AND a **second reconciler competing** — the deployed DaemonSet (OLD baked image) reconciled the same CR (suspend `flux kustomization bioskop-mgmt-operators` + delete the ds for a clean nix-run spike).

**SOLIDIFIED since the nix-run validation (develop e381348 / rke2lab 233d1e4a7, all committed):**
- **Host tool access = nsenter, AUTO-DETECTED** (not systemd — stays k8s DaemonSet). `main.go` `inSeparateMountNamespaceFromInit()` compares `/proc/self/ns/mnt` vs `/proc/1/ns/mnt`; differ ⇒ containerized ⇒ `ExecProvisioner.command()` prefixes `nsenter -t 1 -m -p --` on flox/ctr; same ⇒ host (nix-run) ⇒ direct. One binary, both contexts. Needs `hostPID` (on the DaemonSet) — for nsenter -t 1 AND the detection. `nsenter` baked as a STATIC real file `/usr/local/bin/nsenter` (a dynamic one is shadowed by the host `/nix` mount — same lesson as the controller binary).
- **status.realized[node] enriched**: + `envPath` (the `.flox` source dir on the node) + `gcrootPath` (the plugin's readlink handoff), alongside `storePath`. + a `Ready` printcolumn (`kubectl get floxenv` shows readiness; was only in describe).
- **EnsureBase = create-OR-update-if-managed**: labels the base carrier `app.kubernetes.io/managed-by=flox-controller`; on startup creates if absent, else updates its spec to the embedded def IF still labelled ours (operator fork = label removed → left). So a new controller version's embedded carrier propagates on restart.
