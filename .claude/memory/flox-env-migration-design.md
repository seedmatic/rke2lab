**Comportements flox PROUVÉS par un spike (bioskop-nixos `nixos.bioskop`, flox 1.14, aarch64) — décisifs :**
- **`[build]` outputs ≠ closures d'ENV.** Deux `[build.X]` dans un manifest produisent des packages distincts (run strippé 364MiB sans go ; debug symboles 722MiB avec go). MAIS `flox activate` **n'expose PAS** les build outputs sur le PATH, et `flox install .#spike` **échoue** — un env ne consomme pas son propre `[build]`. CHECK_BUILD **valide** le closure runtime vs `runtime-packages` (les symboles debug embarquent les chemins source go → il faut déclarer `go`).
- **`--mode run|dev` = scaffolding SEULEMENT, pas les packages.** `dlv` ([install]) présent dans les DEUX modes. `.flox/run/<sys>.<name>-run|-dev` → deux closures, mêmes packages. `run` saute les `[profile]` scripts (`on-activate`/`[vars]` tournent).
- flox **wrappe** les binaires : `bin/<name>` = script bash (pose PATH) → `.<name>-wrapped` = ELF.
- `flox containerize` containerize l'**ENV** (packages [install] + entrypoint flox-activate), image nommée **`<envname>:latest`** → confirme le souci RepoTag carrier (nom produit ≠ `prodImage()`).

**Conclusion design (le spike a évité un mauvais virage) :** le plugin (overlay) consomme l'**ENV** = packages `[install]` → **le binaire-flavor DOIT être un flake output installé via `[install]`** (modèle kdns actuel `flake="path:../../..#kdns-debug"`), **PAS via `[build]`** (qui sert build/publish/containerize). Donc :
- **Migration = transposer les manifests `environment.d` existants → `FloxEnv` CRs tels quels** (le modèle flake-flavor y est déjà) ; **pas de nouveau mécanisme flavor à inventer**. kdns d'abord (incrémental).
- **flavor strip/symboles** = deux flake outputs (`#kdns`/`#kdns-debug`), dérivés en nix (build symboles une fois, dériver strippé) ; le mode `run` sert juste l'activation lean des pods prod.
- **Fix contrôleur** : `buildEnv` prenait le PREMIER symlink `/nix/store` de `.flox/run/` → avec `-dev`/`-run` présents, tombait sur `-dev` (alphabétique) → gcrooterait le closure DEV en prod. **Sélectionner par suffixe de mode** (défaut `-run`).

**Décisions des 4 forks (design gelé) :**
1. **Lock bidirectionnel** : `manifest.lock` repo seed `status.lock` (repo→cluster, réalisé verbatim, déterminisme) ; update du lock → **write-back git** (cluster→repo). Tranche l'axe lock-producer = *un updater + write-back*.
2. **Course = C : webhook mutateur + barrière**. Verrou k8s natif via le spec du pod. VÉRIFIÉ : scheduling-gate est pré-node (pas node-aware) ; readiness-gate ne bloque pas le container-create ; **seul un init-container est node-aware ET bloquant**. Donc un **mutating admission webhook** injecte un **init-container `flox-wait`** (busybox, hostPath-mount le gcroot base, poll `<base>/<cat>/<name>`, exit) sur tout pod `flox.dev/environment.<c>`. Quasi-stateless (dérive le chemin de l'annotation, pas de RBAC/lecture FloxEnv). Webhook = **Deployment séparé** du DaemonSet (endpoint stable), certs **self-managés controller-runtime** (pas de cert-manager dans le cluster), `failurePolicy: Ignore`→`Fail`. Sûr à déployer AVANT la migration (no-op sur les gcroots bakés présents au boot). Choisi C plutôt que B (init baké par unit) car N pods déjà annotés (kdns/headscale/headplane/tailscale + Jobs).
3. **Incrémental, kdns d'abord.**
4. **flavor = flake outputs** (spike-corrigé ; `[build]`/`--mode` ne conviennent pas à l'overlay).

**Annotation** : le code Java live utilise encore `flox.dev/environment.<c>` (le chemin gcroot est indépendant du domaine → migration d'annotation = chantier séparé). Node label = `flox.seedmatic.io/enabled`.

**CHAÎNE DE RÉSOLUTION — DESIGN SCELLÉ (2026-08-28, le contrôleur = résolveur flox du cluster).** Le contrôleur ne connaît RIEN de rke2lab (générique) ; c'est le CR qui porte la coordonnée. Deux CRDs (split source/consumer, pattern Flux `Kustomization→GitRepository`) :
- **`FloxFlake`** (source) : `spec.sourceRef: {kind: GitRepository, name: rke2lab, namespace: flux-system}` + `spec.dir: runtime/flox`. Le contrôleur lit `GitRepository.status.artifact.{url,revision}` → **tarball IN-CLUSTER au commit EXACT réconcilié** (`http://source-controller.flux-system.svc…/<sha>.tar.gz`, vérifié live). Ref nix = `tarball+http://…/<sha>.tar.gz?dir=runtime/flox#<flavor>`.
- **`FloxEnv`** (consumer) : `spec.manifest [install].<id>.flake = "<FloxFlake>#kdns"`.

**Pourquoi l'artifact Flux (PAS `github:?ref=branche`)** : commit EXACT réconcilié (flake == manifests déployés, zéro drift) ; **in-cluster, zéro fetch github, zéro token côté flake** (Flux a déjà fetché avec le ghapp) ; source unique = la `GitRepository` de `FluxRootManifestsUnit` (repo `github.com/seedmatic/rke2lab`, branche `manifests/<clusterSlug>` = `BRANCH_PREFIX+clusterSlug`, auth GitHub App via `GithubAppSecretManifestsUnit`).

**Résolution (runtime, post-cluster-up — PAS un build-au-boot) :** lire artifact Flux → `tarball+http` → **LOCK** (eval, source dans le tarball) → `status.lock` (rev+narHash) → **write-back git (fork #1)** → **REALISE** closure (le seul truc que la source ne donne pas : build via `--max-jobs 0`→linux-builder bioskop-nixos, ou substitute cache) → **gcroot**. Le plugin (overlay) readlink le gcroot → active la closure. **Flavor** = quel output flake `[install]` (`#kdns` strippé / `#kdns-debug` symboles+delve, défini par `debug` bool dans `runtime/flox/flake.nix` : `-s -w` vs `-N -l`+wrap delve).

**DEUX REQUIS que ça fige :**
1. le synth **publie le flake `runtime/flox` dans la branche rendue `manifests/<cluster>`** (pas seulement baké image) → présent dans le tarball artifact.
2. contrôleur **Flux-aware** : RBAC `get gitrepositories.source.toolkit.fluxcd.io` (capacité générique, pas un couplage rke2lab).

**Prouvé par spike (ne PAS re-tester) :** overlay consomme l'ENV = `[install]` uniquement (flake OU pkg-path sur le PATH d'activate) ; `[build]`/`.flox/pkgs`/`runtime-packages` produisent des `result-*` **jamais** sur le PATH ni self-installables (`.#x`, `path:$PWD#x` échouent) → **lane artefact/image, hors overlay**. `--mode run|dev` = scaffolding SEUL (mêmes packages, `dlv` dans les 2), `.flox/run/<sys>.<name>-{run,dev}` deux closures. flox WRAPPE les binaires (`bin/<x>`=script→`.<x>-wrapped`=ELF). `path:` **bypasse git** (git n'était qu'un fix de tree SALE→narHash drift ; dir pristine→pas besoin de git).
