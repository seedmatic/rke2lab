## The bug (proven, not theorised)
The local grow (`nix run .#grow -- dev up`) fails at the manifests push: `TransportException: https://github.com/seedmatic/rke2lab: not authorized` (`JgitCheckout.push:158`, `x-access-token` + token). It is NOT `GH_TOKEN` (that only feeds maven/GitHub-Packages at build time); the OPERATOR push reveals the **cellar `github-token`** (`ManifestSynthesisScenario.revealGithubToken()` — OPERATOR = `cellar.fetch(AuthCoordinate.GITHUB_TOKEN)`, IN_CLUSTER = env `RKE2LAB_PUSH_TOKEN`).

Proven by:
1. **TTL measured = exactly 1 h.** Signed an App JWT from `.secrets` `github.app` (appId+installationId+privateKeyPem), `POST /app/installations/{id}/access_tokens` → `expires_at` is now+1h.
2. **App + install + scope all correct** → a FRESH token pushes fine. `GET /app`: App `seedmatic-rke2lab` has `contents:write` (+checks/statuses/pull_requests/packages write, metadata read). Installation (account seedmatic, `repository_selection: selected`) covers **seedmatic/rke2lab AND seedmatic/claude-hub**, both `contents:write`. `AuthSealScenario` mints `TokenScope.WRITER` (`GithubAppTokenMinter:69` → `permissions.contents=write`). So it is purely a FRESHNESS problem, not permissions/coverage.
3. **Code sequencing = gap > TTL.** `ClusterSeedScenario`: `the_github_writer_token_is_sealed` (the `"auth"` sow) runs **BEFORE incus-provision**; the push is a sub-sow **INSIDE** incus-provision (after instance boot + RKE2 + cluster readiness + manifests cultivation). So mint→push spans the whole provisioning → easily > 1 h on a cold grow; on a warm-up worse (Pulumi may not re-run the Entry → token from a prior up). Sealing a ~1h token in a DURABLE store, revealed a whole provisioning later, is wrong BY CONSTRUCTION.

The cellar `github-token` Entry is `cellar:sealed:v1:` (a `PassphraseCellarCipher` envelope: domain/mac/payload) — can't be trivially unsealed to test the raw token, hence the code-sequencing proof above.

## The fix (graved, user chose "in-JVM via the auth port", decoupling preserved)
Durable = the App **credentials**; ephemeral = the **token**, minted at the point of use. In-cluster ALREADY does this (PaC mints a fresh git_auth token per PipelineRun); the host/OPERATOR path is the exception that seals.

Key constraint discovered: **the Cellar is jGiven scenario-state (`@Hidden Cellar`), NOT an OSGi service** — ghapp edges (`GithubAppTokenMinter`) take creds as a PARAM; only a scenario can fetch creds. And **manifests-bdd DELIBERATELY avoids importing ghapp-contract** (`ManifestSynthesisScenario` l.197/388: it mirrors creds as a local `GithubAppMaterial` + a neutral-slug `GhAppCase` returning wire "ghapp", "so no ghapp-contract flat copy is dragged into the module"). So manifests already reveals the durable App creds in-container at push time; only "creds → fresh token" is missing.

Plan:
1. **`auth-contract`**: new pure-JDK port `GithubWriterTokenMint { Optional<String> mint(String appId, String installationId, String privateKeyPem); }` — no ghapp type crosses. Bump `package-info` version; doc the type in a spec (spec-coverage gate: simple-name as whole word in `docs/**/*.adoc`).
2. **`auth-edge`**: `@Component(service=GithubWriterTokenMint.class, property="rke2lab.gardening=cultivating")` `@Reference GithubAppMinter` → `minter.mint(new GithubAppCredentials(appId,installationId,privateKeyPem), TokenScope.WRITER).token()`. Add `ghapp-contract` dep to auth-edge pom.
3. **`manifests-bdd` `revealGithubToken()` OPERATOR**: inject `@OsgiService(await=false) Optional<GithubWriterTokenMint>` + reveal `GithubAppMaterial` (already there) → mint fresh at point of use. Keep IN_CLUSTER `RKE2LAB_PUSH_TOKEN`.
4. **`VersionBumpScenario`** (also manifests-bdd): same mint-on-demand instead of `cellar.fetch(GITHUB_TOKEN)`.
5. **Delete the anti-pattern entirely** (no dead code): `AuthSealScenario` + `AuthRunbookHandler` (RunbookCoordinate "auth") in auth-bdd; the `.sowing("auth", …)` step in `ClusterSeedScenario` (`the_github_writer_token_is_sealed`) AND in `PublishCliScenario:197`; `AuthCoordinate.GITHUB_TOKEN`; `GithubToken` record if it falls unused. Verify auth-bdd still has a reason to exist (it may reduce to nothing → drop the module's scenario, keep only if a runbook remains).
6. Build reactor `-am -Dmaven.build.cache.enabled=false`; the osgi-staging gate (`-Pclaude`, `-Drke2lab.staging.skip=true` to skip the copy) must pass (contract-purity, spec-coverage, realm-boundary).
