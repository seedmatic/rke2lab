= Workspace atlas — measured state, target, and the delta
:toc: left
:toclevels: 3

== How to read this

This atlas records the **delta between the code as measured and the vision as specified**. It
is deliberately dated: every figure and every number was read from the tree or from git on
**2026-10-02**, with the command that established it. The specification states what *should*
hold — link:workspace-manifest-spec.adoc[the workspace manifest spec]; this document states
what *does*, so the distance between the two is visible rather than assumed.

When a line here stops matching reality, the atlas is the file to correct — not the spec.

=== What that cost, measured

[cols="2,3"]
|===
| Fact | Measurement

| the dev toolchain was built from a stale line
| 4 refs pinned to a revision **612 commits behind**, dated August 27

| three refs named a branch whose work had landed
| `feature/viewpoint-separation` is an **ancestor of every live branch**, last commit
  2026-10-02

| the editor file had drifted
| **13 entries for 12 distinct folders**; 3 of 13 labels used `.git` or no suffix where the
  convention is `.d`.
  ✅ **Repaired by hand on 2026-10-02**, after this measurement: the duplicate is gone and all
  12 labels now use `.d`. ★ Keep the measurement — it is *why* this file must become generated.
  The duplicate arose from two correct edits meeting: one hand inserted the entry after
  `memory`, another after `flox-catalogue`. Neither was wrong alone. A generated artifact makes
  that collision **inexpressible**, which no amount of care achieves on a hand-held file.

| one organisation rename was missed
| 1 ref still names the former organisation, in a documentation file

| a shared environment include pointed nowhere
| `../common` is declared by **8 environments** and was **never committed in any revision**

| a neighbour's environment included four dead paths
| and it does **not** fail — `flox activate` returns success, because the lock masks the
  composition until `flox include upgrade`

| the published envs branch had frozen
| last touched **2025-12-14**, **20 real commits** behind, **9 whole environments missing**
|===

★ The last two lines are the heart of it. The defect is not that things break — it is that
they **do not**. A lock freezes a composition, so a declaration pointing at nothing keeps
working until somebody asks it to re-resolve.

----

The target removes the dependency on a worktree's **parent directory**, which was the
constraint dictating where a worktree may live. It follows the one subtree in this perimeter
that stayed current: vendored for consumption, authored in its own worktree.

⚠️ **Not safe to execute in the order it reads.** The published branch is missing nine
environments, three of which the seat actually includes. It must be re-split from the live
subdirectory *before* any consumer imports it, or the import breaks the seat on its first
activation.

=== ★ Partially landed on 2026-10-02 — and the rot survived it

Measured while this increment was being written:

[cols="1,2"]
|===
| the principal
| **migrated**. The environments are vendored in its own tree at `.flox-envs.d` — 81 tracked
  files — and the includes read `./.flox-envs.d/{env}`. The dependency on the parent directory
  is gone.

| the neighbour
| **not migrated**. It still includes four absolute paths that do not exist, and still returns
  success, because the lock masks the composition.

| the two parent-directory symlinks
| **still present**, now orphaned leftovers of the old reach.

| the render worktrees
| **still** in the gitignored scratch directory — four of them.
|===

★★ And the finding that matters most, because it was predicted and then observed: the include
declared by eight environments and **never committed in any revision is still dangling after
the migration**. Vendoring changed where the environments live; it did not make anything
re-resolve an include. That is the measured proof that the defect is not about paths, and the
reason the generated verifier — not the vendoring — is what closes this gap.

== Figure 4 — the outbound branch is a bus

[mermaid,atlas-bus,svg]
----
flowchart LR
    P1["producer 1 — out-cluster renderer"]
    P2["producer 2 — in-cluster reflector"]
    BR["branch manifests/{cluster}<br/>git-only, never in etcd"]
    C1["consumer — Flux in-cluster"]
    WC["local worktree<br/>one producer's working copy"]

    P1 --> WC
    WC --> BR
    P2 --> BR
    BR --> C1
----

Measured: two producers write that branch — the renderer commits and pushes it, and the
in-cluster reflector marshals onto it — for one remote consumer. The local worktree is
therefore **one producer's working copy**, and its location is part of no contract.

Today those worktrees are nested in a gitignored scratch directory of the multi-module root.
The target places them in the layout like every other worktree. The argument is **uniformity
and lifecycle**, not cleanliness: a worktree belongs at `{repo}.d/{slot}`, and the code
already carries a comment about a stale nested worktree holding a branch after a remote
rename.

== Figure 5 — the same pattern already exists in the cluster

[mermaid,atlas-symmetry,svg]
----
flowchart LR
    subgraph LOCAL["local — what the manifest builds"]
        L1["flake:{id}"]
        L2["registry.json"]
        L3["a local worktree"]
        L1 --> L2 --> L3
    end

    subgraph CLUSTER["in-cluster — what already runs"]
        C1["floxcatalog:{name}#{output}"]
        C2["controller rewrites it"]
        C3["a concrete nix ref"]
        C1 --> C2 --> C3
    end
----

An environment in the cluster references a catalogue **by name**, and a controller rewrites
that name into a concrete ref. That is the same indirection the registry provides locally.
The workspace is therefore not inventing a mechanism — it is giving the seat the one the
cluster already has.

★ A consequence worth keeping: the cluster's locks are committed **deliberately**, because
they carry `derivation` and `outputs` and so **realise without re-resolving**. A stale
provenance URL inside such a lock blocks a *re-lock*, not a realisation. That measurement is
also what proves activation needs no registry.

=== Deliberately deferred

[cols="1,3"]
|===
| deriving the closure instead of enumerating it
| The list of worktrees *could* be computed from the principal's references — flake inputs,
  subtree prefixes, tool paths — and the depth-2 case (`nnh` through `ndh`) shows the closure
  is transitive. The decision is to **enumerate, statically, for now**. The door stays open;
  nothing is built against it.

| the name of the envs branch
| Naming it after the tool would close that namespace for every future branch, because git
  refuses a ref that is both a file and a directory.
|===

== Deviations from the handoff that produced this work

Recorded because the handoff is scratch and this file is not:

[cols="1,2,2"]
|===
| | The handoff states | Measurement shows

| 1
| one repository is "an input of nobody, an editor folder only"
| it is an input of a neighbour, and reaches the window **transitively**, at depth 2

| 2
| "the DAG", "the DAG closure"
| the **declared** graph has mutual edges — two repositories each naming the other. The
  **evaluated** graph terminates because a back-reference is bound to the **root** by a
  reciprocal empty follows, which is a fixpoint and **not** a removed edge. That is the graph
  the registry populates, and it is why the registry cannot disturb a mutual edge. See the
  specification, *Why the registry does not disturb a mutual edge*

| 3
| the editor file has 12 folders
| it had **13 entries**, one folder duplicated — the handoff's count was of *folders*, not of
  *entries*. ✅ Repaired on 2026-10-02, so the file now holds 12 entries for 12 folders with
  uniform labels. The non-regression assertion is therefore the simple one again — **same set
  of slots, same folder 0** — and no intended diff has to be carved out for it

| 4
| the sink repository is an input of 5 of 6
| of **6**

| 5
| the generator runs in the activation hook
| it **cannot** produce the registry there — the environment builds before the hook runs. The
  materialisation step produces; the hook verifies
|===
