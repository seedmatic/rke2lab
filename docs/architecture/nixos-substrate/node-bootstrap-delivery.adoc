= Node-side bootstrap delivery — closing the substrate loop
:toc: left
:toclevels: 3

[NOTE]
====
This spec covers ONE seam of the NixOS node substrate: how the small *bootstrap set*
(the CNI + Flux) reaches a freshly-grown node's RKE2 auto-deploy directory now that
cloud-init and the `/srv/host` mount are gone. The broader substrate vision (homogeneous
image, `role is config not OS`, `chacun son rôle`) lives in link:substrate-model.adoc[the
substrate model]; where each concern lands is link:concern-ownership.adoc[concern
ownership]; the before/after delta is the link:../atlas/nixos-substrate.adoc[atlas view].
====

== The problem

Every RKE2 server auto-deploys any YAML placed under
`/var/lib/rancher/rke2/server/manifests/` at boot. Under the old model the manifests
scion rendered the tree and the incus GROW *mounted* it into the node via `/srv/host`.
That mount — and cloud-init — were dissolved by the NixOS-substrate refactor, leaving
NOTHING that writes to the node's `server/manifests`. The consequence: with
`services.rke2.cni = "cilium"` the node would still not converge the way the lab needs
(no HelmChartConfig, no Flux), and nothing seeds the GitOps bootstrap. The loop was open.

== The rule — bootstrap set vs the rendered branch

The synthesis produces the whole cdk8s tree, but delivery splits by *when* a resource is
needed:

* the *rendered branch* (git, opt-in push) carries everything Flux reconciles POST-join —
  the workload manifests. Unchanged.
* the *node-side bootstrap set* carries the few resources that must exist BEFORE Flux can
  run: the cilium `HelmChartConfig` (customising RKE2's bundled cilium — the CNI, so the
  node reaches Ready without waiting on Flux), the Flux operator/instance/root, and the
  `sops-age` + `githubapp` Secrets Flux needs to pull and decrypt the branch.

A unit joins the bootstrap set by carrying the `io.seedmatic.rke2lab/node-bootstrap`
annotation (`ManifestAnnotation.NODE_BOOTSTRAP`), stamped once per unit by its
`PackageMetadataProfile(..., nodeBootstrap = true)` so no resource of a bootstrap unit
can escape the lane.

[IMPORTANT]
====
*Cilium native routing is DUAL-STACK and PER-CLUSTER.* The node's `cluster-cidr` is
dual-stack (`10.<44+id>.0.0/16,fd00:<44+id>::/56`) and differs per cluster, so it CANNOT be
a static `nixos/rke2.nix` literal — the `node-base` image is homogeneous across all clusters.
Instead the grow projects the CIDRs (from `ClusterNetworkBlueprint.podCidrDualStack(clusterId)`)
onto the instance's `user.rke2lab.cluster-pod-cidr` / `cluster-service-cidr` devlxd keys;
`rke2lab-identity` reads them into `/run/rke2lab/node.env`, and the `rke2lab-dualstack` oneshot
writes rke2's `10-dualstack.yaml` drop-in from there at boot (the same runtime-drop-in pattern as
`rke2lab-tls-san`). The cilium `HelmChartConfig` MUST enable IPv6 and set both native-routing
CIDRs — `routingMode: native` hard-fails the helm install (`ipv6NativeRoutingCIDR must be set
when routingMode is native`) the moment `ipv6.enabled` is true, and a v4-only config leaves the
node NotReady. `CiliumConfigManifestsUnit` derives those from the SAME blueprint
(`podCidr()` / `podCidrV6()`), so nix and cilium track one source (the identity-keyed blueprint)
rather than both hardcoding a literal. See link:../cluster-api/cluster-addressing-plan.adoc[the
cluster addressing plan] for the per-cluster CIDR formulae.
====

== The seam — synth carves, host poses, node writes

[mermaid]
----
flowchart LR
  subgraph osgi["OSGi realm (in-container)"]
    synth["synthesis scion"]
    explode["exploder"]
    file["NodeBootstrapArtifact.MANIFESTS<br/>.bootstrap/rke2lab-bootstrap.yaml"]
    cellar["ScenarioCellar<br/>SERVER_MANIFESTS (SEALED)"]
    synth --> explode
    explode -->|"NODE_BOOTSTRAP docs"| file
    file -->|"scion reads + files"| cellar
  end
  subgraph host["FLAT realm (host)"]
    grow["InstanceGrow"]
  end
  subgraph node["node (guest)"]
    unit["rke2lab-server-manifests.service<br/>(devlxd oneshot)"]
    dir["server/manifests/rke2lab-bootstrap.yaml"]
    rke2["rke2-server"]
  end
  cellar -->|"grow fetches (revealed)"| grow
  grow -->|"user.rke2lab.server-manifests"| unit
  unit -->|"writes, before"| dir
  dir --> rke2
----

. The *exploder* routes `NODE_BOOTSTRAP`-marked documents out of the per-resource branch
  tree into one multi-doc file, `NodeBootstrapArtifact.MANIFESTS` — a sibling one level
  above the exploded tree, so it is never committed.
. The *synthesis scion* reads that file and files it in the transactional cellar under
  `ServerManifestsCoordinate.SERVER_MANIFESTS` as a `ServerManifestsBundle`, SEALED (it
  carries the App private key and the cluster age identity).
. The pure-host *GROW* fetches it (revealed across the graft) and poses it on the
  instance's `user.rke2lab.server-manifests` devlxd key — alongside the cluster-PKI cases,
  the same dual-realm cellar crossing.
. The node's `rke2lab-server-manifests.service` (a devlxd oneshot, ordered BEFORE
  `rke2-server`) reads the key and writes `server/manifests/rke2lab-bootstrap.yaml`, so
  RKE2 auto-deploys the CNI + Flux on first boot.

== The types

[cols="1,2,2",options="header"]
|===
| Type | Module | Role

| `NodeBootstrapArtifact`
| `manifests-contract` (bundle-only)
| Enum whose one instance resolves the bootstrap file's path from an exploded tree — an
  instance, not a static path helper (instance-discipline). Used by the exploder (writes)
  and the synthesis scion (reads).

| `ServerManifestsCoordinate`
| `manifests-ingress-contract` (`type=dual-realm`)
| The `SeedCoordinate` the scion files under and the host GROW fetches by — dual-realm so
  the FLAT-realm GROW may reference it (the `ClusterPkiCoordinate` lesson).

| `ServerManifestsBundle`
| `manifests-ingress-contract` (`type=dual-realm`)
| The `@SeedContract("server-manifests")` record carrying the multi-doc YAML across the
  cellar; SEALED at rest.

| `NodeGithubTokenCoordinate`
| `manifests-ingress-contract` (`type=dual-realm`)
| The twin `SeedCoordinate` for the node's github *fetch* token — the coordinate the synthesis
  scion files under and the host GROW fetches by. Filed `Persistence.TRANSIENT` (not durable):
  the App creds are the durable source, the minted token is not, so it never persists between
  runs (the `github-token-mint-on-demand` discipline).

| `NodeGithubToken`
| `manifests-ingress-contract` (`type=dual-realm`)
| The `@SeedContract("node-github-token")` record carrying the fresh `contents:read` App
  installation token the standalone GROW poses into the node's cloud-init as
  `/run/rke2lab/nix-github.conf`, where the `rke2lab-rke2-config` oneshot reads it (nix
  `access-tokens`) to fetch the private `manifests/<cluster>` branch, then erases. SEALED at rest.

| `ReplicatorSourceSecretsMaterial`
| `manifests-contract` (bundle-only)
| The mittwald-replicator SOURCE secrets (git basic-auth, docker dockerconfigjson, tailscale
  oauth) the `replicator-secrets` seal rehydrates from `.secrets` and files SEALED; revealed
  in-container and rendered by `ReplicatorManifestsUnit` onto THIS lane, so the real credentials
  are seeded node-side and never committed to the branch. A blind manifests-side mirror (the
  `GithubAppMaterial` treatment).
|===

The *replicator source secrets* ride the bootstrap lane rather than the branch precisely because
they carry real credentials: the branch is committed via jgit with no sops filter, so a secret
rendered there would be plaintext (see the exploder's `.gitattributes` second belt). The seal
(`ReplicatorSecretsSealScenario`, sown by `the replicator secrets are sealed` before
incus-provision) reads `.secrets` `kubernetes.secrets` (the source→target mapping) + the
`tekton.*` / `tailscale.*` credential blocks through the read-only `SecretsGateway`, assembles the
`ReplicatorSourceSecretsMaterial`, and files it SEALED. The rendered source secrets carry the
mittwald `replication-allowed` + `replication-allowed-namespaces` annotations so the in-cluster
replicator fans each out to the target namespaces where the `replicate-from` placeholders live.
