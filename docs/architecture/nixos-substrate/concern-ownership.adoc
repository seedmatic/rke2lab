[NOTE]
====
The payoff of the systemd-scripts review: where each provisioning responsibility LANDS once the
substrate is declarative. This is the redistribution map that makes link:substrate-model.adoc[the
substrate model]'s "chacun son rôle" concrete — old responsibility → new home, and whether the flake
already carries it.

== The dissolution

The old chain — `distrobuilder` image, `cloud-init` user-data, ~28 host systemd scripts materialised
onto `/srv/host` then stowed into `/etc/systemd/system` — redistributes cleanly. The delivery
*mechanism itself* (`rke2lab-systemd-link` + `rke2lab-activate`) dissolves into NixOS
`systemd.services.*`: there is no tree to materialise, no stow step, because *the closure IS the
config*.

== Per-node residue is bootstrap config

Per-node residue (name/kind, join token, the per-node ZFS dataset, the layer publish flags) is
*bootstrap config*: generated by CAPRKE2 for peers/workers, a small seed for master — never a
hand-script. It reaches each instance over *devlxd* (`user.rke2lab.*` keys), read back at boot by
`nixos/identity.nix`. The former `RKE2LAB_MANIFESTS_PUBLISH_*` env→symlink flags are re-plumbed to
Flux Kustomizations enabled/disabled on the rendered branch.

== The ZFS dataset layout is a dataplan, owned by seed-master

The *layout* of the cluster's ZFS datasets is no longer a static literal in ndh's
`zfs-disko-config.nix`. It is a *cluster need*, so its single source of truth is
rke2lab `seed-master`, provided to ndh as a *dataplan* — the storage twin of the
netplan blueprint (see link:../patterns/dataplan-single-source.adoc[Dataplan
SSOT]). ndh pulls `lib.dataplan` over the flake edge, merges it into
`catalog.datasets`, and materialises it; the root is `tank/rke2lab` (owner, not
the `rke2` distro), and *every cluster gets its own root under it*:
`tank/rke2lab/<role>/{ephemeral,persist}`.

The two dataset natures split their *lifecycle* owner:

* *ephemeral* `<role>/ephemeral/*` — wiped by *ndh* at instance renewal (host
  layer, right timing: a fresh instance boots before rke2, no in-cluster agent, no
  `nsenter` — ZFS is a `/dev/zfs` concern the host already owns);
* *persist* `<role>/persist/*` — retained across grows, a *sibling* of
  `ephemeral` inside the cluster root so the wipe never reaches it; bound
  in-cluster by a static PV with a stable handle (the funnel cert survives → no
  Let's Encrypt re-issuance).

This diverges from the *tailnet device* prune, which stays in-cluster (a Job
before the Tailscale operator registers) because the tailnet is SaaS-side and the
host cannot reach it. Two prunes, two owners.

=== The node owns its containerd dataset — the layout declares only parents

The per-node dataset named in the table above is *created by the node*:
`nixos/containerd.nix` does `zfs create -p` when it is absent, then mounts it.
That is why the dataplan declares only the PARENTS (`<role>/ephemeral/nodes`,
`<role>/ephemeral/volumes`) and no node roster — a CAPI-provisioned node's name is
random, so a declared roster could only ever describe host-grown pets, and the
live tree proved it: three declared pets sat empty while the real workload node
had made its own dataset.

IMPORTANT: the dataset is keyed on the NODE NAME, never on the node's
link:../cluster-api/pac-in-cluster-render-spec.adoc#pet-label[pet label] — the
mount is ordered `before=rke2-server.service`, so it happens before the node joins
and before any `Node` object exists to carry a label. See
link:../patterns/dataplan-single-source.adoc#pet-not-in-the-path[the rule]: the pet
names what must survive, the node name names what must not.
