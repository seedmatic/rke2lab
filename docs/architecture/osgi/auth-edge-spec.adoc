[NOTE]
====
*Status:* IMPLEMENTED (2026-07-07). The seventh external edge of the frontier-playability model, after
link:pulumi-edge-handoff.adoc[pulumi-edge], link:ssh-to-age-edge-handoff.adoc[ssh-to-age-edge],
link:dbus-systemd-edge-spec.adoc[dbus-systemd-edge], link:cluster-edge-spec.adoc[cluster-edge],
link:incus-edge-spec.adoc[incus-edge] and link:bbox-edge-spec.adoc[bbox-edge]. It mirrors the
bare-`ProcessBuilder` shape of incus-edge: a single `@Component` shells the external tool; everything
else consumes a port.

Same working unit as the rest of the control-plane→OSGi sweep: *one external contact, extracted
atomically* — the port, the edge, AND the re-wiring of the consumer, in one change. The criterion
holds: a type migrates to a bundle only if a bundle `@Component` contacts an external system (→ edge)
or rides its verb (→ port). Reading an environment variable is not a contact — it stays host.
====

== The contact today — inlined in the host launch-secrets updater

`IncusResourceBootstrap.LaunchSecretsUpdater` (seed-master) upserts two credentials into the
launch-secrets YAML: a GitHub token and a FloxHub token. Each is resolved by a two-step precedence —
first an environment variable (`GITHUB_TOKEN`/`GH_TOKEN`, `FLOXHUB_TOKEN`/`FLOX_TOKEN`/`FLOX_AUTH_TOKEN`),
then, failing that, by *asking the provider's CLI*: `gh auth token` / `flox auth token`, run through a
`ProcessBuilder` (`captureCommandOutput`).

Only that CLI call is an edge. The environment-variable precedence, the YAML upsert that preserves
comments, and the dry-run guard are host orchestration that genuinely stays — reading `System.getenv`
crosses no frontier.

== Resolution — an `auth-edge` `@Component` and an `auth-contract`

* *auth-contract* (`type=contract`): `AuthTokenContact` — the verb `tokenFor(AuthTokenSource) →
  Optional<String>` (empty = the CLI is absent/unauthenticated/non-zero, a present value is trimmed and
  non-blank); and `AuthTokenSource`, the flat contract enum (`GITHUB`, `FLOXHUB`). No host config type
  crosses; the host maps its own env-var precedence and only asks the contact when the environment
  yielded nothing. It also carries the GitHub push-token *mint verb*: `GithubWriterTokenMint`, a
  pure-JDK `mint(appId, installationId, privateKeyPem) → Optional<String>` that mints a FRESH
  `contents:write` installation token AT THE POINT OF USE from the durable App credentials a consumer
  reveals from its own cellar case. The credential fields cross as plain strings so no `ghapp-contract`
  type is dragged into a consumer that mirrors the App material; empty = the mint edge is filtered out
  (survey/preview) so the caller skips the push. Its least-privilege twin `GithubReaderTokenMint` has
  the SAME signature but mints a `contents:read` token — for a consumer that only READS a private repo
  (a node fetching its rendered `manifests/<cluster>` branch to install its rke2 config), where a
  write-scoped token is over-privileged. This SUPERSEDES the former durable auth-seal
  (`GithubToken` filed SEALED at an `AuthCoordinate` and revealed on fetch): an installation token is
  ephemeral (≈1 h), so a token sealed before provisioning had gone stale by the reveal after the cluster
  came up — mint-on-demand is the fix. `GithubToken` and `AuthCoordinate` are deleted.
* *auth-edge* (`type=edge`, `@Component`): `CliAuthTokenContact` — maps `GITHUB → gh auth token`,
  `FLOXHUB → flox auth token`, and shells nothing else. Pure `ProcessBuilder` over the JDK, no embedded
  jars, mirroring incus-edge's ssh contact. Its sibling `GithubWriterTokenMintEdge` realises
  `GithubWriterTokenMint` by delegating to the ghapp `GithubAppMinter` (the JWT-signing GitHub contact);
  it is `cultivating`-gated, so it activates only when the minter is present. `GithubReaderTokenMintEdge`
  is its least-privilege twin — same delegation, `TokenScope.READER` (`contents:read`).
* *seed-master* (host): the updater keeps the env-var precedence and the YAML upsert;
  `ensureLaunchSecretsToken` resolves `AuthTokenContact` from the registry
  (`singleSpiProvider(AuthTokenContact.class)` on the already-held `BootedFramework`) and passes it into
  `LaunchSecretsUpdater.ensureTokensPresent`. The host `captureCommandOutput` is gone.
