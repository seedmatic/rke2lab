**Status:** 📐 vision, open for brainstorming. Nothing here is built. Seeded on 2026-10-08 from the
specifications first written for link:relock-across-levels.adoc[relock across the platform's levels].
That design is paused on this one and will be rebased on it.

== Overview

Every seedmatic repo is reached from other repos: it is pinned as a flake input, its outputs are read
(the netplan contributions, the CRDs staged into the synthesis), and its relock is requested. What a
repo *is*, and how it relates to the others, is today scattered. Part of it is in `flake.nix`
(inputs, `lib.*`), part in `flake-registry.json`, part in the arguments each repo passes to
`lib.mkRelockApp` — including `consumers`, a list a repo writes about repos that pin *it* — and
part in committed JSON at the root of rke2lab (`dataplan.json`, `network-blueprint.json`).

The vision: **each repository owns one manifest that describes it, in a directory of its own.**

[source]
----
.github/          what GitHub reads about the repo
.seedmatic.d/     what seedmatic reads about the repo
  repository.json   the repo's manifest — owned by the repo, introspected by its consumers
  relock.json       the trace of the last relock that changed something
  netplan.json      a contribution (today rke2lab's network-blueprint.json)
  dataplan.json     a contribution (today rke2lab's dataplan.json)
----

A consumer introspects a repo's manifest to learn its relations with the other repos. Nobody writes
another repo's relations.

== Principles

. **One owner per manifest.** A repo's `repository.json` is written in that repo only. The relations
  it states are the ones *it* holds — what it pins, what it is the hop of — never who pins it. The
  inverse is computed by whoever reads all the manifests.
. **A claim, checked against the fact.** A declared relation is a claim; the repo's `flake.lock` is
  the fact. Every reader that orders work by the manifests checks them against the locks first.
. **Tool-independent.** The manifests are JSON, so nix (`builtins.fromJSON`), Java (the synthesis)
  and a cluster pipeline (the GitHub API) all read them without evaluating anything else.
. **GitHub is the channel.** A manifest is visible to the others once pushed. A reader reads the
  pushed head, with nix's cache refused.
. **Changes carry their trace.** A commit that changes derived state carries its context in
  `.seedmatic.d/` in that same commit, never in a commit of its own.

`.seedmatic.d/` is not ignored by git (checked on 2026-10-08: no global or repo rule matches it), so it
is committed and part of a flake's source. It follows the existing style of `.flox-envs.d` and
`.ndh-ssh.d`.

== `repository.json` — a first draft of its schema

[source,json]
----
{
  "schema": "seedmatic.repository/v0",
  "slug": "seedmatic/rke2lab",
  "branch": null,
  "id": "rke2lab",
  "relations": {
    "pins": [ "nix-flake-commons", "flox-controller", "flox-nri-plugin", "ndh", "seed-incluster" ],
    "hopOf": null
  },
  "contributes": {
    "netplan": ".seedmatic.d/netplan.json",
    "dataplan": ".seedmatic.d/dataplan.json"
  },
  "commands": [ "relock" ]
}
----

[cols="2,5",options="header"]
|===
| Field | Meaning

| `slug`, `branch`
| `owner/repo`, and the orphan branch for a flake that is not its repo's default one. The request
reference (`github:<slug>[/<branch>]`) and the visited-list key (`<slug>[:<branch>]`) derive from
them.

| `id`
| the flake-registry id, when it is not the repo's name (`flox-runtime` for flox-nri-plugin). A lock
names an input by `original.id`, and an orphan's `locked` carries no `ref`, so the id is how a lock
is matched to a manifest.

| `relations.pins`
| the repos this one pins as root inputs, by name. Checked against the lock.

| `relations.hopOf`
| a repo whose relock reconciles this one, so it is never run on its own (flox-catalog: rke2lab).

| `contributes`
| the files this repo publishes for others to read.

| `commands`
| what the repo exposes under the uniform names (`#relock` today).
|===

Open on this draft: whether `slug` and `branch` belong in a manifest that already lives in that very
repo; how a repo with several flakes (rke2lab and its two orphans) carries one manifest per branch;
how the schema versions.

== `relock.json` — the trace of a change

Rewritten in the commit that carries a change, never alone:

[source,json]
----
{
  "pass": "2026-10-08T18:40:12Z-nix-flake-commons-5d1a9b5",
  "tool": "98003774…",
  "start": "nix-flake-commons",
  "position": 5,
  "seat": "ndh",
  "bumped": { "flake-commons": [ "83c2364", "5d1a9b5" ], "rke2lab": [ "3827e57", "5e32b50" ] },
  "dropped": [ "nixpkgs" ],
  "catalog": null
}
----

The file states the last change at the head; `git log -- .seedmatic.d/relock.json` gives the
history. The NixOS guests and the nodes provision from the head of `develop`, so this is how the
level that *consumes* a change learns which pass made it.

== The levels that read the manifests

The same platform reads differently depending on where you stand. Three machines are stacked under
the clusters:

. **the Mac** — bioskop, nikopol — under nix-darwin from ndh, hosting the operator's seats;
. **the NixOS guest** `<host>-nixos`, a Tart VM that boots from the generic image `nerd-nixos` and
  then takes its host's name; it is the Incus host;
. **the Incus instances**, NixOS `lxc-container` images built by rke2lab, which are the RKE2 nodes.

Above them run the **clusters**, management and workload, and later the **workspaces**.

== What any writer must provide

A writer is anything that commits to a repo on the operator's behalf: an operator seat today, a
pipeline later.

[cols="2,4",options="header"]
|===
| Need | Why

| `nix`, with network to GitHub
| what it builds is fetched from GitHub

| a GitHub token with `contents:write` on **every** repo it writes
| a token that reaches only some repos stops the work halfway

| a canonical `TMPDIR`
| nix refuses a `git+file` flake that crosses a symlink once it is dirty (measured: `/tmp` on macOS)

| a nix cache it can **isolate** for proofs
| nix caches `revCount` by revision: a warm cache can hide a failure (measured 2026-10-08)

| a git identity, and signing where a branch requires it
| the commits are the trace
|===

== Reading the manifests without the cache

A manifest read from a stale cache would make every reader lie, silently. A reader therefore reads
with `--refresh`, and treats nix's own fallback messages (`using cached version`,
`unable to download`) as a failure. That is the rule `relock` already applies to a bump.

It must be **proven**, not asserted:

. **bats:** the fake `nix` emits the fallback warning on a manifest read. The reader must fail and
  name the repo. A mutation that drops the stderr check must fail that case.
. **real nix, cache isolated:** read a manifest with `XDG_CACHE_HOME` pointed at an empty directory,
  then push a new one and read it again through the operator's warm cache with `--refresh`. Both reads
  must return the pushed value.

== Option studied — projecting the manifests through rke2lab's synthesis

rke2lab already projects state into cluster manifests that Flux reconciles, and it sees most repos
through its inputs. Could it project the repos' `.seedmatic.d/` into the clusters too?

What exists:

* rke2lab's synthesis reads nix only through **classpath staging**: store paths copied into
  `manifests-core/target/generated-resources/{crds,rbac,image-refs}`, then read by a `ManifestsUnit`.
  `dataplan.json` and `network-blueprint.json` flow the other way, from Java into nix.
* rke2lab's input closure holds nix-flake-commons, flox-controller, flox-nri-plugin, seed-incluster,
  ndh, and nnh through ndh. **nch and seat-roster are not in it**: nch pins ndh but is pinned by
  nobody, and seat-roster pins only flake-commons.

Consequences, measured from that:

* Two repos would be invisible to the projection unless rke2lab took them as new inputs. Taking nch
  creates no cycle, since nch pins ndh and not rke2lab. Taking seat-roster adds an input that rke2lab
  does not otherwise use.
* The projected state would be what rke2lab *locked*, one pass behind the heads.
* It needs a new staged directory, a resource entry and a `ManifestsUnit`, all in rke2lab, for a
  view that git already gives.

The projection is useful only if a cluster object must *react* to a manifest. Decision: ⬜ operator.

== Migrating what exists

The convention changes the place of files that exist today. That is a chantier of its own, on its own
branch:

* rke2lab's `dataplan.json` and `network-blueprint.json` move to `.seedmatic.d/`. The move touches the
  `regen-*` apps that write them, relock's `ownedArtifacts`, the `*-fresh` checks, and the Java code
  that writes them. ndh reads them through `rke2lab.lib.*`, so ndh is not touched.
* The `consumers` argument of `lib.mkRelockApp` goes, replaced by the inverse of the manifests'
  `pins`.

== Open questions

* **`pins` declared, or derived from the lock by `original.id`?** `relations.pins` repeats what the
  repo's `flake.lock` already says. Any reader that orders work reads the remote locks anyway, to check
  `pins` against them (the plan's `verified.locks`). The field is therefore a second source of truth
  that adds nothing, and the argument "what ordering needs without the network" does not hold, since
  that reader is on the network. Only `id`, `branch` and `hopOf` say what the lock cannot say. The
  relock design depends on the answer: its contribution is written as "only what its lock cannot say"
  (link:relock-across-levels.adoc[relock across the platform's levels], § A seat's contribution).
* **Token reach.** Does the GitHub App installation, or gtm's write token, cover every repo? seat-roster
  appears in no document read for this vision.
* **Workspaces and worktrees.** No document says how a workspace pod gets its git worktrees.
* **Status back to GitHub.** No Flux Alert or commit status reports anything today, although the App
  holds `statuses` and `checks`.
* **Several flakes in one repo.** rke2lab carries three: `develop` and its orphans `seed-incluster`
  and `flox-catalog`. One manifest per branch, or one per repo that names its branches?
* **The schema's home and versioning.** Where `seedmatic.repository/v0` is defined, and who validates
  it.
