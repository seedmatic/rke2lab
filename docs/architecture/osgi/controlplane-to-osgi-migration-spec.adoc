= control-plane → OSGi — the external-contact sweep
:toc: left
:toclevels: 3

[NOTE]
====
*Status:* SHIPPED (2026-07-07). Record of the completed sweep that moved the host-side
`controlplane/` external contacts into OSGi edges the host composes. This document is the *index and
rationale* of the sweep; each contact has its own edge spec (linked below). It is read FROM the code
(the shipped edges + the stage imports of 2026-07-07), not imposed on it.

*This supersedes an earlier framing.* The first draft of this spec proposed migrating "the 87
Pulumi-free `controlplane/` files into domain services (port + core + fake), in coupling order
config→policy→readiness→…". That framing was wrong and was abandoned: two increments built on it
(config, policy) were reverted (commit `8eec94a`). The correct model — and what actually shipped — is
below.
====

== The criterion — what migrates, learned the hard way

A type moves into an OSGi bundle *if and only if* a bundle `@Component` **contacts an external
system** (→ it belongs in an `-edge`) or **rides that contact's verb** as a parameter/return (→ it
belongs in a `-contract`). Nothing else moves.

"Pulumi-free" is NOT the criterion. Being reachable on `{JDK ∪ ports}` (a closed dependency DAG) is
*necessary* but not *sufficient*: a class can be perfectly placeable and still have no reason to
cross, because nothing about it touches the frontier. Orchestration, config-input records, the bdd
`Stage`s, the retry loops, the Pulumi resource graph — all of that is placeable AND stays host,
because none of it is an external contact.

The consequence: the real migration surface was never "87 files". It was a handful of *external
contacts* — the points where host code shelled a process, opened a socket, or drove a CLI. Each was
extracted atomically.

== The working unit — one contact, extracted atomically

Every extraction is one change that ships together:

. `-contract` declares the verb (a `type=contract` interface) + its flat request/result records — an
  installed bundle, wired bundle-to-bundle inside the OSGi world; no host config type crosses.
. `-edge` provides it (`@Component`, `type=edge`) — the single door to that external system, and
  nothing else.
. the host CONSUMER is re-wired in the SAME change to compose the edge from the registry
  (`awaitService` in a `Stage`, `singleSpiProvider` in host Pulumi code) — the old inlined mechanism
  is deleted, not deprecated.
. a boot proof asserts the embedded edge resolves and SCR publishes the contact typed across the
  seam.

The pattern has two shapes: *bare `ProcessBuilder`* (incus, auth, cluster, ssh-to-age — pure JDK, no
embedded jar) and *library-backed* (bbox — a third-party client made an OSGi bundle and imported, the
library vocabulary translated to a home vocabulary at the edge so no library type crosses the seam).

== The cut line — the two-worlds invariant

`grep -ri pulumi osgi/ == 0` ⇒ `com.pulumi` CANNOT enter Felix. The host is a *midwife*:
`Pulumi.run(ctx)` crosses the frontier first, calls OSGi through the registry, receives a flat value,
materialises `com.pulumi.*` resources, then its job is done. One direction only (host → OSGi via
`awaitService`); OSGi never calls back, it returns flat records (or a serialized `Document` for
deep-DAG data). The frontier is a *birth canal*: crossed once at master's seed, then sealed. The
existing gateway suffices; the sweep added no new machinery.

== What stays host — and why it is NOT a dead-end

[NOTE]
.Re-baselined — the migration completed past this 2026-07-07 snapshot
====
This section was written when the host `controlplane/` still held an orchestration spine. Since then the
migration LARGELY COMPLETED and re-shaped: the host stage/orchestrator classes named below —
`IncusResourceBootstrap`, `BboxReconciliationOrchestrator`, `SeedSystemdAdapterEndpointGate`,
`StageContext`, `SeedProbes`, `SystemdAdapterStage`, `BboxStage`, `IncusStage`, and the
`Outputs`/`Resources` stages — are all SUPPRESSED. Their metier moved into the domain scions
(`bbox-bdd`, `incus-bdd`, `systemd-bdd`, `cluster-bdd`), reached by `broker.sow`. `ClusterSeedScenario`
is now a jGiven scenario whose steps are sow-and-graft callers, not a stage assembly. What genuinely
stays host is the `com.pulumi` Pulumi edge (the instance GROW, shipped as `InstanceGrow` in
`host/pulumi/incus-ingress`) and the flat config input. Read the bullets below as the rationale (which
kinds of code never cross), not as a current inventory of host classes.
====

The bulk of `controlplane/` was placeable yet stayed host, because it is not an external contact:

* *Orchestration* — the provisioning graph + `Output<T>` wiring, blueprint enumeration, the readiness
  retry loop/deadline/`ObservationView` projection. This orchestration never crossed the frontier; in
  the completed migration it was re-homed as domain scions (metier) + the pure-host Pulumi graph
  (`InstanceGrow`), not kept as the original host stage classes.
* *Config input* — `Rke2labConfig`/`BootstrapConfig` read Pulumi config host-side and project flat
  scalars into the edge requests.
* *The Pulumi edge* — the `com.pulumi` files (resource registration + `Output<T>`), now in
  `host/pulumi/incus-ingress` (`InstanceGrow` + `IncusProviderContext` + `IncusImportLookup`).
* *The scenario spine* — `ClusterSeedScenario` runs ON `scenario-engine` and composes the domains; it is
  a jGiven scenario of sow-and-graft steps (the former `StageContext`/`SeedProbes`/`Outputs`/`Resources`
  stage types are gone). Owner is the seeding-scenario concern, not a leaf domain.
* *Determinism made it moot* — `RuntimeCommandPreflight` (command-availability checks) was deleted, not
  migrated: nodes are provisioned with nix, so their environment is deterministic and the checks
  guarded nothing.

== How the edges are consumed (re-baselined — the stages are gone)

The original sweep left host `Stage`s (`SystemdAdapterStage`, `BboxStage`, `IncusStage`) that reached a
contact through the registry (`awaitService`). Those stages are SUPPRESSED. In the completed migration
the contact-consuming metier lives in the domain scion, reached by `broker.sow`, and the sole host
consumer of an edge is the pure-host Pulumi GROW:

* the systemd / bbox / cluster contacts are consumed by their scions (`systemd-bdd`, `bbox-bdd`,
  `cluster-bdd`), which `@OsgiService`-inject the contact in-container — not by a host stage;
* the `ImageBuilder` contact is composed by the host `InstanceGrow` (`host/pulumi/incus-ingress`) from
  the registry, only when a rebuild is needed — the one place a host Pulumi consumer still composes an
  edge directly.

A migrated contact does not imply a re-pointed stage: a contact moves into an `-edge`, and its consumer
is either the domain's scion or (for the image build) the host Pulumi GROW. See the IMPORTANT note below
for why the host reaches domain metier by `sow`, never by `awaitService` on a `type=contract` type.

[IMPORTANT]
====
*The host holds only `seed-broker-port`; it reaches every domain through `broker.sow`.* A domain's
contact types are `type=contract` — installed bundle-side, wired bundle-to-bundle, NOT a seam — so they
are not on the host's flat classpath and the host cannot consume them by `awaitService`. A contact is a
`SeedHandler` behind the door; the host sows a coordinate and reaps a verdict.

The frontier therefore runs THROUGH the host Pulumi GROW (`InstanceGrow`, `host/pulumi/incus-ingress`),
not around it: the `com.pulumi.*` provisioning graph is host (Pulumi cannot enter Felix); the
contact-consuming metier (`ImageBuilder`, `AuthTokenContact`, the network blueprint) is the domain's
in-container scion (`incus-bdd`), reached by `sow`. Incus is a graft-caller in
link:../bdd/bdd.adoc#clusterseed-scenario-map[the ClusterSeed scenario map] — the host sows the incus
scenario and grafts its scion, holding no incus vocabulary.
====

== The SPEC_COVERAGE ratchet

The `SPEC_COVERAGE` gate (`maven-embed-staging-ext`) requires every type a bundle EXPORTS to be
named as a whole word in some `docs/` `.adoc`, OR to carry `@Transitional`. It is a code-first ratchet,
not a violation counter: a type leaves the specs only when the CODE stops exporting it. The
fluent-synthesis grammar shows the far end of the ratchet: it was once the `pipeline-port` seam
under SPEC_COVERAGE, but its engine (`Phase`, `PhaseRunner`, `PhaseFailure`) is now UN-EXPORTED,
internal to `manifests-core` (`io.seedmatic.rke2lab.manifests.internal.synthesis`), so it left the
specs the moment the code stopped exporting it — no doc names it any longer. Each shipped edge's
exported contract types are covered by that edge's own spec (table above). This index names them
once more so the sweep reads whole in one place.
