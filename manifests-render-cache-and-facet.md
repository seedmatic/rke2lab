## 1. Tailscale Connector cold-start race → planner cross-layer edge (FIXED + PROVEN, commit `412724651` pushed)

`FluxServiceKustomizationPlanner` skipped the derived CRD→CR `dependsOn` edge whenever the CR's provider shared the consumer's **coord** (`!consumer.coord().equals(providerCoord)`). Tailscale is the only installer whose operator (HelmChart, operators layer) and its `Connector` CR (workloads layer) live in the **same coord `mesh/tailscale`** (differ only by LAYER) → the edge `mesh-tailscale-workloads → mesh-tailscale-operators` was never emitted, though `TailscaleManifestsUnit`'s own comments rely on it. On cold-start the `Connector` dry-ran before the operator registered `tailscale.com` → `no matches for kind "Connector"`, wedging the kustomization (+ the ProxyClass in the same lot → operator log spam). Cross-coord installers (cert-manager, cilium) were fine (edge passes the guard). **Fix:** skip only the consumer's OWN cell, not its whole coord. **PROVEN locally** (see recipe below): with mesh on, `flux/mesh/mesh-tailscale-workloads.yml` gains `- name: mesh-tailscale-operators`. Manual unblock used at the time: `flux reconcile kustomization mesh-tailscale-workloads --with-source` (RESTMapper was stale after the CRD established 2s after the failed dry-run).

## 3. ★ `synthesize` vs `publish` facet asymmetry + the local-validation recipe

In `exec/manifests-cli/.../Main.java`: `synthesize` → `runFromSystemProperties()` → `manifestsFacet()` ONLY (operator posture = every layer on **except mesh**, overridable per-layer via `-Drke2lab.manifests.publish.<layer>=true`). It **never** consults `recordedFacet()`. `publish` → `runForPublish()` → `recordedFacet().orElseGet(operator posture)` (reads `-Drke2lab.manifests.facet.file`). So **`-Drke2lab.manifests.facet.file` is IGNORED by synthesize** — passing the recorded facet to a bare `synthesize` leaves mesh OFF.

**Local-validation recipe (how a planner/manifests change is proven):**
```
flox activate -- ./mvnw -pl :manifests-cli -am package -Pclaude -DskipTests -Dmaven.build.cache.enabled=false
flox activate -- java -Drke2lab.manifests.publish.mesh=true \
  -jar exec/manifests-cli/target~claude/manifests-cli-0.0.0-SNAPSHOT-exec.jar synthesize
# → reads the printed temp outdir, inspect <outdir>/flux/<domain>/<svc>.yml
```
Use `-Drke2lab.manifests.publish.mesh=true` (NOT facet.file) to render mesh in a standalone synthesize.

**Proposed enhancement (NOT implemented, user asked):** make `synthesize` also honor the recorded facet — priority to explicit `-Drke2lab.manifests.facet.file`, else auto-read `<outdir>/manifest.yaml`'s `facet:` at the render-worktree root, else operator posture — so "synthesize in a render worktree == same facets as the grow" is free, keeping the explicit override.

## 4. This worktree's build/test cache constraints (learned the hard way)

- **Disable the maven build cache** for any real local build here: `-Dmaven.build.cache.enabled=false` (or `-Dmaven.build.cache.skipCache=true`). With it on, editing a module cache-MISSES it but the build-cache extension can't reactor-resolve its siblings (`Could not find artifact … domain-annotations / seed-broker-shape / …`) → BUILD FAILURE. Cache-off makes `-am` build siblings from source.
- The **`all-worlds`** profile clears `surefire.excludedGroups` → runs the **slow LIVE deployment tests** — do NOT use it just to widen the reactor; the default profile keeps live tests excluded (safer).
- Go (flox-controller): the `go test` DRIVER gets OOM-killed here on the envtest-heavy controller pkg → compile-run the test binary directly (`go test -c -o /tmp/x.test ./pkg && /tmp/x.test -test.run …`).
