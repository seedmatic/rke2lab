== Unit repository — per-subsystem view

The fourth subsystem to adopt the ritual. The unit-repository vision — an OSGi-resolution plus
peer-to-peer provisioning and history layer — was developed in the standalone `docrepo-dag-wip` repo
while rke2lab was not yet ready to host it. The runtime view's framework now boots in production, so
the vision is folded in here. It does not sit beside the others: it is the GENERALIZATION of which the
doctor's medical-record substrate is one instance (a ledger-backed specialist's stack is a unit-DAG).
The full design is link:../unit-repository/model-overview.adoc[the unit-repository model overview]; this
view holds the inventory, the additivity proof, and the capability map.

=== The objective — what this view is ultimately for

Before the inventory, the goal that gives the work its meaning. Today seed-outcluster is a transient
orchestrator: it boots on the physical host, provisions a cluster, then dies — a special node holding
the amount, its code baked flat in the exec-jar. The objective dissolves that asymmetry: the
orchestrator becomes an ordinary peer in the cluster it bootstrapped, and everything — data and code —
lives in the DAG. The move is monotone: seed-outcluster is not deleted, it MOVES from orchestrator to
workload-peer; the kernel level-0 shrinks to a throwaway bootstrapper that creates the empty cluster,
seeds the first pull, and erases. At steady state everything is a workload-node — total homogeneity,
the reflexive bootstrap closed. SHIPPED: the level-0 kernel and the cluster as an output. DESIGN: the
store holding code, migration-by-pull, the homogeneous steady state, the mesh. The before/after figures
live in link:../unit-repository/model-overview.adoc[the model overview]; this view proves the design that
gets there is additive.

=== The model inventory

[cols="2,1,3",options="header"]
|===
| Model | Status | Note

| resolution oracle — `UnitResolver`
| ✅ Shipped (blue)
| Wraps the injected Felix `Resolver`; computes any unit set's Provide/Require closure. In production
  via `ManifestsUniverse` plus `CoherentManifestsDomainRegistry`; the hand-rolled walker is deleted.

| manifests universe — `ManifestsUniverse`
| ✅ Shipped (blue)
| Re-expresses each `ManifestsUnit` and domain as a `UnitResource` with Provide/Require — the resolver
  candidate set, the reserved sense of `universe`.

| filter match — `CapabilityFilter`
| ✅ Shipped (blue)
| Matches a requirement's `filter:` directive (RFC-1960 LDAP) against a candidate capability's
  attributes, via `FrameworkUtil.createFilter` — a pure parser usable with no running framework, so it
  fits the standalone-resolver model. An absent/blank filter matches anything.

| handler SPI, providing half — `UnitHandler`
| ✅ Shipped (blue)
| Provides `osgi.extender=unitrepo.handler`. No concrete implementor yet; the requiring half lands with
  the first specialist unit.

| handler edge — type wiring
| 🟢 Design
| The `unitrepo.type` namespace carries the per-type edge into the resolution graph (two axes, not one
  overloaded `osgi.extender`). Makes connected-by-construction resolver-proven.

| ingest — Visit-unit history fold
| 🟢 Design
| Fold each Pulumi checkpoint into a content-addressed Visit-unit; reuses `StackCheckpoint` /
  `StackSnapshot`; touches no gRPC.

| load from store
| 🟢 Design
| Load a handler bundle from the store into the embedded Felix at runtime — no host rebuild for a new
  unit type.

| ContentStore on JGit — option B
| ⬜ Design
| Units serialize as git trees, a Visit is a commit, backed by JGit's `ObjectDatabase` SPI, decorrelated.

| mediation seam — `unitrepo-pulumi` ACL
| ⬜ Design
| Neutral `ResourceDescription` in, narrow engine gRPC facade out. The downstream extension of the port
  seam: the bundle hands a description, the host actualises it.

| federation — resolve-and-pull, lens, lockfile-DAG
| ⬜ Design
| Peer nodes serve their own DAG, pull closures on need, no central registry. The P2P horizon.
|===

=== Verdict — does it hold?

. *Monotone: yes.* Every shipped box and arrow survives unchanged — the resolver, the universe, the
  coherence gate, the SPI, the ports, the `awaitService` seam, the engine edge. The design additions are
  green boxes on amber ground.

. *The ONE honest changed collaborator:* `ComponentResource` stops calling the engine on its own data
  and is DRIVEN by a `ResourceDescription` handed through the ACL south port. The box stays, its gRPC
  arrow to the engine stays — only its INPUT shifts from inline to description. Named per the ritual, not
  silently redrawn. Same nature as the HealthSystem `Generalist` collaborator-swap in Diagram C.

. *The mediation seam composes, it does not conflict.* The shipped `-port` plus `awaitService` answers
  "how does the host READ a model the bundle computed". The mediation seam answers the next question,
  "how does the host ACTUALISE that description over the engine" — it slots downstream, refactoring the
  `ComponentResource` call sites, not the port seam. This is the orchestration-OSGi inversion (DIP:
  actualisation stays host, exposed as ports).

. *The convergence with the doctor, earned not asserted.* `stack-as-unit` is the substrate under both
  `MedicalRecord` and `InterventionLedger` — two shipped instances of "a stack is a unit-DAG". unitrepo
  is the generalization of the ledger-backed-specialist pattern, reached independently from the doctor
  side (the specialist-as-ledger north-star).

Conclusion: the constellation holds, and unitrepo is additive against the shipped rke2lab base.

=== Design scenarios — the seven capabilities as DSL sentences

The third movement (see <<the-scenario-map>>): each capability-map row above, written in full as a
design scenario. The GIVEN is the shipped rke2lab constellation; the WHEN is the box that licenses
the sentence; the THEN is the capability AND its additivity. Tagged playable (re-derivable from the
reactor today) or narrated (reasoning, no executable substrate yet), colored by horizon.

. *Any unit set resolves in one Felix resolve* — `[playable]` blue +
.. GIVEN the reactor as shipped (the Felix `Resolver` injected, the manifests universe built)
.. WHEN the `UnitResolver` oracle wraps the resolver
.. THEN any unit set resolves in one Felix resolve — the universe holds 46 units on bioskop — AND
   the hand-rolled walker (`ManifestsUnitDependencyApplier`) is erased (the one named deletion, already
   absorbed).

. *A checkpoint is a foldable Visit-unit DAG* — `[playable, partial]` green +
.. GIVEN `StackCheckpoint` / `StackSnapshot` shipped and the `MedicalRecord` fold proven
.. WHEN ingest plus the ContentStore land
.. THEN a checkpoint folds into a content-addressed Visit-unit DAG — AND no gRPC is touched, the fold
   is additive over the file backend. (Partial today: the fold is shipped, ingest is not.)

. *A handler loads from the store at runtime* — `[narrated]` green +
.. GIVEN the embedded Felix booting inside `Pulumi.run` (R4 shipped)
.. WHEN load-from-store lands and one concrete `UnitHandler` implements the providing half
.. THEN a handler bundle loads from the store into the running framework with no host rebuild — AND
   the `osgi.extender=unitrepo.handler` contract (already exported) is its resolution edge, nothing
   rewired.

. *The model decides what, the host actualises how* — `[narrated]` green +
.. GIVEN the shipped `-port` + `awaitService` seam (the host READS a model the bundle computed)
.. WHEN the neutral `ResourceDescription` and the `unitrepo-pulumi` ACL land
.. THEN the model decides WHAT and the host actualises HOW over the engine — AND `ComponentResource`
   is driven by a description instead of inline data (the one named changed collaborator), its gRPC
   edge unchanged.

. *Recruit a specialist by pulling its closure* — `[narrated]` amber +
.. GIVEN the resolution oracle and the (designed) ContentStore
.. WHEN resolve-and-pull lands
.. THEN a node recruits a specialist by pulling its closure — AND this is the specialist-as-ledger
   north-star reached from the unitrepo side, additive over the doctor's shipped record substrate.

. *Share a severed, gated lens of a DAG* — `[narrated]` amber +
.. GIVEN content-addressed units in the store
.. WHEN lens severance lands
.. THEN a peer shares a severed, gated lens of its DAG — AND the federation horizon opens with no
   central registry, additive.

. *Reproduce a deploy byte-exact* — `[narrated]` amber +
.. GIVEN the content-addressed store and the resolution closure
.. WHEN the lockfile-DAG lands
.. THEN a deploy reproduces byte-exact from its lockfile-DAG — AND reproducibility is a property of
   the DAG, nothing in the shipped base rewritten.

. *A design scenario resolves as a unit* — `[narrated]` green +
.. GIVEN scenarios written as prose Given/When/Then in the atlas, their gates counted by hand
.. WHEN the scenario engine is made pure and a scenario is expressed as a `UnitResource`
   (Provide/Require: "this scenario requires these boxes")
.. THEN a design scenario resolves as a unit — its GATES become resolution EDGES, so the compass's
   "how many increments" is RESOLVED by the Felix resolver, not hand-counted — AND this reuses the
   shipped `UnitResolver`, additive. Shut gate: the orchestration-OSGi inversion (the shared leverage
   box, see the runtime view).

*Coverage of this view:* 8 capabilities, 8 scenarios — complete per <<scenario-completeness>>. One

==== Worked example — the gates of scenario 3 (how narrated becomes playable)

A narrated scenario does not float; it is moored to named boxes whose gates are shut. Decomposing
scenario 3 ("a handler loads from the store at runtime") clause by clause shows exactly what must ship
to flip it playable — narrated describes the GATES, not the scenario (which is already fully written).

[cols="3,2,1,1",options="header"]
|===
| Clause | Gating box | Colour | Gate

| GIVEN — embedded Felix boots inside `Pulumi.run`
| R4 boot seam
| 🔵 blue
| OPEN

| WHEN(a) — a concrete `UnitHandler` implements the providing half
| the handler's requiring half (one concrete handler)
| 🟢 green
| shut

| WHEN(b) — load-from-store lands
| load-from-store
| 🟢 green
| shut

| THEN — the bundle loads into the running framework, no host rebuild
| (depends on WHEN a+b)
| 🟢 green
| shut
|===

Three shut gates, two distinct green boxes. To flip the scenario playable: ship one concrete
`UnitHandler` (flip green→blue, gate WHEN(a) opens), ship load-from-store (flip green→blue, gate
WHEN(b) opens) — then every box on the path is blue and the scenario flips narrated→playable by
derivation, no re-tagging. Once playable, the probe writes itself, because blue boxes are probe-able by
construction: WHEN(a) → "a class implements `UnitHandler` and provides `unitrepo.type=X`" (scan the
reactor); WHEN(b)+THEN → "loading that bundle from the store into an embedded Felix resolves it" (an
`@OsgiSpike`, green/red). This is the worked instance the ritual's gate definition points to.

=== Glossary remediation (the reserved words — see the "two spaces" note)

Folding the unitrepo docs in reconciles their vocabulary with the atlas's reserved words:

* *World-A* (the unitrepo durability regime, pull=own) collides with `world` = the runtime classloader
  region. Renamed *the pull-own regime*.
* *node* — the unitrepo peer-node is disambiguated from rke2lab's cluster/env node (`NodeEnvContext`):
  say *unit-node* vs *cluster-node* where both are in scope.
* *name-space* (schema-name space, class space) — kept hyphenated, never bare `space` (which is a layout
  dir).
* *universe* is a happy coincidence: the unitrepo `RepositoryView` candidate-set IS the reserved sense,
  embodied by `ManifestsUniverse`.
* *Unit* and *Visit* were chosen to align with rke2lab's `ManifestsUnit` / `Visit` — safe anchors.
* module layout adopts the `-port` / `-core` / `-spi` taxonomy; `unitrepo-pulumi` is the host-world ACL.
