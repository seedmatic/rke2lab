:toc: macro
:icons: font

== Overview

*Status*: IMPLEMENTED (design 2026-06-03; shipped since). The target model below is now the code in
`AbstractManifestsUnit` (`osgi/domains/manifests/manifests-core`), with two naming differences from
the original cadrage: the template method is named **`apply(ManifestsUnitContext context)`** (not
`synthesize(scope)`) to match the `ManifestsUnit` interface, and the subclass hook is
**`doSynthesize(Construct scope, ManifestsUnitContext context)`** (it also receives the context). The
per-unit scope Construct, the group-marker `ConfigMap`, the pure constructor, direct `new XxxUnit()`
registration, and the removal of `ManifestsUnit.lazy(...)` are all in place. Read `synthesize`/
`delegate` in the figures below as today's `apply`/`scope`.

A `ManifestsUnit` has two distinct moments that must not be conflated:

. *Construction* — pure instance initialization: assign metadata fields (id, deps, phase,
  output dir). No domain logic, no I/O, no context lookups, no CDK8s nodes.
. *Synthesize* — the unit's actual work: emitting the K8s `ApiObject`s into a scope it is
  *given*. Invoked by the synthesis pipeline after construction, with the chart scope passed in.

== Root cause: a unit should not BE a Construct

Before this shipped, `AbstractManifestsUnit extends Construct` (superseded). A CDK8s `Construct` demands its parent
scope at `super(scope, id)` time, and units use `this` as the scope for their `ApiObject`s
(`new ApiObject(this, ...)`). This single inheritance choice causes three coupled problems:

. *`lazy()` exists only to work around it.* Registrars declare units (id, deps, phase) *before*
  the `Chart` exists, but a Construct can't be instantiated without a scope — hence
  `ManifestsUnit.lazy(...)` defers construction ("to avoid creating Construct instances with
  null scope", per its own Javadoc). Remove the inheritance and the workaround disappears.
. *Work happens in the constructor.* Because the scope arrives at `super(...)`, and `this` is
  the scope for `ApiObject`s, units create their manifests in the constructor (28 of 30 do).
  That conflates construction with synthesis.
. *No clean synthesize hook.* A base-class constructor can't safely call overridable logic
  (subclass fields aren't initialized yet), so shared synthesize-time behavior (e.g. the group
  marker) has nowhere natural to live.

Crucially, `this` is used *only* as an `ApiObject` scope — no unit calls `Construct` methods on
itself or on another unit; inter-unit references go through the applicative
`ManifestsUnitReferenceRegistry`, and `addDependency(...)` is called on `ApiObject`s, not units.
So the inheritance buys nothing the model needs.

*owns* one, briefly, only while synthesizing. The base `synthesize` is a template method: it (1)
creates the delegate under the passed-in scope, (2) calls the subclass `doSynthesize(delegate)`

grouping node and the marker both live on the delegate, with zero per-unit boilerplate.

== Shipped model: unit is a plain object with `apply(ManifestsUnitContext)`

* `ManifestsUnit` is a plain object holding metadata. Its constructor is pure initialization.
* `AbstractManifestsUnit.synthesize(Construct scope)` is a *template method*. It owns the
  CDK8s coupling so subclasses never touch it:
  . creates the *delegate* — `new Construct(scope, manifestUnitId)` — the grouping node that
    replaces the old `this`. The unit no longer *is* a Construct; it *owns* one for the duration
    of synthesis.
  . calls the abstract hook `doSynthesize(Construct delegate)`, where the subclass emits its
    `ApiObject`s into the delegate (`new ApiObject(delegate, ...)`).
  . emits the group marker into the same delegate, uniformly, with scope and metadata both in
    hand — no init-order hazard.
* Subclasses implement only `doSynthesize(delegate)` — pure domain logic, no scope plumbing, no
  marker boilerplate. (This mirrors the existing `*Assets` helpers, which already delegate CDK8s
  node creation rather than inheriting it.)
* Registrars instantiate units directly (`new XxxUnit()`), no `lazy()`, no deferred factory.

(`synthesize` is the CDK8s-native verb — `App.synth()`, "synthesizer". Reserve `materialize`
for writing host files, as the `*Assets` host-asset code already does.)

The scope only exists when `synthesize` is called — never at construction. The base creates the
**delegate** Construct under that scope, hands it to the subclass `doSynthesize` hook, then emits
the group marker into the same delegate. So a unit is freely instantiable in a registrar, every
`ApiObject` lands under one grouping node, and the marker is emitted with scope and metadata both
in hand.

== The rule

[cols="1,2,2",options="header"]
|===
|Phase |Allowed |Forbidden

|Constructor
|Metadata field assignment, capturing immutable inputs
|Creating `ApiObject`s / Constructs, reading `ManifestSynthesisContext`, I/O, overridable calls

|`doSynthesize(delegate)` (subclass)
|Creating manifests in the given delegate, reading context
|Creating the delegate, emitting the group marker (the base owns both)

|`synthesize(scope)` (base, template)
|Creating the delegate, calling `doSynthesize`, emitting the group marker
|(`final` — subclasses override `doSynthesize`, not this)
|===

== Group marker: deterministic output directories

Each unit declares an output directory (`<domain>/<outputDir>()`) where its manifests are
exploded. A unit may legitimately produce *zero* manifests in a given mode — e.g.
the cluster-api units skip when there is no real image identity bound. Without
intervention, no output directory is created, and a downstream consumer expecting it (the
explode step, a reader walking the per-resource tree) trips over the missing dir.

To stay *deterministic*, every unit emits a *group marker* during synthesize: a placeholder
that guarantees the output directory exists even when empty.

* The marker is a `ConfigMap` carrying `config.kubernetes.io/local-config: "true"` plus the
  unit's `io.seedmatic.rke2lab/domain` + `io.seedmatic.rke2lab/package` annotations.
* The exploder writes it (so the directory is created), but the installer script skips
  `local-config` documents — so the marker is never linked into RKE2's manifests dir, only its
  directory survives.
* An empty directory → the script links nothing and exits 0 (OK). An absent directory →
  `exit 1`. The marker turns "absent" into "empty", removing the failure mode.

Emitted uniformly by the base `synthesize` template method into the delegate, after the subclass
`doSynthesize` hook runs — so all units get it with zero per-unit boilerplate and no chance of a
conditional unit being forgotten.

NOTE: today the system has no controller, so the model is strictly `manifest → resource` or
`manifest → nothing`. The group marker is the `manifest → nothing` case expressed as a
`local-config` ConfigMap. *Future evolution*: when a controller exists to reify groups, this
marker should become a real `rke2lab.io/ManifestGroup` custom resource (a typed kind we own)
instead of a ConfigMap. The annotations already carry the needed identity; only the kind and a
controller would change.

== Migration (cadrage → prototype → generalize)

The target model touches all 30 units, so it is adopted in three deliberate steps:

. *Cadrage (this doc)*: fix the model on paper — unit is a plain object, `synthesize(scope)`
  replaces construction-time work, `lazy()` is removed, the base class emits the group marker.
. *Prototype (one unit)*: convert a simple unit (e.g. `ClusterRuntimeNamespaceManifestsUnit`)
  to the target model end-to-end — drop `extends Construct`, add `synthesize(Construct scope)`,
  instantiate it directly in its registrar (no `lazy`). Validate it compiles and the preview is
  unchanged for that unit. This proves the shape before touching the rest.
. *Generalize (remaining units)*: apply the proven shape to the other 29 units uniformly,
  remove `ManifestsUnit.lazy` and its overloads, simplify the registrars, and move the group
  marker into the base `synthesize`.

Until the prototype lands, the boot-unblocking group marker may ride whichever hook currently
exists; its final home is the base `synthesize` once the model flips.

== Known debt — de-soup the Map-literal units

Some units render their resources as long `Map.of(...)` blobs inside a pile of private `createXxx(scope,
…)` helpers — a catch-all decomposition that buries the resource shape in positional literals and threads
scalars (e.g. the cluster name) through helper signatures. When a unit like this is next touched, *empty
the catch-all*: lift the resource data into typed records / small local classes, keep each resource's own
naming scheme cohesive with the resource, and let the unit consume its narrow view
(`ManifestsUnitContext.nodeEnvContext()`) once. Do NOT smuggle a large de-soup into an unrelated fix — a
big unit warrants a dedicated pass.

Current candidates (observed while routing cluster identity through the node-env view, so the `bioskop`
literal could die): `HeadscaleManifestsUnit`, `TailscaleManifestsUnit`, `TektonDashboardManifestsUnit`.
