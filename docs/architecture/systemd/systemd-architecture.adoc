= RKE2Lab Systemd Architecture
:toc: left
:toclevels: 3

== Status: DISSOLVED

[NOTE]
====
This document described the systemd architecture *synthesised* by the manifests
world: a CDK8s-`systemd` extension (`SystemdChart`, `SystemdService`,
`SystemdTarget`, `SystemdDropIn`, `SystemdScript`) that emitted a target hierarchy
(`rke2lab.target` and its `-network` / `-tools` / `-bootstrap` / `-manifests` /
`-secrets` children), an `rke2-server.service` drop-in with pre/post-start hooks,
and the bootstrap script sequence — all delivered under `/srv/host/systemd-*.d`.

That whole synthesis is *gone*. The node moved to a declarative NixOS substrate,
so its systemd units, ordering, and the rke2-server integration are now expressed
directly in the `nixos/` modules rather than synthesised and shipped as host
assets:

* `nixos/rke2.nix` — `services.rke2`, the `rke2lab.target` aggregate, and the
  apiserver tls-san drop-in;
* `nixos/identity.nix` — `rke2lab-identity.service` (devlxd → hostname + node.env);
* `nixos/sops.nix` — `rke2lab-sops-fetch.service` + `sops-install-secrets`;
* `nixos/containerd.nix` — `rke2lab-zfs-containerd.service` + the flox NRI runtime;
* `nixos/host-access.nix` — dbus-over-TCP + mDNS.

The one piece that survives on the OSGi side is the *read* path: the seed-outcluster
systemd adapter (`dbus-systemd-edge` / `systemd-core`, over the `systemd-contract`
probe types) opens a dbus-over-TCP connection to a node and reads live unit state,
probing `rke2lab.target` as the substrate-ready signal.
