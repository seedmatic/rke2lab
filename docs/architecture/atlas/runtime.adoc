== OSGi runtime view — per-subsystem view

The config view (above) proved the *schema/resolution* half of the bundle/host contract on the bench.
This view tracks the **runtime** half: `java.util.ServiceLoader` is replaced with a launched Felix
framework + Declarative Services (SCR), and `seed-outcluster` boots the framework inside its `Pulumi.run`
callback and consumes the pure-model services from the registry. Two decisions shape it: the
*API-extraction* (the boundary ports live in `osgi/<domain>/<domain>-port`, so the host compiles
against the port and fails fast at build) and the *proof reframe* (the boot seam is proven by
`pulumi preview`, not a live deploy).

=== The two worlds, as shipped at R4 (C4 — Context)

One process, two classloader worlds. The HOST world is flat and holds gRPC (invariant #1565: no gRPC
type ever crosses into a bundle); the OSGI world holds the pure-model bundles Felix resolves. The host
`FrameworkLaunch.embedded()` boots Felix inside `Pulumi.run`, the host seam reads the typed
services from the registry, and OSGi logs converge on the host's Logback via Pax with
`StaticLogbackContext` (logs follow the bootstrap direction — outward to the host).

=== The model

The runtime is `ServiceLoader`-free for services: every entrypoint boots under Felix and reads its
services from the SCR registry. The pieces:

* *felix.scr + embedded Felix* — `@Component` publishes, `@Reference` binds; the anti-cheat is a
  consumer left unsatisfied when its provider is absent.
* *The 5 SPIs as `@Component`s, consumed intra-bundle via `@Reference`* — e.g.
  `DefaultManifestSynthesisService` aggregates its domain registrars through SCR.
* *API-extraction* — the boundary ports live in `osgi/<domain>/<domain>-port` (the port belongs to the
  DOMAIN, not the adapter); the host compiles against the port and fails fast at build; each port
  carries its own `@Version`, imported versioned.
* *The boot seam* — Felix is embedded in the Pulumi callback; the self-contained exec-jar embeds its
  bundles intact (the model core + felix.scr/resolver + pax-logging). Proven by `pulumi preview` (full
  pipeline under Felix, no live deploy). All three entrypoints boot Felix the same way and demote the
  model `-core` to `runtime` scope. The host↔OSGi seam is `seed.broker.port` alone: every entrypoint
  (seed-outcluster + both CLIs) DRIVES a jGiven scenario that sows a coordinate through the broker,
  speaking only JSON — never `awaitService` on a typed domain service (a `type=contract` service
  registers with the bundle's class copy, so a flat host copy never matches). `netplan.api` moved into
  `netplan-contract` (single-exported); `netplan-cli`'s `yamlExport` sows `netplan` and grows the
  `netplan-bdd` scion. See link:seed.adoc[the seed atlas] and link:../osgi/netplan-bdd-spec.adoc[netplan-bdd-spec].
* *The synthesis grammar + the boot decomposition* — the fluent-pipeline engine was once duplicated as
  seed-outcluster's `TopicRunner` + manifests-core's `SynthesisTopicRunner`, briefly unified into a shared
  `pipeline-port` seam, then DISSOLVED: with the boot de-grammatised and the seed's own chains the last
  host holdout, manifests-core became its only OSGi consumer, so the engine relocated INTO manifests-core
  as un-exported internal synthesis (`Phase`/`PhaseRunner`/`PhaseFailure`,
  `io.seedmatic.rke2lab.manifests.internal.synthesis`) — no shared seam. The three copied
  `bootEmbeddedOsgiRuntime()` were NOT collapsed into a `SeedRuntime` seam (an earlier design) but
  DISSOLVED by the boot decomposition (link:../osgi/osgi-boot-decomposition-spec.adoc[boot
  decomposition]): the pure decision `BootPlanner` → `BootPlan` told apart from the effectful
  `FrameworkLauncher` → `BootedFramework`, entered through one `FrameworkLaunch.embedded().launch()` the
  three exec apps share — a plain launch operation, not a pipeline verb. `OsgiRuntime` and the old
  `SeedRuntime` class are both GONE. (Name note: the socle's later `@SeedRuntime` is an unrelated
  homonym — a jGiven lifecycle-discipline annotation in `scenario-engine`, not this boot seam.)

`ServiceLoader` survives only for `FrameworkFactory` discovery (permanent, by design); the 8 orphaned
`META-INF/services` on the ports are gone. The one remaining thread is any residual static-path
cleanup.

=== The refinement this view makes to the two-spaces frame

The top-of-atlas frame draws ONE generic edge: the *bundle/host contract* (`Require osgi.extender` +
`SectionReader`). The runtime work refines that single edge into a typed model — *named honestly here
because the ritual requires every changed collaborator to be called out, not silently redrawn:*

* The crossing is now a RUNTIME *service registry*, not only a build-time *resolution*. Once Felix is
  launched (R4), SCR publishes `@Component` services and consumers bind by `@Reference` (in-bundle) or
  `getServiceReference` (at the host seam).
* The typed boundary splits by NATURE — the name follows the relation the module holds with whoever
  depends on it (the `-contract`/`-spi` taxonomy). Note this is NOT the *bundle/host contract* of the
  config view (`Require osgi.extender`, a capability seam) — that is the extender capability; what used to
  be loosely called "the contract" as a typed model crossing the frontier is now the domain *contract*:
  ** *contract* — a boundary a consuming bundle calls and an OSGi bundle implements. It is a PURE model
     (interfaces + records, zero engine imports), so by the purity axis its nature is osgi/ and it lives in
     `osgi/<domain>/<domain>-contract` (e.g. `manifests-contract`, `netplan-contract`, `systemd-contract`).
     In hexagonal terms the contract belongs to the DOMAIN, not the adapter — the impl bundle depends on it
     and the consumers depend on it (DIP), neither depends on the other's impl. It is a versioned bundle
     INSTALLED into Felix (`type=contract`) and wired bundle-to-bundle: its consumers inside the OSGi world
     import it and share one copy of the interface, nothing system-exported to the host (the host speaks
     only to the seed-broker seam). This is the DE-SEAMED state — the contracts used to be `-port` seams
     system-exported flat; they are now installed bundles, one per domain. (A contract is BOTH api and spi
     at once — a consumer calls it, the impl implements it — so it is named by concern, never `.api`/`.spi`.)
  ** *intra-OSGi spi* — a boundary resolved ONLY inside the OSGi world (e.g. `unitrepo-handler-spi`, an
     extender SPI) → stays an spi bundle in the OSGi world, never crosses the host↔osgi frontier.

This does not erase the old contract box — it types it. The `Require/Provide osgi.extender` resolution
(config view) and the service registry (this view) are the two halves of the same seam.

=== Verdict — does it hold?

. *Monotone through R4: mostly — with one honest exception.* The SPI impls are unchanged and the
  `@Component` annotations decorate the SAME impl classes (R2) without rewriting them; R1–R4 + the ports
  are GREEN additions. The exception: once R4 booted Felix, the HOST seam's `ServiceLoader` path was CUT
  to a single registry path (`awaitService`, fail-fast) — not kept beside it. That was deliberate
  (`pulumi preview` proved the deployed exec-jar always embeds the bundles, so the flat half was dead,
  not deferred — the no-fallback discipline). So `ServiceLoader` survives ONLY in the two un-migrated
  CLIs (and the 8 orphaned `META-INF/services` they still need); R5 deletes that last remnant. The
  registry and the static path no longer "both live at once" in seed-outcluster — only in the CLIs.

. *The ONE deliberate erasure is R5, and it is named.* R5 deletes `ServiceLoader`/`META-INF/services` —
  the single non-additive step in the whole migration. It is drawn amber (exploration), gated behind
  R4, and called out here precisely because the ritual forbids erasing a box silently. Until R5 the
  surface is strictly additive; R5 is the conscious, justified breaking change (uniformity: one
  consumption mechanism, not registry + static cousin).

. *The ports are NEW osgi/ boxes, not a rewrite.* They lift the boundary models OUT of the OSGi impl
  modules into `osgi/<domain>/<domain>-port`; the impls then depend on them (DIP), and the host compiles
  + host-loads them (system-exported). The host's current direct imports of impl classes
  (`DefaultManifestSynthesisService`, `ManifestYaml`, `FloxRuntimeAssets`) are wrong-direction crossings the
  atlas already flags — inverted at R4, not lifted into the port.

. *Honest scope.* R1–R3 are proven on embedded Felix (surefire, no `-Plive`). R4's proof is a real
  `pulumi preview` (a dry-run that boots Felix without mutating master) — the `-Plive up` is an optional
  final confirmation, the user's gesture. gRPC stays on the flat host classloader throughout (issue
  #1565); no gRPC type crosses into a bundle.

Conclusion: the runtime migration is additive through R4, with R5 the one named, deferred erasure. The
static `ServiceLoader` surface and the live registry coexist until every caller boots under Felix.

==== Verdict — does it hold?

. *The one named erasure is realised, not new.* Diagram J's `sl` box (`ServiceLoader + META-INF/services`)
  and its edges are DELETED — exactly the R5 CLI-half the J verdict pre-authorised ("delete the static
  path once every entrypoint boots under Felix; then drop the 8 orphaned `META-INF/services`"). The `cli`
  box is NOT erased: it is rewired from `sl` to the registry via the boot pipeline — a changed
  collaborator, named per the ritual.

. *The synthesis grammar is now internal to manifests-core, not a seam.* It unified the two runner copies
  (`TopicRunner` + `SynthesisTopicRunner`) the atlas never drew, briefly as a shared `pipeline-port` seam;
  once the boot was de-grammatised and the seed's own chains were the last host holdout, manifests-core
  was its only OSGi consumer, so it relocated INTO manifests-core (`Phase`/`PhaseRunner`, un-exported).
  Only `comp` (in-bundle) points to it now — the host `flp` boot no longer uses it, so it crosses no seam.

. *The boot is DECOMPOSED, not a `SeedRuntime` seam.* An earlier design collapsed the three
  `bootEmbeddedOsgiRuntime()` copies into a host `SeedRuntime` prefix; the shipped shape instead
  DISSOLVED them (link:../osgi/osgi-boot-decomposition-spec.adoc[boot decomposition]) into a pure
  decision (`BootPlanner` → `BootPlan`, OSGi-space) told apart from the effectful act
  (`FrameworkLauncher` → `BootedFramework`), entered through one `FrameworkLaunch.embedded()` the
  three exec apps share. `OsgiRuntime` and the `SeedRuntime` class are GONE. (The socle's later
  `@SeedRuntime` is an unrelated homonym — a jGiven discipline annotation, not this boot seam.)

. *L2 not drawn.* The passive-stage module was dropped (candidate stages are host-coupled); nothing added
  for it — honest absence, not a silent omission.

Conclusion: additive, with the single erasure being the atlas's own pre-named R5 CLI-half. The constellation
holds.

=== Design scenarios — the runtime capabilities as DSL sentences

The third movement (see <<the-scenario-map>>) for the runtime migration. Every row of this view's
inventory is shipped, so every scenario is playable-and-blue — the richest playable surface for the
designer's runbook. GIVEN the static `ServiceLoader` surface, WHEN a slice lands, THEN the capability
AND its additivity.

. *A component publishes a service the framework binds* — `[playable]` blue +
.. GIVEN the 5 SPIs discovered by `java.util.ServiceLoader`
.. WHEN R1 adds felix.scr to the BOM and proves `@Component`/`@Reference` on embedded Felix
.. THEN a component publishes a service and a consumer binds it — AND the anti-cheat holds (the
   consumer is unsatisfied when the provider is absent), `ServiceLoader` still coexists.

. *The five SPIs are declared components* — `[playable]` blue +
.. GIVEN the SPI impl classes
.. WHEN R2 annotates them `@Component` (bnd emits OSGI-INF)
.. THEN the five SPIs are declared services — AND the same impl classes are decorated, not rewritten;
   `ServiceLoader` stays active.

. *A registry aggregates its contributors by reference, not by ServiceLoader* — `[playable]` blue +
.. GIVEN `DefaultManifestSynthesisService` loading its domain registrars via `ServiceLoader`
.. WHEN R3 makes it `@Component` + `@Reference`
.. THEN the registry aggregates its contributors through the service registry — AND the dual
   `forServiceLoader()` path is kept beside it (additive).

. *The host calls a domain across a versioned port, fail-fast at build* — `[playable]` blue +
.. GIVEN the host importing impl classes directly (wrong-direction crossings)
.. WHEN the boundary models are lifted into `osgi/<domain>/<domain>-port` (DIP)
.. THEN the host compiles against a versioned port and the impl implements it — AND the ports are new
   osgi/ boxes, system-exported flat so host and bundle share one copy.

. *seed-outcluster boots Felix inside Pulumi.run and reads services from the registry* — `[playable]`
  blue +
.. GIVEN the host seam reading via `ServiceLoader`
.. WHEN R4 embeds Felix in the `Pulumi.run` callback and the seam reads via `awaitService`
.. THEN seed-outcluster boots the framework and consumes pure-model services from the registry — proven
   by `pulumi preview` — AND the host's `ServiceLoader` path is CUT to a single registry path (the
   one named, deliberate erasure, no-fallback discipline).

. *Every entrypoint boots under Felix, the CLIs included* — `[playable]` blue +
.. GIVEN the two CLIs still flat on `ServiceLoader`
.. WHEN the CLI alignment generalises the boot seam (manifests-cli + netplan-cli)
.. THEN every `main()` entrypoint boots embedded Felix and DRIVES a jGiven scenario that sows its
   coordinate through `seed.broker.port` (JSON only, never a typed `awaitService`) — AND `netplan.api`
   moves into `netplan-contract` so the consumed contract is single-exported, `netplan-cli` growing
   the `netplan-bdd` scion.

. *One synthesis grammar, internal to manifests-core* — `[playable]` blue +
.. GIVEN the grammar duplicated as `TopicRunner` + `SynthesisTopicRunner`, briefly shared as `pipeline-port`
.. WHEN the boot is de-grammatised (a plain `FrameworkLaunch.embedded().launch()`, not a pipeline verb)
   and the boot decomposition (`BootPlanner`/`FrameworkLauncher`) dissolves the three boot copies, leaving
   manifests-core the grammar's only OSGi consumer
.. THEN the grammar relocates INTO manifests-core as un-exported internal synthesis (`Phase`/`PhaseRunner`)
   — no shared seam, nothing crosses to the host (L2 dropped: host-coupled).

. *Nothing of ours discovers services by ServiceLoader any more* — `[playable]` blue +
.. GIVEN `ServiceLoader` + the 8 orphaned `META-INF/services` files
.. WHEN R5's CLI-half deletes them once every entrypoint boots under Felix
.. THEN no code of ours discovers services by `ServiceLoader` (only `FrameworkFactory` discovery
   remains, permanent) — AND this is the single pre-named erasure of the whole migration, realised.

. *The orchestration runs as an OSGi service* — `[narrated]` green +
.. GIVEN the orchestration logic host-side (the pipeline stages drive Pulumi inside `Pulumi.run`)
.. WHEN the orchestrator is inverted into an OSGi service, the actualisation steps (Incus/Pulumi/gRPC)
   staying host as ports it calls (DIP)
.. THEN the orchestration runs as an OSGi service while the engine stays host — AND nothing host-only
   is forced pure (host orchestration may be the final architecture); the gain is maximising what lives
   in the OSGi world, where the code is best-structured. The shut gate is the
   orchestration-OSGi inversion; this is a leverage box (it also gates the unitrepo
   "scenario resolves as a unit" and the designer-runbook "pure bundle" scenarios).

*Coverage of this view:* 9 capabilities, 9 scenarios — complete per <<scenario-completeness>>. Eight
playable-and-blue today; one narrated-green (the orchestration-OSGi inversion, a shared leverage gate).
