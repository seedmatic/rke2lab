== Core Architecture

=== Build & Packaging

* link:architecture/patterns/flake-build-entry-point.adoc[Flake as Build Entry Point] (✅ substantially implemented) - Flake as the authoritative deploy build (Maven=dev loop, flake=release); store-built seed-master + manifests + NRI plugin
* link:architecture/patterns/netplan-blueprint-single-source.adoc[Netplan Blueprint Single Source] - Cross-repo single source of truth for the network underlay; the flake runs the netplan jar (IFD) and exposes a flat `lib.networkBlueprint` that nix-darwin-home consumes via `deriveMacs`
* link:architecture/patterns/dataplan-single-source.adoc[Dataplan Single Source] - The storage twin of the netplan blueprint: rke2lab `seed-master` owns the cluster ZFS dataset layout (`tank/rke2lab/*`, ephemeral `control-nodes` + `persist`), emits a checked-in `dataplan.json` -> flat `lib.dataplan` that ndh pulls into `catalog.datasets` + materialises via disko; the same SSOT feeds the openebs-zfs StorageClass pool + the static persist PV. Motivated by etcd being wiped every cold-start (persist needs a stable handle)
* link:architecture/patterns/service-contributors-views-adapters.adoc[Service / contributors / views / adapters] - The system's dominant DI idiom, named: a passive service (knows no one), contributors via a uniform SPI, narrow role-owned view-adapters, monotone cascade down the DAG. Already conformant in Doctor, seed-broker, host-asset, Pulumi outputs; hold-outs = `ManifestSynthesisContext`, `NodeEnvContext`
* link:architecture/patterns/cli-scion-and-dual-realm-ingress.adoc[CLIs are scions — north-adapter + dual-realm ingress] - The two laws of the host↔OSGi boundary a CLI must honour: Law 1 — a CLI is a thin north-adapter that SOWS a root scenario through the broker (never `awaitService` a `type=contract` service host-flat — structurally broken); Law 2 — typed values BOTH realms hold live in a `type=dual-realm` ingress module (`Component`/`BumpLevel` for the manifests bumper), never duplicated host-side. Worked examples: manifests-cli, netplan-cli, seed-master

Orchestration, config input, the Pulumi resource graph and the scenario spine are placeable yet stay host — they are not contacts. Cross-references every edge spec.

== GitOps & Cluster API

* link:architecture/cluster-api/management-workload-topology.adoc[Management / Workload Topology] (🎯 anchor — current architecture) - The management/workload cluster separation: a permanent, run-on-demand management cluster (CAPI/CAPN/CAPRKE2) greenfield-creates the workload clusters (`bioskop-wrkld`, `nikopol-wrkld`) across two bare-metals. The reference the other cluster-api/bootstrap docs are being reframed against; explains why self-management was rejected (the CAPRKE2 adoption wall).
* link:architecture/cluster-api/manifests-rendered-branches.adoc[Manifests Rendered Branches] (🎯 delivery model — current) - How the manifests reach the clusters: `main` = source, `manifests/<host>-<role>` = per-cluster rendered branches (history-preserving fast-forward push), consumed by `seed-master` (`-mgmt`) and CAPI/CAPN (`-wrkld`); one Flux/vCluster per cluster; the render shape is a function of the consumer. The delivery companion to the topology anchor.
* link:architecture/cluster-api/pac-in-cluster-render-spec.adoc[In-cluster render via Pipelines-as-Code] (🎯 upstream loop — target) - The UPSTREAM half of the GitOps loop: a push to the manifests source triggers a Tekton PaC PipelineRun that re-renders + pushes `manifests/<cluster>` in-cluster (grow does the first render; PaC maintains). PaC authenticates as the baked GitHub App and hands the push token, so the in-cluster render stays secret-blind (no `KubeSecretsGateway`). `clean verify` gated, flox-NRI toolchain, `~/.m2` PVC. Upstream companion to Rendered Branches.
* link:architecture/cluster-api/cluster-addressing-plan.adoc[Cluster Addressing Plan] (✅ Shipped — addressing SSOT) - How every span a cluster owns (node/VIP/LB, pod, service, IPv6 ULA, clustermesh `cluster.id`, BGP ASN) derives deterministically from `<host>-<role>` via `clusterId = (host<<1)|role`. Forced by four clusters on a shared L2 fabric federating in two role-partitioned meshes (mgmt↔mgmt, wrkld↔wrkld): pod/service CIDRs and ASN move from global constants to per-cluster derivations. The addressing companion to the topology anchor + the BGP fabric.
* link:architecture/cluster-api/github-credential-model.adoc[GitHub Credential Model] (🟡 Model frozen; domain built) - The auth companion to Rendered Branches: every GitHub access derives from ONE `seedmatic`-org-owned GitHub App (`seedmatic-rke2lab`), never a personal PAT — escaping corporate token governance. One identity, per-token least privilege (each usage mints a scoped installation token: writer `contents:write`, Flux `contents:read`, Tekton `statuses/PR/checks`), and ONE App private key — isolation by token scope + short lifetime, not per-cluster keys (generating App keys is UI-only). Host writer mints host-side; Flux mints in-cluster (native App auth); the App-auth Secret rides the local-only bootstrap seed. Caveats: key-in-cluster (contained), runtime mint/refresh, no branch-scoped read.
