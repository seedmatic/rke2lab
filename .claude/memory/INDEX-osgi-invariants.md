- [fabric8 K8s client wrapped as ONE bundle — PROVISIONAL, owe official-OSGi switch (2026-08-07)](fabric8-osgi-wrap-provisional-debt.md) — **fabric8 7.8.0 is NOT cleanly stageable: core jars (client/api/httpclient) are header-less plain JARs, and the ~21 model jars SPLIT-PACKAGE `io.fabric8.kubernetes.api.builder` (17x) + `model.annotation` (11x) — Felix can't wire it.** The `:bundle` classifier is client-only (still imports the split model) + `Require-Capability osgi.serviceloader.processor` (aries-spifly). So `osgi/runtime/fabric8-wrap` embeds the whole closure `lib:=true` on ONE Bundle-ClassPath (split dissolved, plain first-match) + exports `io.fabric8.*` once; ServiceLoader bypassed via explicit `JdkHttpClientFactory` (no spifly needed — it's ORTHOGONAL). Resolves green (realm-wiring 0 error, zero raw model jars staged). **DEBT: switch back to official OSGi (`kubernetes-client:bundle` + a resolvable model bundle set + aries-spifly, already roadmapped) once fabric8 dedups the model split or ships an aggregate** (watch fabric8io/kubernetes-client #822/#487/#3890/#3774), then delete the wrap. See [[cdk8s-carrier-flat-jar-pattern]] [[serviceloader-specialist-spi]] [[prefer-osgi-edge-three-reasons]].
