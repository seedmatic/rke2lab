**Le renversement + le pivot.** Le render in-cluster était réputé « structurellement secret-blind » ([ExecutionEnvironment](host/host-runtime/.../ExecutionEnvironment.java) force `IN_CLUSTER -> EmptySecretsGateway`). FAUX : il l'est UNIQUEMENT parce que `.secrets` atterrit sops-chiffré au repos (pas de filtre smudge). Amène le filtre git-sops in-cluster → `.secrets` se smudge → le cellier se remplit comme sur l'opérateur → **secret-full**. **Et le pivot (user) :** une fois secret-full, la doctrine « secrets jamais sur la branche » perd sa prémisse → **les secrets ride la BRANCHE, sops-chiffrés** (le clean filter chiffre `data`/`stringData` au commit ; Flux déchiffre avec `sops-age` + `decryption.provider: sops`). NODE_BOOTSTRAP rétrécit à **l'amorce irréductible que Flux a besoin pour réconcilier** (sops-age, install Flux) — la frontière tranchée par l'user. Dissout : devlxd pour ces secrets, l'apply-fabric8, le panier `.bootstrap`.

**Deux assets sops statiques sur la branche** (pas une "policy" code manifests-core — c'est la policy SOPS déclarative) : `.gitattributes` (`**/*-secret-*.yml filter=sops-yaml`, quels FICHIERS) + `.sops.yaml` (`encrypted_regex: ^(data|stringData)$` + recipients age dont la clé cluster `age1k0tc4` pour Flux ; quels CHAMPS). L'exploder écrit `.gitattributes` ; `recordSopsPolicy` copie le `.sops.yaml` **source verbatim** (SSOT recipients). La clé age in-cluster = `SOPS_AGE_KEY` depuis le Secret `sops-age`.

**SHIPPED — ndh `git-sops-filter` (SSOT host+conteneur, 5 commits, tip `ad423dc8`, poussé, validé bioskop-nixos) :** paquet `packages.<sys>.git-sops-filter` ([modules/home-manager/git.d/git-sops-filter.nix]) consommé par home-manager (`sops.nix` = 1 include du store path) ET (à venir) le flox-catalogue. Le paquet porte les DÉFINITIONS ; le home ne fait qu'`include.path = <store>/sops`. Fixes : (1) shebang portable `#!/usr/bin/env bash` ; (2) dispatcher installé `sops-dispatch` PAS `sops.sh` (sinon le re-exec `realpath $0` → basename `sops.sh` → mode générateur au lieu de clean) ; (3) `required = true` sur les 11 fragments (un filtre non-`required` stocke le fichier NON-filtré = plaintext silencieux sur échec — c'est comme ça que le kubeconfig a fui) ; (4) **robustesse sous `required=true`** — clean tolère un HEAD non-sops (ré-encrypte), smudge passe un blob non-sops through, et le guard `test -r .sops.yaml` est **clean-only** (le déchiffrement n'a pas besoin de `.sops.yaml` → un checkout d'une branche sans policy ne plante plus).

**SHIPPED — rke2lab (`4fdeeaeb7` sur `feature/nixos-node-substrate`, poussé) :** `recordSopsPolicy` (écrit `.sops.yaml` racine), `ClusterApiWorkloadManifestsUnit` drop NODE_BOOTSTRAP sur `<host>-incus-identity` + les 4 `<cluster>-{ca,cca,etcd,peer-etcd}` (→ branche, attachés à la namespace de branche ; `createNodeBootstrapNamespace` retiré), test `JgitRenderedBranchTest` prouvant que **jgit 7.7.1 AddCommand lance le clean filter EXTERNE** (donc un Secret rendu chiffre au commit via jgit, pas de fuite).
